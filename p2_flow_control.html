PART 01

控制流程就是決定下一個執行位置

程式預設由上往下執行。條件式讓它選一條路，迴圈讓它回到前面再做一次。讀流程控制時不要只看縮排；C++ 真正採用的是括號、分號與大括號。每次追蹤都問三件事：現在檢查哪個條件、條件值為何、下一行去哪裡。

動手練習

條件為 false 的 if 本體會執行幾次？

看解答與理由

零次；流程直接跳到該本體之後，或進入相連的 else。

PART 02

bool 轉換、比較、邏輯與短路

比較運算 == != < <= > >= 產生 bool。數值放進條件時，0 轉成 false，非 0 轉成 true。能明寫比較時通常更清楚，例如 count != 0。

#include <iostream>
int main() {
    int divisor{0};
    int value{12};
    if (divisor != 0 && value / divisor > 2) {
        std::cout << "large quotient\n";
    } else {
        std::cout << "not available\n";
    }
}
預期輸出
not available

&& 只有左側 true 才算右側；|| 只有左側 false 才算右側，這就是短路求值。上例先看到除數為 0，右側除法根本不執行。! 反轉真假。不要把位元運算子 &、| 當邏輯運算子使用。

短路求值播放器

右式是否執行取決於左式。

int divisor{0};
int value{12};
bool ok = divisor != 0 && value / divisor > 2;


動手練習
條件 ready || count > 0 在 ready 為 true 時，右側還會比較嗎？
看解答與理由
不會；|| 已能確定整體為 true，因此短路。





PART 03
if / else if / else 與大括號


#include <iostream>
int main() {
    int score{78};
    if (score >= 90) {
        std::cout << "A\n";
    } else if (score >= 70) {
        std::cout << "B\n";
    } else {
        std::cout << "C\n";
    }
}
預期輸出
B



條件由上往下檢查，第一個 true 的分支執行後，整條鏈便結束。因此區間門檻通常由高到低排。即使本體只有一行也保留大括號，日後新增第二行才不會意外落在條件外。


if (loggedIn)
    std::cout << "welcome\n";
    std::cout << "menu\n"; // 無論 loggedIn 為何都執行


另一個危險是把比較 == 寫成指定 =：if (status = 1) 先把 status 改成 1，再把 1 轉為 true。警告選項常能抓到它，但根本方法是讀成「是否相等」與「把值放進去」兩個不同動作。


動手練習
score=95；若先檢查 score>=60，再 else if score>=90，會選哪支？
看解答與理由
第一支。else-if 鏈只執行第一個為 true 的分支，所以較窄、較高的門檻應先檢查。





PART 04
switch、case、break 與刻意 fallthrough


#include <iostream>
int main() {
    char command{'s'};
    switch (command) {
        case 's':
            std::cout << "save\n";
            break;
        case 'q':
            std::cout << "quit\n";
            break;
        default:
            std::cout << "unknown\n";
    }
}
預期輸出
save



switch 先計算一次整數類或列舉類運算式，再跳到相等的 case。執行不會在下一個 case 標籤自動停止；若缺 break，便繼續向下執行，稱為 fallthrough。這可刻意合併案例，但應用 [[fallthrough]]; 表意。字串不能直接當傳統 switch 的條件。


動手練習
case 1 印 A 後沒有 break，case 2 印 B 後才 break；輸入 1 印什麼？
看解答與理由
依序印 A、B。控制流從 case 1 進入後向下走，case 標籤不是障礙。





PART 05
while：先檢查，再決定是否進入


#include <iostream>
int main() {
    int n{37};
    int digits{0};
    while (n > 0) {
        n /= 10;
        ++digits;
    }
    std::cout << digits << "\n";
}
預期輸出
2



while (條件) { 本體 } 每圈先檢查條件。若一開始就是 false，本體執行零次。設計迴圈要指出狀態如何朝停止條件前進；上例每圈把正整數除以 10，最後會變 0。忘記更新 n 就可能形成無窮迴圈。


動手練習
n 一開始是 0，上例 digits 最後多少？
看解答與理由
0。while 是前測迴圈，第一次條件已為 false。


檢查時刻ndigits動作
第1次370進入本體
第2次31進入本體
第3次02離開迴圈


逐圈來看，第一次本體把 n 從 37 改成 3，digits 從 0 改成 1；第二次把 n 改成 0、digits 改成 2；第三次條件失敗才離開。若刪掉更新 n 的敘述，或把條件錯改成 n >= 0，狀態就不再靠近停止條件。





PART 06
do-while：本體至少執行一次


#include <iostream>
int main() {
    int value{-3};
    do {
        std::cout << value << "\n";
    } while (value > 0);
}
預期輸出
-3



do { 本體 } while (條件); 先執行本體才檢查，所以至少一次。尾端的分號是語法一部分。它適合必須先顯示一次選單或先讀一次輸入的情境；若本體是否能執行必須先驗證，則用 while。


動手練習
如何辨認 while 與 do-while 最大語意差異？
看解答與理由
前者可能零次；後者至少一次。不要只看關鍵字，要看條件是在本體之前或之後。


此例的順序是「先輸出 -3，再檢查 -3 > 0」。若把完全相同的條件改寫成前測 while，第一次檢查就失敗，輸出會是空的。若本體必須在條件成立時才安全，就不應為了至少一次而選 do-while。





PART 07
三段式 for 的精確時序


#include <iostream>
int main() {
    int sum{0};
    for (int i{1}; i <= 4; ++i) {
        sum += i;
    }
    std::cout << sum << "\n";
}
預期輸出
10



for (初始化; 條件; 更新) 的初始化只做一次；每圈先檢查條件，再執行本體，最後做更新，才回去檢查下一圈。上例本體做 4 次，但條件 i<=4 檢查 5 次。i 只活在迴圈範圍內。


逐圈追蹤 for
注意更新發生在本體之後。
int sum{0};
for (int i{1}; i <= 4; ++i) {
    sum += i;
}
std::cout << sum;


動手練習
把條件改成 i < 4，本體執行幾次、sum 為何？
看解答與理由
i 依序為 1、2、3，共 3 次；sum=6。


部分何時執行本例狀態
初始化 int i{1}只在開始一次i=1
條件 i<=4每圈前與最後一次true 四次，false 一次
本體條件 true 後sum 加入目前 i
更新 ++i每圈本體後i 前進到下一值


若把更新式刪掉，i 永遠停在 1；若把條件誤改成 i < 4，合法圈只剩 i=1、2、3。讀 for 時要把四個時刻展開，不能把括號內三欄當成同時發生。





PART 08
break 與 continue 改變哪一段流程


#include <iostream>
int main() {
    int sum{0};
    for (int i{1}; i <= 6; ++i) {
        if (i == 3) continue;
        if (i == 6) break;
        sum += i;
    }
    std::cout << sum << "\n";
}
預期輸出
12



continue 結束目前這一圈，for 仍先做更新再回到條件；break 立刻結束最內層迴圈。上例加入 1、2、4、5，跳過 3，遇到 6 時離開。while 使用 continue 時要特別確保更新沒有被跳過。


動手練習
巢狀迴圈內層執行 break，外層也會停止嗎？
看解答與理由
不會；break 只離開最內層的 switch 或迴圈。若要結束兩層，需要重組條件、旗標或函式回傳。


逐圈結果是：i=1、2 加入；i=3 執行 continue 後先做 ++i；i=4、5 加入；i=6 在加總前 break。若在 while 中把更新放在 continue 後方，被跳過的更新可能使條件永遠不變。





PART 09
巢狀迴圈：精確次數與成本直覺


#include <iostream>
int main() {
    int count{0};
    for (int row{0}; row < 3; ++row) {
        for (int col{0}; col <= row; ++col) {
            ++count;
        }
    }
    std::cout << count << "\n";
}
預期輸出
6



不能看到兩層迴圈就機械地說 n²。要先數內層對每個外層值做幾次：此例是 1+2+3=6。若外層跑 n 次而內層每次也跑 n 次，工作量是 n×n。Big-O 描述輸入規模 n 增大時，操作次數成長的上界，忽略固定倍數與較低階項；例如 3n+5 寫作 O(n)，n(n+1)/2 寫作 O(n²)。


這是成本的第一層直覺，不是碼表計時。迴圈本體若本身呼叫昂貴操作，還要把那項成本乘進去。精確執行次數適合先驗證推理，再用 Big-O 描述成長趨勢。


動手練習
外層 i=0..n-1，內層 j=0..i，內層本體精確執行幾次？Big-O 為何？
看解答與理由
次數為 1+2+…+n=n(n+1)/2；主要項與 n² 成比例，所以是 O(n²)。





三種控制流程的形狀
循序只往下；選擇只走一支；重複在狀態更新後回到條件。追程式時把每一步落到這三種形狀之一。


條件運算子的讀法
運算子讀法要注意
== / !=相等／不相等= 是指定，不是比較
< <= > >=大小關係邊界是否包含等號
&&而且左側 false 時右側短路
||或者左側 true 時右側短路
!不是／反轉真假複合條件可加括號表意


三元運算子：選一個值
condition ? value_if_true : value_if_false 是一個運算式，會先判斷條件且只計算其中一支。它適合兩個簡短值的選擇；若分支會做多個敘述或需要說明，用 if/else。
#include <iostream>
int main() {
    int age{12};
    int fee = age < 18 ? 80 : 120;
    std::cout << "fee=" << fee << '\n';
}
預期輸出
fee=80

不要把 ?: 當成縮短所有 if 的工具。 巢狀三元式很快失去可讀性；它的核心用途是產生一個值。


if 鏈與 switch 怎麼選
比較switchif / else if
條件形狀同一整數類／列舉值與各 case 常數比較可寫範圍、複合條件與不同變數
檢查順序跳到匹配 case由上而下，第一個 true
分支結束通常需 break；否則 fallthrough一支完成後整鏈結束
適用情境指令碼、狀態碼、選單成績區間、資格條件


for 邊界與實際走過的值
寫法本體次數i 的值常見用途
for(int i=0;i<n;++i)n（n≥0）0 到 n−1零起點索引
for(int i=1;i<=n;++i)n（n≥1）1 到 n一到 n 的計數
for(int i=n-1;i>=0;--i)n（n≥1）n−1 到 0倒序；i 必須是有號型別
for(int i=0;i<n;i+=2)ceil(n/2)0,2,4,…每隔一項
無號倒數是另一個問題。 size_t i>=0 永遠成立；不要把上表的 int 寫法機械換成 size_t。


用 chrono 量一段程式：逐件拆解
steady_clock::now() 是對 clock 型別呼叫靜態方法；auto 讓編譯器推導時間點型別。計時值會受硬體、編譯最佳化與系統負載影響；這裡真的輸出微秒數。下方 240 只是示例，你的結果可以不同，甚至在時鐘精度不足時為 0。
#include <chrono>
#include <iostream>
int main() {
    auto start = std::chrono::steady_clock::now();
    long long sum{0};
    for (int i{0}; i < 100000; ++i) sum += i;
    auto stop = std::chrono::steady_clock::now();
    auto elapsed = std::chrono::duration_cast<std::chrono::microseconds>(stop-start);
    std::cout << "sum=" << sum << " elapsed_us=" << elapsed.count() << '\n';
}
輸出示例（數字依實際執行而變）
sum=4999950000 elapsed_us=240

零件角色
start/stop工作前後的時間點
stop-start時間長度
duration_cast<microseconds>轉成指定單位
elapsed.count()取得該單位的數值；每次可不同


迴圈選擇與成本矩陣
問題形狀首選次數推理典型成本
次數未知、可能零次while追蹤條件與更新依狀態收斂速度
本體必須先做一次do-while至少 1 次依後測條件
明確計數或索引三段式 for展開初始化→檢查→本體→更新常見 O(n)
每圈把正數除以 2while約 floor(log₂n)+1（n≥1）O(log n)
外層 n 次、每次折半迴圈巢狀n·(floor(log₂n)+1)O(n log n)
兩層各完整跑 n 次巢狀迴圈n×nO(n²)
內層跑 1+2+…+n三角形巢狀迴圈n(n+1)/2O(n²)
範圍 for 的值、參考、const 參考五維比較已移到 P5 的完整 range-for 表，避免在容器出現前先用。


倒序邊界與折半迴圈
寫法前提實際值／次數成本
for(int i=n-1;i>=0;--i)n≥1、i 為有號型別n−1,n−2,…,0；n 次O(n)
for(int i=n-1;i>0;--i)n≥1n−1,…,1；n−1 次，刻意不含 0O(n)
while(x>0){x/=2;}x 初值 n≥1n,floor(n/2),…；floor(log₂n)+1 次O(log n)
#include <iostream>
int main() {
    int x{10};
    int iterations{0};
    while (x > 0) {
        x /= 2;
        ++iterations;
    }
    std::cout << "iterations=" << iterations << '\n';
}
預期輸出
iterations=4

狀態依序是 10→5→2→1→0，本體四次。每次減 1 與每次除 2 的成長率不同，不能都因為「一個 while」就判成 O(n)。


PART 10
P2 語法速查


結構何時用關鍵
if / else if互斥條件分支第一個 true 分支
switch同一整數類值的離散案例通常以 break 結束
while次數未知且可能為零先測條件
do-while本體至少一次尾端有分號
for初始化、條件、更新清楚條件常比本體多查一次
break離開最內層迴圈／switch後續圈不再執行
continue跳過本圈剩餘本體for 仍執行更新


動手練習
需要反覆讀值，直到成功讀到 1–5；你會先想到哪種結構？
看解答與理由
若一定要讀一次，可用 do-while；若先前已有一次讀值，也可用 while。重點是每次失敗後必須更新輸入狀態與 value，讓條件有機會改變。
