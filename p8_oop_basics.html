PART 01

類別把狀態與合法操作放在一起

當幾個數值必須共同遵守規則，把它們散放成變數會讓任何程式碼都能製造無效狀態。類別定義一種新型別：資料成員保存狀態，成員函式提供操作。依類別建立出的每個物件叫 instance；每個 instance 各自擁有非 static 資料成員。

#include <iostream>
class Reading {
public:
    double value{0.0};
    void add(double amount) { value += amount; }
};
int main() {
    Reading morning;
    Reading evening;
    morning.add(2.5);
    evening.add(7.0);
    std::cout << morning.value << " " << evening.value << '\n';
}
預期輸出
2.5 7

class Reading { ... }; 的尾端分號屬於類別定義。morning.add 與 morning.value 的點號表示「存取這個物件的成員」。兩個物件使用同一組成員函式定義，但狀態分開保存；修改 morning 不會改 evening。後續會把 value 收進 private，讓類別守住規則。

動手練習

建立 Reading a 與 b，只呼叫 a.add(3)。b.value 為何？

看解答與理由

仍是 0.0，因為類別內的 value{0.0} 是每個物件各自的成員初值，不是所有 instance 共用的一格。

PART 02

建構式先建立有效物件

建構式在物件建立時自動執行，名稱與類別相同，而且沒有回傳型別，連 void 都不能寫。它的工作不是「稍後修補」，而是讓物件從生命開始就滿足規則。若類別完全沒有使用者宣告的建構式，編譯器通常可產生預設建構式；一旦宣告了帶參數建構式，無引數版本不會因此自動保留。

#include <iostream>
class Reading {
    double value_;
public:
    Reading() : value_{0.0} {}
    Reading(double value) : value_{value} {}
    double value() const { return value_; }
};
int main() {
    Reading empty;
    Reading sample{18.5};
    std::cout << empty.value() << " " << sample.value() << '\n';
}
預期輸出
0 18.5

Reading empty; 尋找無參數建構式；Reading sample{18.5}; 尋找能接收 double 的候選。冒號後是 member initializer list，它在進入建構式本體前直接初始化成員。若只寫 Reading(double v) { value_=v; }，value_ 會先經歷預設初始化，再被指定；對需要建構的成員可能多做一次工作。

不要假設 Reading empty; 會把普通基本型別成員自動清成 0。上例能保證 0，是因為無參數建構式明寫 value_{0.0}。

動手練習

只保留 Reading(double) 後，Reading r; 為何失敗？

看解答與理由

呼叫沒有引數，但類別只有需要一個 double 的候選；編譯器不會因為你需要就額外合成無參數建構式。應明確提供 Reading() 或合適的預設引數。

PART 03

類內初值與初始化串列如何合作

資料成員可以在類別定義內提供 in-class initializer，作為建構式沒有另外指定時的後備初值。這能把共同預設集中一處；某個建構式若在初始化串列提供該成員，便使用建構式的值。

#include <iostream>
#include <string>
class Reading {
    std::string label_{"untitled"};
    double value_{0.0};
public:
    Reading() = default;
    Reading(std::string label, double value)
        : label_{label}, value_{value} {}
    void show() const { std::cout << label_ << ": " << value_ << '\n'; }
};
int main() {
    Reading first;
    Reading second{"room", 21.5};
    first.show();
    second.show();
}
預期輸出
untitled: 0
room: 21.5

= default 要求編譯器產生無參數建構式；其成員使用類內初值。第二個建構式逐一覆蓋 label_ 與 value_ 的後備值。成員真正的初始化順序永遠依它們在類別中宣告的順序，不依初始化串列書寫順序，因此串列最好也照宣告順序排列。

動手練習

value_ 有類內初值 0，而某建構式寫 : value_{8}，最後是哪個值？

看解答與理由

8。類內初值是後備方案；該建構式已直接指定 value_ 的初始化式。

PART 04

this、物件指標、點號與箭頭

每次呼叫非 static 成員函式，都有一個隱含的 this 指標，指向此次呼叫的物件。直接寫 value_ 等同 this->value_。參數與成員同名時，this-> 能明確指出左側成員。

#include <iostream>
class Reading {
    double value_{0.0};
public:
    explicit Reading(double value) : value_{value} {}
    void setValue(double value) { this->value_ = value; }
    double value() const { return value_; }
};
int main() {
    Reading room{20.0};
    Reading* p{&room};
    room.setValue(21.0);
    p->setValue(22.5);
    std::cout << room.value() << " " << (*p).value() << '\n';
}
預期輸出
22.5 22.5

物件本身用 .；物件指標用 ->。p->value() 等同 (*p).value()，括號不能省，因為點號的優先順序高於解參考。箭頭不會替你檢查空指標；p 必須指向仍存活的 Reading。explicit 則防止單一引數建構式被拿來做意外的隱式轉換。

動手練習

p 是 Reading*，哪個呼叫正確：p.value() 或 p->value()？

看解答與理由

後者。p 本身是指標而不是 Reading 物件；也可寫成較冗長的 (*p).value()。

同型別物件之間的連結：一步一步追蹤工作流程

物件指標也可以成為資料成員。以下每個 WorkStep 保存步驟名稱，以及下一個步驟的位址；它表達的是物件之間的連結。這個例子中的所有步驟都由 main 建立，next 只借用它們的位址，不負責配置或釋放。

#include <iostream>
#include <string>
class WorkStep {
public:
    std::string name;
    WorkStep* next;
    WorkStep(std::string text) : name(text), next(nullptr) {}
};
int main() {
    WorkStep pack("包裝"), check("檢查"), send("寄出");
    pack.next = &check;
    check.next = &send;
    WorkStep* current = &pack;
    while (current != nullptr) {
        std::cout << current->name << '\n';
        current = current->next;
    }
}
預期輸出
包裝
檢查
寄出

宣告中的 WorkStep* 表示指向另一個 WorkStep，並不把另一個完整物件塞進自身。pack.next 保存 check 的位址，check.next 保存 send 的位址，send.next 則仍為 nullptr。current 每輪換成目前步驟的 next；改變的是走訪指標，三個步驟物件的位置與名稱都沒有被修改。

箭頭每次只前進一層：current->name 讀目前物件的名稱；current->next 讀目前物件保存的下一個位址。進入本體前先排除 nullptr，走到 send 之後取出的 next 為空，下輪便停止。這也說明為什麼不能直接把「指標非空」當作完整安全保證：本例還依賴三個區域物件一直存活到 main 結束。

動手練習

若把 check.next 改成 nullptr，會印幾行？send 是否因此消失？

看解答與理由

只印包裝與檢查兩行。連結變短並不銷毀 send；它仍是 main 裡的區域物件，只是這次走訪無法經由 next 抵達它。

PART 05

public、private 與不變條件

public 是使用者可依賴的介面；private 是類別自己維護的實作細節。class 在未標示時預設 private。封裝的目的，是讓每一次狀態改變都通過能檢查規則的入口，而不是機械地替每個欄位做無條件 setter。

#include <iostream>
class Reading {
    double value_{0.0};
public:
    explicit Reading(double value) { setValue(value); }
    bool setValue(double value) {
        if (value < -100.0 || value > 100.0) return false;
        value_ = value;
        return true;
    }
    double value() const { return value_; }
};
int main() {
    Reading r{20.0};
    std::cout << r.setValue(150.0) << " " << r.value() << '\n';
}
預期輸出
0 20

不變條件是所有公開操作前後都必須成立的規則；此例要求 value_ 落在 -100 到 100。建構式与 setter 共用同一檢查路徑，失敗時保留原值。若 value_ 是 public，外部可直接寫 150，類別就無法保證自己的承諾。更嚴格的設計可能讓無效建構直接丟出例外；這裡先用普通回傳值表達結果。

Reading r{20.0};
// r.value_ = 150.0; // 編譯錯誤：value_ 是 private
動手練習

為什麼「private 欄位 + 不檢查的 setValue」未必形成有效封裝？

看解答與理由

若 setter 接受任何值，外部仍可透過公開介面破壞規則。關鍵是公開操作是否維持不變條件，而不只是欄位能否直接碰到。

PART 06

三個 const 位置，承諾不同

double value() const 的尾端 const 約束隱含的 this：此函式不能經由一般成員修改物件狀態，因此可對 const Reading 呼叫。它不表示回傳值自動成為 const。相反地，回傳 const T& 是限制呼叫端透過回傳的參考修改那個 T。

#include <iostream>
#include <string>
class Reading {
    std::string label_{"room"};
    double value_{21.0};
public:
    double value() const { return value_; }
    const std::string& label() const { return label_; }
};
int main() {
    const Reading r;
    double copy = r.value();
    const std::string& view = r.label();
    std::cout << view << " " << copy << '\n';
}
預期輸出
room 21

第一個函式按值回傳 double，呼叫端修改 copy 不影響物件。第二個回傳內部 string 的唯讀參考，避免複製並阻止經由 view 修改；但參考不能活得比 r 久。若把尾端 const 拿掉，兩個函式都不能對 const r 呼叫，即使函式本體看起來只讀。

動手練習

const std::string& label() const 中兩個 const 各約束什麼？

看解答與理由

前面的 const 使回傳參考只能讀 string；尾端 const 使函式承諾不經由 this 修改 Reading，因而可對 const 物件呼叫。

PART 07

建構式候選：先看引數，再比較轉換

物件建立式會形成一組可見的建構式候選。編譯器先淘汰引數個數或型別不能成立者，再比較所需轉換，選唯一最佳者；若沒有可行候選或同樣好，就編譯失敗。這個選擇在編譯時完成。

class Timer {
public:
    Timer();
    explicit Timer(int seconds);
    Timer(int minutes, int seconds);
};
Timer a;          // Timer()
Timer b{30};      // Timer(int)
Timer c{2, 15};   // Timer(int, int)
// Timer d{1,2,3}; // 沒有三參數候選

建構式候選播放器

用 Timer c{2,15} 逐步篩選候選。

Timer();
explicit Timer(int seconds);
Timer(int minutes, int seconds);
Timer c{2, 15};


預設引數也會影響候選可行性。若同時有 Timer(int) 與 Timer(int,int=0)，Timer{30} 會多義。不要靠加入更多相似多載來猜使用者意圖；讓每種建立方式有清楚且不重疊的呼叫形狀。


動手練習
已有 Timer() 與 Timer(int seconds=0)，無引數建立 Timer 會選哪個？
看解答與理由
兩個候選都可行且沒有唯一更好者，因此多義並編譯失敗。移除重疊的預設引數或其中一個版本。





PART 08
解構、生命週期與基本複製


#include <iostream>
class Timer {
    int seconds_{0};
public:
    explicit Timer(int seconds) : seconds_{seconds} {
        std::cout << "construct " << seconds_ << '\n';
    }
    Timer(const Timer& other) : seconds_{other.seconds_} {
        std::cout << "copy " << seconds_ << '\n';
    }
    ~Timer() { std::cout << "destroy " << seconds_ << '\n'; }
};
int main() {
    Timer first{5};
    { Timer second{first}; }
    std::cout << "after block\n";
}
預期輸出
construct 5
copy 5
destroy 5
after block
destroy 5



建構完成後物件生命開始；離開作用域時自動呼叫 ~Timer()，名稱前有波浪號、沒有參數與回傳型別。內層 second 先離開，所以先解構；first 活到 main 結束。解構式用於釋放物件擁有的資源，普通數值成員通常不需要自行清理。


Timer second{first} 呼叫 copy constructor，以既有同型物件建立新物件。兩者之後仍是獨立 instance。若沒有自訂版本，編譯器的基本行為通常逐成員複製；當類別直接擁有裸指標資源時，淺複製可能使兩個物件誤以為擁有同一資源，需改用安全成員或完整設計複製語意。


物件生命週期播放器
觀察內層物件先銷毀。
Timer first{5};
{
  Timer second{first};
}
std::cout << "after block\n";


動手練習
second 是 first 的 copy；修改 second 的 int 成員會自動改 first 嗎？
看解答與理由
不會。逐成員複製會建立另一份 int。只有成員本身代表共享或別名關係時，才需要進一步分析是否指向同一資源。





PART 09
operator<< 與 friend：維持串接慣例


#include <iostream>
class Reading {
    double value_{0.0};
public:
    explicit Reading(double value) : value_{value} {}
    friend std::ostream& operator<<(std::ostream& out, const Reading& r) {
        out << r.value_;
        return out;
    }
};
int main() {
    Reading r{23.5};
    std::cout << "reading=" << r << '\n';
}
預期輸出
reading=23.5



左運算元是 std::ostream，不是 Reading，所以這個 overload 寫成非成員函式。第一參數用 ostream&，因為輸出要累積在同一個 stream；第二參數用 const Reading&，避免複製且承諾不改物件。回傳同一個 out 的參考，才能讓 std::cout << r << "\n" 繼續串接。


friend 讓這個指定函式可讀 private 成員，它不是成員函式，也沒有 this。friend 會擴大可接觸內部狀態的範圍，因此只授權確實需要的函式；若公開 getter 已足夠，也可不用 friend。


動手練習
operator<< 若回傳 void，最直接失去什麼？
看解答與理由
無法自然串接下一個 <<。標準慣例回傳收到的 std::ostream&。





PART 10
組合：一個物件擁有另一個物件


#include <iostream>
#include <string>
class Reading {
    double value_{0.0};
public:
    explicit Reading(double value) : value_{value} {}
    double value() const { return value_; }
};
class Parcel {
    std::string id_;
    Reading weight_;
public:
    Parcel(std::string id, double weight)
        : id_{id}, weight_{weight} {}
    void show() const { std::cout << id_ << " " << weight_.value() << '\n'; }
};
int main() { Parcel box{"A17", 2.4}; box.show(); }
預期輸出
A17 2.4



Parcel 的 weight_ 是一個 Reading 子物件，表示 has-a 關係。建立 Parcel 時，成員必須先完成建構，才進入 Parcel 建構式本體；因此初始化串列把 weight 傳給 Reading 建構式。銷毀時順序反過來：先完成 Parcel 解構式本體，再自動銷毀成員。


若 Reading 沒有無參數建構式，省略 weight_{weight} 就會失敗，因為 C++ 會嘗試先無參數建立 weight_。組合通常比手動 new 一個成員更簡單：Parcel 的生命週期自動包含其 Reading，不需要自己 delete。


動手練習
為何不能等進入 Parcel 建構式本體後才「建立」weight_？
看解答與理由
進入本體前所有資料成員都必須已初始化。初始化串列負責選擇 Reading 建構式；本體內的指定只能修改一個已存在的成員。





PART 11
從類別宣告到多檔程式


標頭檔放呼叫端需要看見的類別宣告，來源檔放非 inline 成員的定義，main.cpp 使用公開介面。Reading::value 中的 :: 是 scope resolution operator，表示這個 value 函式屬於 Reading；少了 Reading:: 就是在定義無關的自由函式。


Reading.hpp
#ifndef READING_HPP
#define READING_HPP
#include <iosfwd>
#include <string>
class Reading {
    std::string label_;
    double value_{0.0};
public:
    Reading(std::string label, double value);
    const std::string& label() const;
    double value() const;
    friend std::ostream& operator<<(std::ostream&, const Reading&);
};
#endif


Reading.cpp
#include "Reading.hpp"
#include <ostream>
Reading::Reading(std::string label, double value)
    : label_{label}, value_{value} {}
const std::string& Reading::label() const { return label_; }
double Reading::value() const { return value_; }
std::ostream& operator<<(std::ostream& out, const Reading& r) {
    return out << r.label_ << ": " << r.value_;
}


main.cpp
#include "Reading.hpp"
#include <iostream>
int main() {
    Reading room{"room", 22.5};
    std::cout << room << '\n';
}


g++ -std=c++17 -Wall -Wextra -pedantic Reading.cpp main.cpp -o reading
./reading


include guard 的三行形成條件：第一次包含時 READING_HPP 尚未定義，因此讀入內容並定義它；同一 編譯單元（每個 .cpp 經過 include 展開後交給編譯器的內容） 再包含時便跳過，避免類別重複定義。巨集名稱要在專案內唯一。標頭只前向需要的 stream 型別，因此用 <iosfwd>（只提供 ostream 等串流型別的宣告，不提供輸出操作的完整定義）；真正輸出操作所在的 Reading.cpp 再包含 <ostream>。


編譯命令同時提供兩個 .cpp，讓它們各自編譯後再連結。只編 main.cpp 時，宣告足以讓呼叫通過編譯，卻會在連結階段找不到 Reading 的建構式與 operator<< 定義。不要在 main.cpp 直接 include Reading.cpp；應 include 標頭並把來源檔交給編譯器。


動手練習
為何 Reading.cpp 第一行仍要 include 自己的 Reading.hpp？
看解答與理由
它讓編譯器用同一份宣告檢查類別外定義，能及早抓出參數、const 或回傳型別不一致；也確保來源檔獨立取得所需宣告。





PART 12
P8 語法速查


概念寫法判斷重點
物件成員object.member()左側是物件
指標成員pointer->member()指標非空且目標存活
建構式Reading(...) : member_{...} {}成員先於本體初始化
const 成員value() const可對 const 物件呼叫
唯讀回傳const T& view() const回傳參考不可比物件長壽
解構式~Reading()生命結束時自動呼叫
類別外定義T Reading::value() const簽章須與宣告一致
include guard#ifndef / #define / #endif防同一翻譯單元重複定義


動手練習
看到 const T& get() const，應分別問哪兩件事？
看解答與理由
問回傳參考能否修改 T，以及函式能否修改／能否對 const 物件呼叫；前後兩個 const 是不同承諾。
