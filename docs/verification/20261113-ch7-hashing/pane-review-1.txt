已逐段核對十個新推導、講義與頁面正文／收合區，並在記憶體中重算及執行頁面的計數函式；未修改或建立檔案。以下區分本輪新增問題與既存問題。

• 【必改｜新增】quick_analysis 的比較次數模型與本章實作不一致。
位置：search_more.py:313 (tools/enrich/content/search_more.py:313)、頁面:2446 (searching_sorting.html:2446)。原句：「分割要比約 n-1 次」，接著使用等式遞迴式，推出
「\(1.39n\log_2n\)」「多約 39%」。本章 partition 會重複比較交換前後的元素：直接執行頁面函式，[2,3,1] 的一次 partition 是 5 次，並非 n-1=2；[1,2,3,4] 完整排序是 9 次，並非
3+2+1=6。枚舉三個不同元素的全部排列，實際平均為 4 次，該遞迴式則給 8/3。遞迴式的代數運算本身正確，但不能把其常數套在目前實作。建議明示這是「每次 partition 恰比較 n-1 次的理想模
型」，或依實際計數重新推導；目前應撤掉與本章實作連在一起的「多 39%」。

• 【必改｜新增】load_analysis 混用了精確值、漸近近似與計數單位。
位置：search_more.py:238 (tools/enrich/content/search_more.py:238)、頁面:1657 (searching_sorting.html:1657)。原句：「平均比較次數如下」，以及積分結果「和上面的加總結果一致」。鏈
結法加總是
\[
1+\frac{n-1}{2m},
\]
積分卻是 1+n/(2m)，兩者差 1/(2m)，只能說近似一致。線性探查公式也不是任意有限表的精確值：m=2,n=1 時，失敗搜尋有一半機會探查一次、一半兩次，精確平均 1.5，表中公式給 2.5。另線性探查
計入最後的空槽，是「探查次數」；鏈結法算的是 key 比較次數。建議標明大表近似、線性探查的 0≤λ<1、成功查詢等機率及無刪除／搬移的假設；先寫離散平均，再以 ≈ 接到積分，並分清兩種計數單
位。

• 【必改｜新增】shell_bounds 目前證明的是下界，不能據此推出上界。
位置：search_more.py:288 (tools/enrich/content/search_more.py:288)、頁面:2165 (searching_sorting.html:2165)。原句：「為什麼本章的折半增量最差是 O(n²)」，接著只構造需要約 n²/8 次
位移的輸入。這證明最差情況是 Ω(n²)。建議補上：gap 為 g 時有 g 組、每組長約 n/g，該輪至多 O(n²/g)；折半 gap 的倒數和有常數上界，因此總計 O(n²)，合起來才是 Θ(n²)。
131328 次位移確認無誤：使用 [513,1,514,2,…,1024,512]，前面各輪零位移，最後一輪正好 512×513/2=131328。這個反例同時否定正文「最後 gap = 1……此時資料已經幾乎排序好」作為普遍保證的寫
法（頁面:2056 (searching_sorting.html:2056)）；應改成通常的直覺，保留最差例外。

• 【必改｜新增推導與既存文字】平均分析缺少「元素互異」假設，快速排序的嚴格大小敘述也不適用重複值。
位置：search_more.py:260 (tools/enrich/content/search_more.py:260)、search_more.py:280 (tools/enrich/content/search_more.py:280)、search_more.py:313 (tools/enrich/content/
search_more.py:313)。原句分別是「n+1 個空隙」、「任一對位置是逆序的機率是 1/2」、「pivot 最後落在每個位置的機率都是 1/n」。這些分析需要互異元素及相應的均勻抽樣假設；有重複值時不
能直接使用。全相等輸入隨機打亂後，插入排序仍只有 n-1 次比較，本章 quicksort 卻仍退化成二次時間。建議在三段開頭補齊假設；頁面:2331 (searching_sorting.html:2331) 的「左邊都小於
pivot，右邊都大於 pivot」改為「左邊不大於、右邊不小於」，詞彙卡的 Split Point 同步修正。

• 【建議｜新增推導揭露既存不一致】有序循序搜尋表仍把近似值寫成精確平均。
位置：頁面:713 (searching_sorting.html:713)、頁面:741 (searching_sorting.html:741)。原句：「預期比較次數降到 n/2」，表格平均欄也直接填 n/2。新推導在等機率空隙模型下算出的
\[
\frac n2+\frac{n}{n+1}
\]
算式正確；成功搜尋則是 (n+1)/2。例如 n=10，分別是 65/11≈5.909 與 5.5，都不是 5。建議表中填精確值，或將欄名改為「平均（大 n 近似）」；正文也要附上失敗查詢等機率落在各空隙的條件。

• 【建議｜新增】gcd_block 跳過了證明週期長度的關鍵一步。
位置：search_more.py:161 (tools/enrich/content/search_more.py:161)、頁面:1253 (searching_sorting.html:1253)。原句：「g 的倍數只有 m/g 個，而它們剛好全部走得到。」前面只證明不會走
出這些位置，尚未證明全部可達。可補兩句：令 s=gs'、m=gm'，其中 \(\gcd(s',m')=1\)；回到起點需要 \(m\mid ts\)，等價於 \(m'\mid t\)，最小正整數 t=m'，故週期正好 m/g。公式與列出的數例
重算均正確。

• 【建議｜新增】why_block 的雜湊表成本缺少容量與分布條件。
位置：search_more.py:32 (tools/enrich/content/search_more.py:32)、頁面:545 (searching_sorting.html:545)。原句：「找最小值、列範圍都得把元素全部看一遍，O(n)；只有『在不在』能直接
算出位置，平均 O(1)。」對本章掃描 slot 的實作，走完整張表花 O(m)，不能省略容量 m；平均常數查詢也需要良好分布及受控負載。建議表前限定 m=Θ(n)、雜湊計算為常數時間、負載控制得當。其
餘 vector 的 O(log n+k) 推導確認無誤。

• 【建議｜新增】merge_bound 的 nlog n 是合併寫入量，不能含混當成精確比較次數。
位置：search_more.py:299 (tools/enrich/content/search_more.py:299)、頁面:2295 (searching_sorting.html:2295)。原句：「設排 n 個元素要 T(n) 次操作」，接著令 T(n)=2T(n/2)+n。此模型
在 n=2ᵖ 時展開正確，但本章前言宣稱分析一律以比較次數計算。實際動畫對 [1,2,3,4] 是 4 次比較、8 次寫入；\(n\log_2n=8\) 對應後者。建議明確命名為「合併寫回元素的次數」，或把比較次數
遞迴式改成最差的 C(n)=2C(n/2)+n-1。後半的決策樹下界推導本身確認無誤。

• 【必改｜本輪要求尚未完成】兩個核心結論仍然只有引用，沒有推導。
頁面:1666 (searching_sorting.html:1666) 原句：「把群聚算進去……得到……；這一步要用到較多的組合計數，這裡不展開。」前面的幾何級數只能推出隨機探查模型的 1/(1-λ)，不能推出線性探查的平
方分母。
頁面:2165 (searching_sorting.html:2165) 原句：「最差比較次數是 O(n^{3/2})；證明需要較多的數論與計數。」相鄰增量互質也不足以推出此界。兩個結論不是因此變錯，但仍未達成「非平凡結論
附推導」的要求。建議補足關鍵計數／引理；若不展開，應明標為引用定理，不能將該部分稱為已完成推導。

• 【建議｜既存缺漏】仍有三處複雜度缺少對應的短推導。
頁面:936 (searching_sorting.html:936) 的「精確的最多次數是 \(\lfloor\log_2n\rfloor+1\)」，目前只由近似折半說明帶過；可補 B(0)=0, B(n)=1+B(⌊ n/2⌋)。
頁面:2774 (searching_sorting.html:2774) 的 Shell 最佳 O(nlog n) 尚未推導；已排序且 n=2ᵖ 時，每輪比較 n-g 次，加總為 \(n\log_2n-n+1\)。
頁面:2294 (searching_sorting.html:2294) 的 merge 峰值額外空間 O(n) 尚未解釋為何不再乘遞迴層數；可補同時存活的各層暫存量受 n+n/2+n/4+⋯<2n 控制。

• 【必改｜收合要求未完成】部分明確超出講義的內容仍在正文。
頁面:1361 (searching_sorting.html:1361)：「次要群聚（secondary clustering）……主要群聚（primary clustering）」及「11 格裡只碰得到其中 6 格」仍在收合區外；講義只介紹平方探查序列與
範例，未講這些性質。相同結論又出現在 頁面:1439 (searching_sorting.html:1439) 的摘要框及 頁面:2995 (searching_sorting.html:2995) 的回顧。
頁面:2237 (searching_sorting.html:2237)：「任何只透過比較來排序的演算法都至少要 Ω(nlog n)」仍在正文；講義沒有比較式排序下界，而且此句漏了「最差情況」。
頁面:2393 (searching_sorting.html:2393) 的「std::stable_sort() 保證穩定」，以及 頁面:866 (searching_sorting.html:866) 的 C++20 前轉型規則，也超出講義直接講授內容。建議將這些延伸
移入標「（補充）」的收合區，連同重複摘要一起處理。Hibbard 的 O(n^{3/2}) 與負載公式本來就出現在講義，不能把它們誤判為講義完全未涵蓋。

• 【必改｜既存事實錯誤】「沒有系統化方法造出完美雜湊函數」不正確。
位置：頁面:1030 (searching_sorting.html:1030)，另見 1127
行「不存在通用方法」。原句：「給定任意一組資料，並沒有系統化的方法造出完美雜湊函數。」對已知靜態鍵集合，已有建構方法與產生器；GNU gperf 官方說明
(https://www.gnu.org/software/gperf/) 就是直接反例。這句雖沿用講義，仍應修正為：「一般用途的固定雜湊函數不能保證對任意輸入集合都沒有碰撞；已知靜態集合可另外建構完美雜湊函數。」

• 【必改｜既存事實錯誤】鏈結串列二分搜尋被誤寫成不能做、必然 O(nlog n)。
位置：頁面:2677 (searching_sorting.html:2677)，來源 search_legacy.py:815。原句：「總時間……退化成 O(nlog n)……必須轉成
Array。」這只適用於每次從整條串列開頭重新按索引尋址的做法。保留目前區間起點後，走訪量可由 n+n/2+n/4+⋯ 控制為 O(n)，比較仍為 O(log n)；C++ 標準草案
(https://eel.is/c++draft/alg.binary.search) 也明載非隨機存取 iterator
的線性步數。建議改為「可以做，但不能得到陣列版的對數總時間」。同表把氣泡／選擇排序的必要屬性寫成隨機存取，也過強：循序掃描並保留節點指標即可實作。

• 【必改｜既存矛盾】空間複雜度與「就地」定義前後衝突。
頁面:2393 (searching_sorting.html:2393) 說 quicksort「不需要 O(n) 額外空間」，但比較表正確列出最差遞迴空間 O(n)。頁面:2802 (searching_sorting.html:2802) 又把就地定義成僅用 O(1)
或 O(log n)，再無條件稱 quicksort 就地，與本章最差情況不相容。應分開說明「partition 不需額外陣列」及「遞迴堆疊平衡時 O(log n)、最差 O(n)」。
另 頁面:2689 (searching_sorting.html:2689) 將 linked-list merge 的 O(1) 指標空間直接當作整個 merge sort 的空間；遞迴版仍有 O(log n) 堆疊，只有適當的迭代版本才能宣稱整體 O(1)。

• 【必改｜既存矛盾】put() 補充區把「沒有新增碰撞」誤寫成「不需要探查」。
位置：頁面:2893 (searching_sorting.html:2893)、來源 search_legacy.py:1011 (tools/enrich/content/search_legacy.py:1011)。原句：「同一個 key 重複 put……不會觸發任何 rehash。」後面的
第四個例子 put(44,"lamb") 就必須由 slot 0 探查到 slot 1，直接反駁此句。應改成「不新增 entry；若既有 key 曾因碰撞移位，仍須沿原探查路徑找到它」。同表「hash 值不同……各走各的 slot，
互不相干」也錯：77、44、1 依序插入時，44 會占 slot 1，使原本 hash 為 1 的 key 也必須探查。

• 【必改｜既存計數缺漏】median-of-three 動畫沒有計入選 pivot 的比較。
位置：頁面:3754 (searching_sorting.html:3754)。程式用 candidates.sort((x,y) => x.v-y.v) 找中位數，沒有增加 cmp。直接執行 [1,2,3] 的 median 模式，在「三者取中」完成時仍顯示 0 次比
較，最後標示總共 3 次，實際漏算選 pivot 的比較。因此兩種 pivot 策略的統計不能公平比較。建議使用明確計數的三數取中程序，或將欄名改成「partition 比較次數，不含選 pivot」。

• 【建議｜既存過度保證】三數取中與效能建議需要收斂措辭。
詞彙卡:37 (data/flashcards_zh/ch7.json:37) 原句：「取……中位數，避開最差情況。」全相等輸入就是反例：本章即使三數取中，每次仍切成 n-1 與 0。改成「可減輕某些輸入造成的不平衡，但不保
證避開最差情況」。頁面:2789 (searching_sorting.html:2789) 的「實務通用、最快」「常數最小」也沒有通用保證，建議刪除絕對排名，改述適用條件。

另外，quad_note 的奇質數條件、(m+1)/2 個位置及半滿以下插入保證，selection_count 的比較與最多交換次數，以及 merge_bound 的決策樹下界，均已獨立驗算，確認無誤；insertion_count 的逆序
對推導在補齊互異元素假設後也成立。

總評：這輪補上了不少有效推導，但計數模型、漸近近似與上／下界仍有實質問題，且正文收合範圍和原有矛盾尚未清乾淨，目前不宜視為完成驗收。
