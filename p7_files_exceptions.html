PART 00 · 檔案與錯誤

讓資料留下來，並處理走不通的路

本頁先讀寫文字檔，再學習開檔失敗、界線檢查與例外傳遞。檔案範例可以獨立執行，不需其他教材資料。這些做法也適用於一般程式的輸入驗證與錯誤回報。

PART 01 · 檔案

讀檔與寫檔：三個型別、一個模式

檔案串流物件會管理它開啟的檔案。物件生命週期結束時，會執行稱為解構式（destructor）的收尾函式。先理解「物件負責管理資源」即可；本頁使用標準類別，不需要先自行撰寫解構式。

ofstream 寫、ifstream 讀，用法跟 cout／cin 一模一樣 —— 因為它們是同一家族。

寫進去再讀回來
#include <iostream> #include <fstream> #include <string> using namespace std; int main() { ofstream out("notes.txt"); // 開檔寫入，不存在就建立 if (!out.is_open()) { cout << "開檔失敗" << endl; return 1; } out << "READ" << endl << "CHECK" << endl << "SEND" << endl; out.close(); // 也可以讓它離開範圍自動關 ifstream in("notes.txt"); // 開檔讀取 string line; int n = 0; while (getline(in, line)) { // 逐行讀到檔尾 cout << ++n << ": " << line << endl; } return 0; }
預期輸出
1: READ
2: CHECK
3: SEND

三個重點：① 檔案串流需 <fstream>。② getline 回傳串流參考，while 依讀取狀態判斷是否繼續；最後一行沒有換行也可成功讀取。③ 物件正常離開作用域時解構式會關檔，但本例要在 out 還活著時立刻讀同一檔案，所以先明確 close，確保寫入完成。

寫法意思
ifstream in("a.txt");開檔讀取
ofstream out("a.txt");開檔寫入，清空原內容
ofstream out("a.txt", ios::app);附加到結尾
getline(in, line)讀取一行，回傳串流；作條件時反映這次讀取是否成功
in >> word讀一個「詞」，以空白切開

順便：字串也能當「檔案」讀 —— stringstream

stringstream 是這一家族的第三個成員：把字串當成 cin 來讀，>> 一樣自動以空白切詞、照變數型別轉換。跟 P1 用 istringstream 模擬鍵盤輸入是同一家，只是 stringstream 讀寫都能做。

將一行用品記錄逐詞讀出
#include <iostream> #include <sstream> #include <string> using namespace std; int main() { stringstream input("pencil blue 12"); string token; while (input >> token) { cout << "[" << token << "] "; } cout << endl; }
預期輸出
[pencil] [blue] [12]

stringstream 讓字串也能用串流的 >> 規則逐項解析，並依目標型別轉換。獨立程式應明確 #include <sstream>，不要依賴特定環境自動引入。

PART 02 · 開檔失敗

檔案開啟失敗時，串流會進入失敗狀態

開一個不存在的檔案
#include <iostream> #include <fstream> using namespace std; int main() { ifstream in("no_such_file.txt"); cout << "is_open() = " << in.is_open() << endl; cout << "檔案不存在時 ifstream 不會丟例外，只是進入失敗狀態。" << endl; cout << "所以開檔之後一定要自己檢查。" << endl; return 0; }
預期輸出
is_open() = 0
檔案不存在時 ifstream 不會丟例外，只是進入失敗狀態。
所以開檔之後一定要自己檢查。

在串流的預設設定下，它不主動拋出串流例外，也不終止程式，只是把串流設成失敗狀態。你如果不檢查就直接讀，會讀到零筆資料然後難以判斷原因。所以 ifstream 開完一定要接一句 if (!in.is_open())。

✅ 相對路徑是相對於「執行時的工作目錄」

檔案讀取失敗時，先確認工作目錄、檔名及開檔狀態，再檢查資料格式。相對路徑以執行時的工作目錄為基準。

PART 03 · 例外

例外不是「壞掉」，是「這條路走不通，換你決定」

例外處理先看三個動作：try 圈出要處理例外的程式，throw 拋出例外物件，catch 依型別接住它。catch (const SpecificError& e) 中，SpecificError 是例外型別，e 是本次例外的唯讀參考，e.what() 取得說明文字。

下面先看語法骨架：risky() 代表可能失敗的函式，SpecificError 代表要捕捉的例外型別，兩者都是占位名稱，不是標準函式或可直接執行的程式。後面的完整範例會換成 readAge 與 invalid_argument。

try { // 可能失敗的那幾行，範圍越小越好找錯 risky(); } catch (const SpecificError& e) { // 只接住你預期會發生的那一種 cout << "拋出例外時: " << e.what() << endl; } // 接住之後程式繼續往下跑
C++Python備註
try { } catch (…) { }try: / except:概念相同
throw X();raise X()主動拋出
e.what()str(e)取得訊息
沒有對應finally:RAII（Resource Acquisition Is Initialization）：物件取得並管理資源，在解構時釋放。例如區域 ifstream 物件離開作用域時會關檔；找到相符 catch 的例外傳遞途中也會清理這類物件
沒有對應else:C++ 沒有這個區塊
⚠️ catch (...) 接得住哪些問題

catch (...) 接住所有傳到此處的 C++ 例外，但不能處理一般的未定義行為或記憶體存取錯誤。它可用於清理後重新拋出，或在程式邊界統一回報；若接住後不記錄、不處理，就可能掩蓋問題。

同一段程式，餵不同的輸入就會走出兩條完全不同的路。按下面兩顆 ▶ 各跑一次，注意例外那條路上 readAge 的框是什麼時候消失的。

#include <iostream> #include <stdexcept> using namespace std; int readAge() { int age; cin >> age; if (age < 0) { throw invalid_argument("年齡不能是負數"); } return age; } int main() { try { int age = readAge(); cout << "年齡：" << age << endl; } catch (const invalid_argument& e) { cout << "輸入有問題：" << e.what() << endl; } cout << "程式繼續往下跑" << endl; return 0; }
›選一條路開始。同一份程式碼，合法輸入與負數輸入走的路完全不同。
速度
堆疊解開 UNWIND

例外不是從 throw 直接跳到 catch。它會沿著呼叫鏈往回走，把中間每一個函式的框架逐一撤掉，撤掉時該框架裡區域物件的解構式都會被呼叫 —— 這叫 stack unwinding。所以檔案串流這類物件不必手動收尾，例外飛過去的時候它們也會自己關好。

型別要對得上 MATCH

catch 只接住型別相符的例外。丟 invalid_argument、只寫 catch (const out_of_range& e)，例外就會穿過去繼續往上飛；一路到 main 外面都沒人接，程式直接 terminate 終止。標準例外型別繼承自 std::exception，所以 catch (const exception& e) 應放在各種較具體的標準例外之後；它不會接住 throw 3; 這種不屬於該類別家族的例外。最後的 catch (...) 才能接住其他 C++ 例外。繼承關係的語法見 P9。

PART 04 · at() 與 []

兩個下標寫法，一個檢查範圍一個不檢查 查錯時用得到

同一個越界存取，兩種下場
#include <iostream> #include <vector> #include <stdexcept> using namespace std; int main() { vector<int> v = {10, 20, 30}; // 錯誤示範：v[10] 越界，行為未定義，因此不執行。 try { cout << "trying at: "; int value = v.at(10); cout << value << endl; } catch (const out_of_range& e) { cout << "caught out_of_range" << endl; cout << "details: " << e.what() << endl; } cout << "continue" << endl; }
預期輸出
trying at: caught out_of_range
details: （由實作提供的錯誤描述）
continue

vector 的 v[10] 不符合有效索引前提，屬未定義行為，所以只留在註解中。實際執行的是 v.at(10)：它丟出 out_of_range，catch 接住後可繼續執行。what() 訊息依實作而異；trying at: 已在拋出之前輸出，例外不會回復先前的副作用。

常見標準例外什麼時候發生
out_of_rangevector::at()、string::at() 越界
invalid_argumentstoi("abc") 這種轉不了的輸入
bad_allocnew 要不到記憶體
runtime_error通用的執行期錯誤，自訂例外常繼承它
🎯 什麼時候用哪個

不確定索引時，at() 的範圍檢查能讓錯誤較早被發現。已確認合法且需要控制檢查成本時可用 []；兩者差別是介面契約，不是「所有程式都該用某一個」。string 的 size() 位置另可讀結尾空字元，不能把它和 vector 的界線完全混同。

PART 05 · 主動拋出

用 throw 主動回報輸入問題

函式無法接受輸入時，可以透過例外回報。本例遇到負數就拋出 invalid_argument；正常路徑只回傳已通過檢查的數量。

負數數量應立即拒絕
#include <iostream> #include <stdexcept> using namespace std; int checkedQuantity(int n) { if (n < 0) throw invalid_argument("數量不可為負數"); return n; } int main() { try { cout << checkedQuantity(-1) << endl; } catch (const exception& e) { cout << e.what() << endl; } }
預期輸出
數量不可為負數

先用標準的 invalid_argument 表達輸入不合法，throw 會離開目前正常路徑並尋找符合的 catch。等學過類別、繼承與模板後，P9 保留完整自訂例外與草稿箱例子。

💡 為什麼不回傳一個特殊值就好

特殊回傳值是否合適，取決於函式契約。例如本頁數量只允許非負值，便可另約定以 -1 表示錯誤；但若函式回傳溫度，-1 也可能是正常資料。採特殊值時，呼叫端必須檢查；採例外時，則由相符的 catch 處理。這裡使用 invalid_argument，讓正常回傳值只表達有效數量。

PART 06 · 沒人接

例外沒有人接住會怎樣

未捕捉例外的執行結果
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v = {1, 2, 3}; cout << "接下來這行會丟例外，而且沒有人接：" << endl; cout << v.at(99) << endl; cout << "這一行永遠不會被執行" << endl; return 0; }
預期輸出
接下來這行會丟例外，而且沒有人接：

[執行結束碼 -6]
terminate called after throwing an instance of 'std::out_of_range'
  what():  vector::_M_range_check: __n (which is 99) >= this->size() (which is 3)

程式會終止，後面的正常敘述不再執行。這裡的 terminate 診斷與結束碼是特定環境的示例；不能只憑 -6 判定是未捕捉例外或 assert，因為其他情況也可能呼叫 abort。定位原因時應一起閱讀例外型別、訊息與發生位置。

✅ 沒接住其實常常是對的

在有能力處理或轉譯錯誤的位置使用 catch。若目前這一層無法處理，可讓例外繼續傳遞，交由呼叫端或程式邊界統一回報。保留錯誤資訊，避免無聲忽略後繼續使用不完整的結果。
