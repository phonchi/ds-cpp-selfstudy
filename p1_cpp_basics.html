PART 01

最小完整程式與每一行的角色

#include <iostream>

int main() {
    std::cout << "Hello, C++!\n";
    return 0;
}
預期輸出
Hello, C++!

第 1 行讓程式能使用標準輸入輸出工具。int main() 宣告執行入口，外層大括號界定函式本體。輸出敘述以分號結束；字串中的 \n 是換行字元。return 0 把成功狀態交回作業系統。在 C++ 中走到 main 尾端也等同回傳 0，但初學時明寫能看清入口的回傳型別。

對照錯誤：寫成 cout 而未加 std::，編譯器不會知道你指標準函式庫裡的名稱。整頁都採明寫 std::，避免把整個命名空間匯入後產生名稱衝突。

動手練習

若刪掉輸出行末的分號，程式在哪一階段失敗？

看解答與理由

編譯階段。分號是敘述的語法界線；編譯器常在下一行才發現結構不對，所以要連同錯誤位置前一行一起看。

PART 02

把編譯與執行指令拆開

g++ -std=c++17 -Wall -Wextra main.cpp -o main
./main                 # macOS / Linux
main.exe               # Windows PowerShell / cmd

g++ 是驅動程式；-std=c++17 選定本頁採用的語言版本；-Wall -Wextra 開啟一批實用警告；main.cpp 是輸入；-o main 指定輸出檔名。第二行的 ./ 表示從目前目錄尋找並執行 main。

警告與錯誤不同：錯誤使建置失敗，警告通常仍會產生執行檔，但指出可疑程式。學習階段不要忽略警告；未初始化變數、帶號與不帶號比較等問題常先以警告露面。

建置管線播放器

逐步看同一份來源如何變成可執行檔。

#include <iostream>
int main() { std::cout << "ok\n"; }


動手練習
檔名改成 bill.cpp，希望執行檔叫 bill，命令怎麼寫？
看解答與理由
寫 g++ -std=c++17 -Wall -Wextra bill.cpp -o bill，成功後用 ./bill 執行。





PART 03
從原始碼到執行檔：四個階段


C++ 程式不能把文字檔直接交給處理器。你寫的 main.cpp 會依序經過前置處理、編譯、組譯、連結，最後才得到可執行檔。知道這條路徑的用途，是看到錯誤時能先判斷問題在哪一層。


階段輸入 → 輸出在做什麼常見問題
前置處理main.cpp → 展開後原始碼處理 #include 等指令找不到標頭
編譯C++ → 組合語言檢查型別與語法漏分號、名稱未宣告
組譯組合語言 → 目的檔轉成機器指令通常由 g++ 代辦
連結目的檔 → 執行檔接合函式定義與函式庫undefined reference


這四步通常由一個 g++ 命令代辦。若編譯錯誤，執行檔根本不會更新；此時反覆執行舊檔，看到的仍可能是上一次成功建置的結果。


動手練習
若訊息是 undefined reference to helper()，應先檢查哪一階段？
看解答與理由
這是連結階段：呼叫處已經通過編譯，但連結器找不到 helper 的函式定義或含該定義的目的檔。



「編譯器（Compiler）」與「直譯器（Interpreter）」描述處理程式的角色：前者將程式翻譯成另一種形式，後者在執行時處理程式的操作。實際系統也可能混合編譯、虛擬機與即時編譯，不能一概說成逐行執行，也不能只看語言名稱就保證固定速度差。本頁聚焦先產生執行檔、再啟動它的 C++ 建置流程。


PART 04
型別、宣告、初始化與常數


型別決定一段位元如何解讀、可做哪些運算，以及通常需要多少空間。宣告 int count; 會建立一個 int 物件並給它名稱 count；對區域基本型別而言，它沒有可靠初值，此時讀取會造成未定義行為。更安全的習慣是宣告時初始化。


#include <iostream>
#include <string>
int main() {
    int count{3};
    double price{12.5};
    bool paid{true};
    char grade{'A'};
    std::string item{"notebook"};
    const int limit{10};
    std::cout << item << ": " << count * price << "\n";
    std::cout << std::boolalpha << paid << ", " << grade << ", " << limit << "\n";
}
預期輸出
notebook: 37.5
true, A, 10



{} 是列表初始化，會拒絕部分可能丟失資訊的窄化轉換，例如 int n{3.8};。const 名稱必須初始化，之後不能被指定新值。


型別例子用途
int-7, 0, 42整數
double2.5浮點近似值
booltrue / false條件真假
char'A'單一字元
std::string"Ada"字元序列


動手練習
為何 int total; 後立刻輸出 total 不可取？
看解答與理由
區域變數沒有自動取得可靠的 0；讀取未初始化的基本型別值是未定義行為。應在宣告時給有意義的初值，例如 int total{0};。





PART 05
char、字串與 sizeof


char 保存一個字元值，字面值用單引號；std::string 保存一串字元，字面值用雙引號。char c{"A"}; 錯在右側是字串。要表達一字元字串，本頁直接寫 std::string s{"A"};，讓引號與型別一致。


#include <iostream>
#include <string>
int main() {
    char mark{'?'};
    std::string word{"ready"};
    std::cout << mark << " " << word << "\n";
    std::cout << sizeof(char) << " " << sizeof(int) << " " << sizeof(double) << "\n";
}
預期輸出
? ready
1 4 8



sizeof(T) 以 byte 回報型別或物件所占空間；標準保證 sizeof(char)==1，但一個 byte 的位元數與其他型別的大小由實作決定。上面的 4 與 8 是本教學驗證環境的結果，不該寫成所有電腦都必然如此。陣列的 sizeof 與元素個數細節留到 P4。


動手練習
哪一個表示單一換行字元：'\n' 還是 "\n"？
看解答與理由
前者是 char；後者是含換行字元的字串字面值。兩者輸出效果可相同，但型別與用途不同。





PART 06
輸入、輸出與失敗狀態


std::boolalpha 會讓之後的 bool 輸出顯示 true/false，而非 1/0。輸入運算本身也能轉成真假：成功讀取時條件為 true，失敗時為 false；所以 if (!(std::cin >> ...)) 表示「若讀取失敗」。錯誤訊息送到 std::cerr，讓它與一般結果的 std::cout 分流。


範例輸入
3 12.5

#include <iostream>
int main() {
    int quantity{0};
    double unitPrice{0.0};
    std::cout << "quantity and price: ";
    if (!(std::cin >> quantity >> unitPrice)) {
        std::cerr << "invalid input\n";
        return 1;
    }
    std::cout << "total = " << quantity * unitPrice << "\n";
}
預期輸出
quantity and price: total = 37.5



<< 把右側資料送進輸出流，能串接多項；>> 從輸入流依變數型別解析資料。若使用者在整數位置輸入文字，擷取失敗並留下失敗狀態，因此範例先檢查再計算。std::cerr 用於錯誤訊息，非零回傳值表示失敗。


動手練習
輸入 three 12.5 時，為何不應繼續印總價？
看解答與理由
第一個擷取無法把 three 解析成 int，輸入流進入失敗狀態；守衛條件立即輸出錯誤並回傳。





PART 07
運算優先順序、整數除法與更新


#include <iostream>
int main() {
    int total{17};
    int people{5};
    int each = total / people;
    int left = total % people;
    int score{10};
    score += 3;
    std::cout << each << " remainder " << left << "\n";
    std::cout << score++ << " then " << score << "\n";
}
預期輸出
3 remainder 2
13 then 14



乘、除、餘數先於加減；同一層通常由左到右。括號能直接表達意圖：(a+b)*c 與 a+b*c 不同。兩個 int 做 / 得整數商，朝 0 截斷；% 得餘數。x += y 等價於以相同效果更新 x。


score++ 先產生舊值再遞增；++score 先遞增再產生新值。單獨成行時兩者最後效果一樣，但混進較長算式容易誤判。不要在同一敘述中多次修改並讀取同一變數；拆成幾行更容易推理。


動手練習
手算 2 + 17 / 5 * 3。
看解答與理由
先做除法：17/5 是 3；再乘 3 得 9；最後加 2，答案為 11。





PART 08
轉型時機與溢位


#include <iostream>
int main() {
    int points{7};
    int judges{2};
    double wrong = points / judges;
    double right = static_cast<double>(points) / judges;
    std::cout << wrong << " " << right << "\n";
}
預期輸出
3 3.5



指定給 double 不會讓先前的整數除法復原小數：右側先算完 3，才轉成 3.0。要在除法之前把至少一個運算元轉成 double。static_cast<double> 把意圖寫明，比 C 風格強制轉型更容易檢查。


固定寬度整數能表示的範圍有限。帶號整數溢位是未定義行為，不能依賴它繞回負數；不帶號整數則按模數回繞，但仍常代表計算錯誤。可用較寬型別、輸入範圍檢查，以及在乘法前檢查上限來避免。


動手練習
為何 double avg = static_cast<double>(points / judges); 仍得到 3？
看解答與理由
括號內先以兩個 int 做整數除法，結果 3 才被轉成 double。應轉其中一個運算元：static_cast<double>(points) / judges。





PART 09
從第一則診斷定位問題


main.cpp:5:10: error: expected ‘;’ before ‘return’
    5 |     cout << value
      |                  ^
      |                  ;


典型診斷包含檔名、行、欄、嚴重度與訊息，下一行用符號標位置。先修第一則真正的 error 再重編，因為一個漏分號可能引出十幾則連鎖錯誤。也要讀錯誤行的上一行；編譯器往往走到下一個 token 才知道前面少了東西。


實用流程是：確認正在編譯的檔案、重現錯誤、讀第一則 error、做最小修正、重新編譯。開啟警告後，把警告當成需要理解的訊號；不要用強制轉型只為讓警告消失。


動手練習
顯示 expected ; before } 時，最先檢查哪裡？
看解答與理由
檢查右大括號前一個敘述是否漏分號；錯誤位置常是編譯器終於無法繼續解析的位置，而非原因起點。

靜態型別、大小與範圍


比較問題C++ 靜態型別的答案實際影響
型別何時決定編譯期由宣告與運算式決定許多不相容操作在執行前被拒絕
同一變數能否改放另一型別不能改變變數本身的型別指定時先依規則轉換，可能遺失資訊
錯誤何時發現型別錯誤通常在編譯期輸入格式與範圍問題仍須執行期檢查


型別常見 64 位元環境的 sizeof標準可依賴的範圍／精度觀念用途
char1 byte（保證）至少 8 bits；確切範圍看實作單一字元／byte
int常見 4 bytes至少 −32767 到 32767；用 整數界線常數 查本機一般整數
long long常見 8 bytes至少 64 bits較大整數
double常見 8 bytes浮點近似值，常見約 15 位十進位有效數字含小數量
bool依實作true 或 false條件狀態
表中的 4、8 是常見實測，不是跨平台保證；可用 sizeof 與 <climits> 的整數界線常數 在目標環境查證。

舊式亂數與整數上限哨兵
std::srand(seed) 設定 C 亂數產生器的起始狀態，std::rand() 取下一值；rand()%n 只適合簡單示範，可能有模數偏差，不能用於安全用途。固定 seed 可重現除錯；以時間作 seed 每次可能不同，但同一秒啟動仍可能相同。新程式需要統計品質時用 <random>。
INT_MAX 可代表本機 int 最大值。把它當「無限大」哨兵前，必須保證真實資料不會等於它，也不可直接對哨兵加權重，否則可能溢位；更穩妥的是另存「是否已有值」狀態或用較寬型別。


從症狀判斷錯誤層次
看到的症狀多半屬於先檢查

基本型別完整比較
型別常見 64 位元 Linux 的 sizeof標準限制／本機查法適用資料
bool常見 1值只有 false/true；大小依實作條件狀態
char1（標準保證）是否 signed 依實作；範圍看 CHAR_MIN／CHAR_MAX單一字元／byte
short常見 2至少 16 bits確有範圍／儲存需求的較小整數
int常見 4至少 16 bits一般整數
unsigned int常與 int 相同0 到 2N−1，算術按模數回繞位元／模數語意；不要只為「非負」濫用
long long常見 8至少 64 bits較大整數
float常見 4精度依實作，常約 6–7 位十進位數可接受較低精度的浮點量
double常見 8精度依實作，常約 15 位十進位數一般含小數量
int*此環境常見 8大小由資料模型／平台決定；指標語意見 P4保存 int 物件地址
std::string物件大小依標準庫實作sizeof(string) 不是文字長度；長度用 size()可管理的字元序列，詳見 P5
short ≤ int ≤ long ≤ long long 指可表示範圍至少不縮小，不代表每相鄰型別大小必不同。跨平台程式應查 sizeof、CHAR_BIT 與 <climits> 的界線常數，不能把常見欄當保證。


一行宣告多個名稱：合法但容易誤讀
寫法實際宣告風險／建議
int a=1, b=2;兩個 int 物件短且同用途時合法；分行較容易加註解
int* p, q;p 是 int*，q 是 int* 綁在每個 declarator；最易誤讀，應分行
const int x=1, y=2;兩個 const int兩者都必須初始化
語法必須看每一個逗號後的 declarator，而不是把第一個星號想成套用整行。教學與維護時優先一行一個名稱。

printf、舊式亂數與上限哨兵：完整可跑例
標準函式庫函式以「函式名稱(引數)」呼叫，例如 std::srand(12345)；沒有引數時仍寫括號，例如 std::rand()。P3 再介紹如何定義自己的函式。
#include <cstdio>
int main() {
    int count{3};
    double price{12.5};
    std::printf("%-10s %5s %5s\n", "item", "count", "price");
    std::printf("%-10s %5d %6.2f\n", "pen", count, price);
}
預期輸出
item       count price
pen            3  12.50

負寬度使文字靠左，正寬度靠右，.2 指定小數位。格式與引數型別必須相符；cout 的型別安全介面仍是一般首選。


#include <cstdlib>
#include <iostream>
int main() {
    std::srand(12345);
    int first = std::rand();
    std::srand(12345);
    int again = std::rand();
    int bucket = first % 6;
    std::cout << "same=" << (first == again)
              << " in-range=" << (bucket >= 0 && bucket < 6) << '\n';
}
預期輸出
same=1 in-range=1

測試只依賴「同一實作重設相同 seed 會重現」與模數範圍，不固定跨平台 rand 數列。%6 可能有偏差，也不是安全亂數。


#include <iostream>
#include <climits>
int main() {
    const int infinity = INT_MAX;
    int distance = infinity;
    if (distance == infinity) std::cout << "unreached\n";
    distance = 20;
    int step{5};
    if (distance <= infinity - step) distance += step;
    std::cout << "reachable=" << distance << '\n';
}
預期輸出
unreached
reachable=25

此例使用 <climits> 的 INT_MAX 取得本機 int 上限；infinity 只是變數名稱，不是可任意運算的數學無限大。哨兵只在真實值排除最大 int 時才無歧義；加法前以減法形式檢查，避免對最大值直接相加造成帶號溢位。大型程式通常另存「是否可達」狀態。
