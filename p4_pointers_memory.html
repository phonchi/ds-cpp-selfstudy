PART 01 · 位址

每個變數都住在一個門牌號碼

變數不是憑空存在的，它佔一塊記憶體。&x 就是問「x 住在哪」，sizeof(x) 是問「它佔幾格」。

每個變數的門牌與大小（真的跑出來的）
#include <iostream> using namespace std; int main() { int x = 42; double d = 3.14; char c = 'A'; cout << "x 的值 = " << x << "，位址 = " << &x << "，佔 " << sizeof(x) << " bytes" << endl; cout << "d 的值 = " << d << "，位址 = " << &d << "，佔 " << sizeof(d) << " bytes" << endl; cout << "c 的值 = " << c << "，位址 = " << (void*)&c << "，佔 " << sizeof(c) << " bytes" << endl; return 0; }
預期輸出
x  的值 = 42，位址 = 0x7ffe91aff68c，佔 4 bytes
d  的值 = 3.14，位址 = 0x7ffe91aff690，佔 8 bytes
c  的值 = A，位址 = 0x7ffe91aff68b，佔 1 bytes

三個觀察：① 位址是十六進位的一長串，每次執行都不一樣（作業系統每次配的位置不同）。② 不同型別佔的大小不同：int 4 bytes、double 8、char 1。③ char 的位址要轉成 (void*) 才印得出數字，否則 cout 會把它當字串開頭。

›按「開始」，一步一步看指標怎麼指到變數身上。
速度
程式碼 CODE
int x = 42; int *p = &x; cout << *p; *p = 99; cout << x;
三個符號 KEY

int *p：宣告 p 是「指向 int 的指標」
&x：取出 x 的位址
*p：順著 p 存的位址走進去

圖 1：x 盒裡裝的是值 25，p 盒裡裝的是「x 的位址」——所以 *p = 50; 改的是箭頭那一頭的 x，不是 p 自己。上面的動畫演逐步，這張圖給你前後對照。

PART 02 · 指標

int *p = &x;：三個符號，三件事

初學最容易混的是：* 在宣告時和在使用時意思不一樣。

寫法出現在哪意思
int *p;宣告p 是一個指標，指向 int
p = &x;使用把 x 的位址存進 p
*p使用解參考：p 指向的那個東西（就是 x 本人）
*p = 99;使用透過 p 改動 x
p使用指標本身的值，也就是一個位址
同一段程式把五件事都做一遍
#include <iostream> using namespace std; int main() { int x = 42; int *p = &x; // p 存的是 x 的位址 cout << "x = " << x << endl; cout << "&x = " << &x << endl; cout << "p = " << p << " <- p 存的就是 x 的位址" << endl; cout << "*p = " << *p << " <- 順著位址走進去，看到 x 的值" << endl; *p = 99; // 透過指標改動 x cout << "把 *p 改成 99 之後，x = " << x << endl; cout << "指標本身也佔空間: sizeof(p) = " << sizeof(p) << " bytes" << endl; return 0; }
預期輸出
x  = 42
&x = 0x7ffeec7bfa4c
p  = 0x7ffeec7bfa4c   <- p 存的就是 x 的位址
*p = 42   <- 順著位址走進去，看到 x 的值
把 *p 改成 99 之後，x = 99
指標本身也佔空間: sizeof(p) = 8 bytes

注意倒數第二行：透過 *p 改值，x 真的變了——因為它們是同一塊記憶體。最後一行也重要：指標本身佔 8 bytes（64 位元系統），不管它指向的是 int 還是一整棵樹。

💡 為什麼要有指標

兩個理由，這門課兩個都會用到：① 不想複製 —— 傳一個 8 bytes 的位址，比複製一整個物件便宜（見 P3）。② 結構要能長大 —— 鏈結串列、樹、圖的節點數量在編譯時還不知道，只能執行時 new 出來，而 new 回傳的就是指標。

參考：另一個名字，不是另一個變數 —— 跟指標分清楚

C++ 還有一個長得像親戚的東西：參考（reference，有些書譯作「參照」）。 int &r = x; 讀作「r 是 x 的參考」—— 它不配置新的記憶體、也不存位址， 它就是 x 的另一個名字。P3 實測過：&r == &x，連 sizeof 都一樣， 因為 r 根本沒有自己的身體。兩者常被混為一談，但個性完全不同：

參考 int &r = x;指標 int *p = &x;
它是什麼x 的別名，編譯器層級的化名一個存位址的變數，有自己的記憶體
宣告時可以不初始化嗎不行，宣告當下就得綁定對象可以（但未初始化就是野指標，見下）
可以「不指向任何東西」嗎不行，沒有「空參考」這種東西可以，p = NULL;
可以中途換對象嗎不行，終身只認第一個可以，p = &y; 隨時改指
自己佔記憶體嗎不佔（sizeof(r) 量到的是 x）佔 8 bytes（64 位元系統）
取用時要加符號嗎不用，寫 r 就是 x 本人要，*p 才走得進去
這門課的典型用途函式參數與回傳（P3：T&、const T&）鏈結結構的 next、走訪的 current、new 的回傳值
✅ 怎麼選：用語意決定，不是用喜好

只是想讓函式碰到本人、或省下複製：用參考，呼叫端乾淨、也不必防 NULL。需要「可能沒有對象」或「會換對象」的語意 —— 串列的 next 要能是 NULL 當終點、走訪的 current 要一路往下換人 —— 就非指標不可。這正是第 04 章起節點清一色用指標的原因。

PART 03 · 空指標

NULL：指向「哪裡都不是」 課程用 114 次

NULL 代表「這個指標目前沒有指向任何東西」。它在這門課有一個固定用途：當作結構的終點標記。

走到 NULL 為止——這就是第 04 章整章的骨幹
#include <iostream> using namespace std; class Node { public: int data; Node *next; Node(int d) { data = d; next = NULL; } }; int main() { Node *a = new Node(31); a->next = new Node(17); a->next->next = new Node(93); // 最後一個的 next 是 NULL // 走訪：一路走到 NULL 為止。這就是第 04 章整章的骨幹 Node *current = a; while (current != NULL) { cout << current->data << " -> "; current = current->next; } cout << "NULL" << endl; delete a->next->next; delete a->next; delete a; return 0; }
預期輸出
31 -> 17 -> 93 -> NULL

while (current != NULL) 這一行，你在第 04、05、09 章會看到幾十次。它的意思是「只要還沒走到盡頭就繼續」。最後一個節點的 next 是 NULL，迴圈就停在那裡。

⚠️ 解參考 NULL 會當掉

current->data 在 current 是 NULL 時是未定義行為，通常直接 segmentation fault。所以走訪的迴圈條件一定要先檢查再解參考。這也是為什麼 while (current != NULL && current->data != item) 的順序不能顛倒 —— && 有短路求值，左邊不成立就不會去碰右邊。

✅ 現代 C++ 對照

C++11 之後有了 nullptr，型別更安全，是現在的標準寫法。本課照 cppds 教科書用 NULL，你看別人的程式碼時會遇到 nullptr，兩者在這門課的用途完全一樣。

🔗 這在資料結構課哪裡會用到 · 第 04、09 章

第 04 章的 size()、search()、remove() 全部是 while (current != NULL) 的變形；第 09 章的樹走訪則是「左邊不是 NULL 就往左走」的遞迴版。

PART 04 · 陣列

a[i] 其實就是 *(a + i)

這不是比喻，是定義。陣列名就是首元素的位址，中括號只是「往後跳 i 格再解參考」的簡寫。

三種寫法印出同一個東西
#include <iostream> using namespace std; int main() { int a[5] = {10, 20, 30, 40, 50}; cout << "a = " << a << " <- 陣列名就是首元素的位址" << endl; cout << "&a[0] = " << &a[0] << " <- 一模一樣" << endl; cout << endl; for (int i = 0; i < 3; i++) { cout << "i=" << i << " a[i]=" << a[i] << " *(a+i)=" << *(a + i) << " 位址=" << (a + i) << " 距離首位 " << (char*)(a + i) - (char*)a << " bytes" << endl; } return 0; }
預期輸出
a       = 0x7ffef812b1b0  <- 陣列名就是首元素的位址
&a[0]   = 0x7ffef812b1b0  <- 一模一樣

i=0  a[i]=10  *(a+i)=10  位址=0x7ffef812b1b0  距離首位 0 bytes
i=1  a[i]=20  *(a+i)=20  位址=0x7ffef812b1b4  距離首位 4 bytes
i=2  a[i]=30  *(a+i)=30  位址=0x7ffef812b1b8  距離首位 8 bytes

看最後一欄：每跳一格，位址就前進 4 bytes——剛好是一個 int 的大小。指標算術會自動乘上型別大小，所以 a + 1 不是「位址加 1」，是「往後一個元素」。這也解釋了為什麼索引從 0 開始：a[0] 就是「往後跳 0 格」，也就是原地。

PART 05 · 退化

陣列一進函式，就變成一個指標

同一個陣列，sizeof 卻不一樣
#include <iostream> using namespace std; void f(int arr[]) { // 看起來像陣列，其實是 int* cout << "在函式裡 sizeof(arr) = " << sizeof(arr) << " bytes（這是指標的大小）" << endl; } int main() { int a[5] = {10, 20, 30, 40, 50}; cout << "在 main 裡 sizeof(a) = " << sizeof(a) << " bytes（5 個 int）" << endl; f(a); return 0; }
預期輸出
在 main 裡 sizeof(a) = 20 bytes（5 個 int）
在函式裡 sizeof(arr) = 8 bytes（這是指標的大小）

void f(int arr[]) 看起來收的是陣列，其實編譯器把它當成 int*。所以函式裡量到的是指標的大小（8 bytes），不是陣列的大小（20 bytes）。這叫陣列退化，是 C++ 初學最常踩的坑之一。

⚠️ 所以陣列傳進函式一定要另外傳長度

因為函式根本無從得知長度。void printAll(int arr[], int n) 這種簽章不是囉嗦，是必要。用 vector 就沒這個問題——它自己記得 size()，這也是 P5 要講的第一個好處。

備註：講義第 02 章那行 void (*tests[])(int) 是什麼

效能測試那段有一行長得很兇的宣告： void (*tests[])(int) = {test1, test2, test3, test4};。 讀法由內往外：tests 是一個陣列，每個元素是「收一個 int、不回傳東西的函式指標」。 之後 tests[k](n) 就是「呼叫第 k 個測試函式」——迴圈跑四種測試不用寫四段重複的碼。 能這樣塞是因為函式名跟陣列名一樣，會退化成指標（正是本節講的那件事）。 全課只出現這一次，看得懂就好，作業用不到。

PART 07 · 借與還

new 與 delete 課程用 218 / 32 次

借了要還，而且形式要配對
#include <iostream> using namespace std; int main() { int onStack = 42; // 堆疊：離開範圍自動消失 int *onHeap = new int(42); // 堆積：你不 delete 就一直在 cout << "堆疊變數位址 = " << &onStack << endl; cout << "堆積變數位址 = " << onHeap << endl; cout << "兩者的值都是 " << onStack << " / " << *onHeap << endl; int *arr = new int[5]; // 配一整排 for (int i = 0; i < 5; i++) arr[i] = i * i; cout << "arr = "; for (int i = 0; i < 5; i++) cout << arr[i] << " "; cout << endl; delete onHeap; // 單一個用 delete delete[] arr; // 一整排用 delete[] cout << "都還回去了。" << endl; return 0; }
預期輸出
堆疊變數位址 = 0x7fff825e572c
堆積變數位址 = 0x6146265982b0
兩者的值都是 42 / 42
arr = 0 1 4 9 16 
都還回去了。

注意兩個位址差很多：堆疊那個是 0x7fff…，堆積那個是 0x6146…——它們住在記憶體的兩端。另外 new[] 一定要配 delete[]，配錯是未定義行為（g++ 加 -Wall 通常會警告，但別依賴它）。

›選一個版本，看堆積上的東西怎麼長、怎麼消。
速度 堆積上還沒還的：0

重點 WHY

函式結束時，指標 a 本身（住在堆疊上）會自動消失，但它指向的那塊堆積記憶體不會。沒有 delete，那塊就永遠找不回來了。

圖 2：delete 還的是堆積上那塊記憶體，不是指標 p —— p 還留著舊門牌，就成了懸空指標。多寫一行 p = NULL;，箭頭才真的斷乾淨。

PART 08 · 三種災難

指標出錯的三種典型死法

共同點：編譯器都不會抱怨。這三個名字值得記起來，因為 debug 時你要先猜是哪一種。

災難長什麼樣症狀
記憶體洩漏
memory leak		new 了沒 delete程式跑越久吃越多記憶體，最後被系統砍掉。短程式看不出來
懸空指標
dangling pointer		delete 之後還在用讀到垃圾值，或當掉。最難 debug，因為有時候「剛好」還是對的
二次釋放
double free		同一塊 delete 兩次通常當場當掉，訊息像 free(): double free detected
🎯 一個習慣可以擋掉兩種

delete p; 之後立刻寫 p = NULL;。這樣懸空指標會變成空指標（當掉得很明確、很好找），而 delete 一個 NULL 在 C++ 是合法的空操作，二次釋放也就不會發生。

✅ 現代 C++ 對照

現在的 C++ 會用 std::unique_ptr：它離開範圍時自動 delete，三種災難一次擋掉。本課照 cppds 用手動 new／delete，因為要你先看懂記憶體是怎麼運作的 —— 這跟先學手排再開自排是一樣的道理。

PART 09 · 收尾

從指標到 Node：把第 04 章的第一段程式碼看懂

把前面九節接起來，就是課程 pythonds3/cppds/linked_list.hpp 的開頭：

template <typename T> class Node { private: T data; Node<T> *next; // 指向「同型別的下一個節點」 public: Node(T initdata) { data = initdata; next = NULL; // 一出生先不指向任何東西 } T getData() const { return data; } Node<T> *getNext() const { return next; } void setNext(Node<T> *newnext) { next = newnext; } };
💡 三個「為什麼」，現在都答得出來了

為什麼 next 是指標而不是物件？因為一個型別不可能包含一個自己（那會無限大）；存位址就沒這個問題。
為什麼建構式把 next 設成 NULL？因為新節點還沒接到任何東西，而走訪的迴圈靠 NULL 判斷終點。
為什麼要 new？因為串列有幾個節點是執行時才知道的，堆疊上配不出來。

›按 add 在頭部插入一個節點，看指標怎麼接。
速度
add 的兩行 CODE
void add(T item) { Node<T> *temp = new Node<T>(item); temp->setNext(head); head = temp; }

順序不能反：先讓新節點接上舊的頭，再把頭換成新的。反過來寫，舊的那串就找不回來了。

隨堂 2 · 順序反了會怎樣

如果把 add() 的兩行對調，先寫 head = temp; 再寫 temp->setNext(head);，會發生什麼？

(A) 編譯錯誤
(B) 新節點指向自己，原本那串全部洩漏
(C) 沒差，結果一樣
🔗 這在資料結構課哪裡會用到 · 第 04、05、09 章

這段 Node 就是第 04 章的主角；第 05 章的鏈結版 Stack 與 Queue 用同一個 Node；第 09 章的樹只是把一個 next 換成 leftChild 與 rightChild 兩個指標。看懂這一段，那三章就都有底了。

P4 速查表

語法

寫法意思
int *p;宣告一個指向 int 的指標
&xx 的位址
*p解參考：p 指向的那個東西
p->field等同 (*p).field，指向物件時用這個
a[i]等同 *(a + i)
new T(v)在堆積配一個 T，回傳指標
new T[n]在堆積配 n 個 T
delete p;還一個
delete[] p;還一整排
sizeof(x)x 佔幾個 byte（編譯期就決定）

四條記得住的規則

① 每寫一個 new，當場想清楚它的 delete 在哪。
② new[] 配 delete[]，中括號要成對。
③ delete 之後立刻把指標設成 NULL。
④ 解參考之前先確認不是 NULL。
