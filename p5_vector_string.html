原生陣列有三個痛點，vector 一次解決

先看你已經會的東西壞在哪裡。int a[5]; 這行有三個你改不掉的限制：

痛點原生陣列vector
長度能不能變不能。int a[5] 就是永遠 5 格能，push_back 隨時加
傳進函式會怎樣退化成指標，長度資訊掉光照樣是完整的物件，size() 還在
自己知不知道多長不知道，要另外傳一個 n知道，v.size()
同一件事，陣列做不到、vector 做得到
#include <iostream> #include <vector> using namespace std; void showArray(int arr[]) { // 陣列一進來就退化成 int* cout << " 函式裡 sizeof(arr) = " << sizeof(arr) << " bytes（指標的大小）" << endl; } void showVector(vector<int>& v) { // vector 自己記得長度 cout << " 函式裡 v.size() = " << v.size() << endl; } int main() { int a[5] = {10, 20, 30, 40, 50}; cout << "原生陣列：main 裡 sizeof(a) = " << sizeof(a) << " bytes" << endl; showArray(a); vector<int> v = {10, 20, 30, 40, 50}; cout << "vector：main 裡 v.size() = " << v.size() << endl; showVector(v); v.push_back(60); // 陣列做不到這件事 cout << "push_back 之後 v.size() = " << v.size() << endl; return 0; }

PART 01 · 建立與存取

四種建法，兩種存取

vector 要先 #include <vector>。建立的四種寫法對應四種情境：

寫法結果什麼時候用
vector<int> v;空的，size() 是 0邊跑邊 push_back
vector<int> v(5, 0);5 個 0已知長度、要先填預設值（計數陣列）
vector<int> v = {31, 17, 93};照清單填好寫測試資料
vector<int> w(v);整份複製一份新的要留原本那份不動時

存取有兩個：v[i] 和 v.at(i)。功能一樣，差別只在越界時的反應。

[] 與 at() 的差別
#include <iostream> #include <vector> #include <stdexcept> using namespace std; int main() { vector<int> a; // 空的，size 是 0 vector<int> b(5, 0); // 5 個 0 vector<int> c = {31, 17, 93}; // 初始化清單 vector<int> d(c); // 整個複製一份 cout << "a.size()=" << a.size() << " b.size()=" << b.size() << " c.size()=" << c.size() << " d.size()=" << d.size() << endl; cout << "c[1] = " << c[1] << " <- 不檢查範圍，快" << endl; cout << "c.at(1) = " << c.at(1) << " <- 檢查範圍" << endl; try { cout << c.at(5) << endl; // 越界：at 會丟例外 } catch (out_of_range& e) { cout << "c.at(5) 丟出 out_of_range：" << e.what() << endl; } return 0; }
預期輸出
a.size()=0  b.size()=5  c.size()=3  d.size()=3
c[1]    = 17      <- 不檢查範圍，快
c.at(1) = 17      <- 檢查範圍
c.at(5) 丟出 out_of_range：vector::_M_range_check: __n (which is 5) >= this->size() (which is 3)

at(5) 在只有 3 個元素的 vector 上會丟出 out_of_range，訊息裡連 5 和 3 都寫出來了，非常好 debug。換成 c[5] 就什麼檢查都不做：讀到隔壁那塊記憶體，印出一個看起來像亂數的值，或者直接當掉，而且當掉的位置常常離出錯的那一行很遠。

例外沒人接會怎樣
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v = {31, 17, 93}; cout << "v.at(5)：" << endl; cout << v.at(5) << endl; // 沒有 try/catch，例外沒人接 return 0; }
預期輸出
v.at(5)：

[執行結束碼 -6]
terminate called after throwing an instance of 'std::out_of_range'
  what():  vector::_M_range_check: __n (which is 5) >= this->size() (which is 3)

沒有 try／catch 的話，例外一路往上丟到 main 外面，程式被 abort() 掉。訊息還是印出來了，所以就算你懶得寫 catch，at() 的錯誤訊息依然比 [] 的沉默有用得多。

💡 該用哪一個

寫演算法、索引明顯在範圍內時用 v[i]（課程的排序、搜尋全部用這個）。索引來自使用者輸入或計算結果、你不確定的時候用 at(i)。課程第 03 章自己寫的 ArrayList 就選了後者的做法：operator[] 裡先檢查範圍，超出就 throw out_of_range。

⚠️ 小括號與大括號不是同一件事

vector<int> a(3); 是「3 個元素，各是 0」；vector<int> b{3}; 卻是「1 個元素，值是 3」——大括號優先配對初始化清單。C++ 的難常常不在單一概念，而在相似語法依 context 有不同意思。本課照 cppds 的習慣：計數用小括號、列元素用 = {31, 17, 93}，不混用。

為什麼初學會覺得亂？因為 C 和 Python 都沒有把「宣告」跟「建構」黏在同一行的寫法：

寫法概念
Cint x = 5;宣告＋給值就結束了，沒有建構式這個概念
Pythonv = list(range(5))概念上類似 —— 呼叫型別建立物件 —— 但變數不必宣告型別，「建構」只出現在等號右邊
C++vector<int> v(5);宣告與建構黏在同一行，所以長得像函式呼叫 —— 其實兩件事同時發生

PART 02 · 增刪

五個操作，兩種價錢 本頁重點

增刪的成本只看一件事：你動的是尾巴，還是尾巴以外的地方。動尾巴不影響任何人；動前面或中間，後面每一個元素都要跟著挪一格。

五個操作跑一遍
#include <iostream> #include <vector> using namespace std; void show(const char* tag, vector<int>& v) { cout << tag << " size=" << v.size() << " [ "; for (int x : v) cout << x << " "; cout << "]" << endl; } int main() { vector<int> v = {31, 17, 93}; show("起始 ", v); v.push_back(26); // 尾端加：O(1) show("push_back(26) ", v); v.pop_back(); // 尾端刪：O(1) show("pop_back() ", v); v.insert(v.begin(), 54); // 頭部插：後面每一個都要往後挪 show("insert(begin) ", v); v.erase(v.begin() + 1); // 中間刪：後面每一個都要往前挪 show("erase(begin+1)", v); v.clear(); // 清空，但容量不還 cout << "clear() 之後 size=" << v.size() << " capacity=" << v.capacity() << " <- 容量沒有跟著變 0" << endl; return 0; }
預期輸出
起始            size=3  [ 31 17 93 ]
push_back(26)   size=4  [ 31 17 93 26 ]
pop_back()      size=3  [ 31 17 93 ]
insert(begin)   size=4  [ 54 31 17 93 ]
erase(begin+1)  size=3  [ 54 17 93 ]
clear() 之後  size=0  capacity=6  <- 容量沒有跟著變 0

看 insert(v.begin(), 54) 那一步：31、17、93 三個元素全部往後挪一格，54 才放得進第 0 格。erase(v.begin() + 1) 同理，後面的元素往前補位。最後一行的 clear() 把 size 清成 0，但 capacity 還是 6——記憶體沒有還給系統，下次 push_back 可以直接用。

PART 03 · 容量與攤還

size() 是住了幾個，capacity() 是有幾個位子

vector 的元素一定放在一整塊連續記憶體裡——這是 v[i] 能 $O(1)$ 的原因。連續就代表不能隨便往後長，隔壁可能已經被別人佔走了。所以位子坐滿時，vector 的做法是：另外找一塊更大的，把所有元素搬過去，再把舊的還掉。

▲ 一次擴容其實做了四件事，而只有第三步是 O(n)：其餘三步都是常數時間。位子坐滿才會走這四步，容量每次翻倍，所以走這條路的次數只有 $\log_2 n$ 回——這就是 push_back 攤還 $O(1)$ 的來源。順帶一提，第四步把舊塊還掉，正是本頁 PART 05 講的 iterator 失效的根本原因。

17 次 push_back，容量變化與搬移總量
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v; size_t cap = v.capacity(); long long moved = 0; // 累計搬移過幾個元素 cout << "一開始 size=0 capacity=" << cap << endl; for (int i = 1; i <= 17; i++) { v.push_back(i); if (v.capacity() != cap) { // 容量變了，代表剛剛搬過家 long long n = v.size() - 1; // 搬的是「新元素放進去之前」的那些 moved += n; cout << "第 " << i << " 次 push_back：capacity " << cap << " -> " << v.capacity() << "，搬了 " << n << " 個元素" << endl; cap = v.capacity(); } } cout << "17 次 push_back，總共搬移 " << moved << " 個元素" << endl; cout << "平均每次 push_back 搬 " << (double)moved / 17 << " 個 -> 這就是攤還 O(1)" << endl; return 0; }
預期輸出

第 1 次 push_back：capacity 0 -> 1，搬了 0 個元素
第 2 次 push_back：capacity 1 -> 2，搬了 1 個元素

第 5 次 push_back：capacity 4 -> 8，搬了 4 個元素

容量走的是 0 → 1 → 2 → 4 → 8 → 16 → 32，每次翻倍（這是 libstdc++ 的策略，標準只要求攤還 $O(1)$）。17 次 push_back 裡只有 6 次搬了家，總共搬移 31 個元素，平均每次不到 2 個。這就是攤還分析：個別一次可能很貴，但把成本分攤到所有操作上，平均仍是常數。

為什麼是翻倍 WHY

如果每次只多加一格，塞 n 個元素要搬 1+2+…+(n-1) 次，是 $O(n^2)$。改成翻倍之後，搬家次數只有 $\log_2 n$ 回，搬移總量是 1+2+4+…+n，不超過 2n。把 2n 分攤到 n 次 push_back，平均每次是常數。

reserve TIP

已經知道要放幾個的話，先 v.reserve(n) 把位子訂好，一次搬家都不會發生。

reserve 之後，擴容次數歸零
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v; v.reserve(1000); // 先講好要用 1000 格 size_t cap = v.capacity(); int grows = 0; for (int i = 0; i < 1000; i++) { v.push_back(i); if (v.capacity() != cap) { grows++; cap = v.capacity(); } } cout << "reserve(1000) 之後塞 1000 個，擴容次數 = " << grows << endl; vector<int> w; cap = w.capacity(); grows = 0; for (int i = 0; i < 1000; i++) { w.push_back(i); if (w.capacity() != cap) { grows++; cap = w.capacity(); } } cout << "沒有 reserve 塞 1000 個，擴容次數 = " << grows << endl; return 0; }

沒有 reserve 時，塞 1000 個元素要擴容 11 次（1、2、4、…、1024）；先 reserve(1000) 就是 0 次。這也是第 02 章 benchmark 裡「with reserve」那一列會比較快的原因。

第 03 章要你自己動手寫 ArrayList，用的就是這一節的邏輯：append() 先檢查 lastIndex == maxSize，滿了就呼叫 grow()；grow() 做的是 maxSize = maxSize * 2、new int[maxSize]、把舊元素一個一個複製過去、delete[] 舊陣列。你在那一章手寫的，就是 vector 幫你做掉的事。

PART 04 · 走訪

三種寫法，還有那個關鍵的 &

三種走訪在效能上完全一樣，差別在你需不需要索引、要不要改到元素本人。

寫法拿得到索引嗎什麼時候用
for (unsigned i = 0; i < v.size(); i++)拿得到要比較 v[i] 與 v[i+1]、要換位置（排序全部用這種）
for (int x : v)拿不到只是把每個值讀一遍，最好讀
for (auto it = v.begin(); it != v.end(); ++it)間接可以要呼叫 insert／erase（它們吃的就是 iterator）
三種走訪，加上 & 的差別
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v = {31, 17, 93, 26}; cout << "① 索引： "; for (unsigned i = 0; i < v.size(); i++) cout << v[i] << " "; cout << endl; cout << "② 範圍 for： "; for (int x : v) cout << x << " "; // x 是複製品 cout << endl; cout << "③ iterator： "; for (vector<int>::iterator it = v.begin(); it != v.end(); ++it) cout << *it << " "; // *it 跟指標一樣要解參考 cout << endl; for (int x : v) x = x * 10; // 改的是複製品，白改 cout << "for (int x : v) x*=10 之後： "; for (int x : v) cout << x << " "; cout << endl; for (int& x : v) x = x * 10; // 加了 & 才是本人 cout << "for (int& x : v) x*=10 之後： "; for (int x : v) cout << x << " "; cout << endl; return 0; }
預期輸出
① 索引：      31 17 93 26 
② 範圍 for：  31 17 93 26 
③ iterator：  31 17 93 26 
for (int x : v) x*=10 之後：  31 17 93 26 
for (int& x : v) x*=10 之後： 310 170 930 260

前三行印出一樣的東西。重點在後面兩組：for (int x : v) 的 x 是複製品，改它等於改一個馬上就要丟掉的暫存值，原本的 vector 一動也沒動；加了 & 寫成 for (int& x : v)，x 才是元素本人，改了就真的改到。

💡 什麼時候一定要加 &

兩個時機：① 你要改元素；② 元素很大、複製很貴（例如 vector<string> 或第 08 章的 vector<Vertex>）。只讀又不想改到的話，寫 for (const string& s : words) 最保險——不複製，也不會手滑改到。課程第 08 章的字梯程式就是這樣寫的。

💡 為什麼講義的迴圈計數常寫 unsigned 而不是 int

v.size() 和 s.length() 回傳的不是 int，而是一個無號整數（size_t）——長度本來就不可能是負的。拿 int i 去跟它比大小，兩邊型別不同，編譯器會丟出 comparison of integer expressions of different signedness 這類警告。所以講義乾脆把計數變數宣告成無號的，第 02、07 章都是這樣寫：unsigned pos = 0; while (pos < aList.size())。

代價是要記住一件事：無號數相減永遠不會是負的，減過頭會從最大值繞回來。v.size() - 1 在空 vector 上不是 −1，而是 18446744073709551615（64 位元的最大值）。所以 for (unsigned i = 0; i < v.size() - 1; i++) 這種寫法碰到空 vector 就會跑天文數字圈然後越界當掉——想比較相鄰兩格時，改寫成 i + 1 < v.size() 才安全。

✅ 現代 C++ 對照

iterator 那一行常常寫成 for (auto it = v.begin(); it != v.end(); ++it)，讓編譯器自己推型別，比手寫 vector<int>::iterator 短很多。本課照 cppds 教科書，兩種寫法都會出現，考試以課程風格為準。

PART 05 · iterator 失效

push_back 之後，舊的指標可能指到空地

PART 03 說擴容會把元素整批搬到新位址。那你在搬家前記下來的位址呢？它還指著舊地址——而舊那塊已經還給系統了。這就是 iterator 失效。

同一個指標，push_back 前後指到不同的地方
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v = {31, 17, 93}; cout << "size=" << v.size() << " capacity=" << v.capacity() << "（已經滿了）" << endl; int *p = &v[0]; // 指向第 0 格 cout << "push_back 前： &v[0] = " << p << "，*p = " << *p << endl; v.push_back(26); // 容量不夠，整批搬家 cout << "push_back 後： &v[0] = " << &v[0] << "，v[0] = " << v[0] << endl; cout << "capacity 變成 " << v.capacity() << "，元素被搬到新位址了" << endl; cout << "舊指標 p 還停在 " << p << "，讀出來是 " << *p << "（未定義行為，這個數字每次跑都可能不同）" << endl; return 0; }
預期輸出
size=3 capacity=3（已經滿了）
push_back 前： &v[0] = 0x5b6abd6c32b0，*p = 31
push_back 後： &v[0] = 0x5b6abd6c42e0，v[0] = 31
capacity 變成 6，元素被搬到新位址了
舊指標 p 還停在 0x5b6abd6c32b0，讀出來是 -1230252349（未定義行為，這個數字每次跑都可能不同）

第一行說明前提：size 和 capacity 都是 3，位子剛好坐滿。所以第四步的 push_back(26) 一定會觸發搬家，&v[0] 從第一個位址變成另一個位址。最後一行的 *p 讀的是已經釋放掉的記憶體，這是未定義行為：上面這個數字是這次跑出來的結果，你自己跑會拿到別的值，也可能直接當掉。

⚠️ 最陰的是它常常「看起來還是對的」

如果 capacity 還有空位，push_back 就不會搬家，舊指標照樣好用。所以這種 bug 會等到資料量剛好跨過某個門檻才爆，測試時的小資料完全測不出來。不要記位址，要記索引——索引 2 搬家前後都是索引 2。

操作誰失效
push_back / insert有擴容的話全部失效；沒擴容的話，插入點之後的全部失效
erase(it)it 之後的全部失效（erase 會回傳下一個有效的 iterator）
pop_back只有最後一個失效
clear全部失效
v[i] = x沒有人失效，改值不影響配置
隨堂 1 · 這個迴圈錯在哪

有人想在走訪時把等於 0 的元素刪掉，寫成 for (auto it = v.begin(); it != v.end(); ++it) if (*it == 0) v.erase(it);。問題在哪？

(A) 編譯錯誤，erase 不吃 iterator
(B) erase 之後 it 已經失效，再 ++it 是未定義行為
(C) 只是慢，因為每次 erase 都是 O(n)
PART 06 · 二維 vector

vector<vector<int>>：一個裝著 vector 的 vector

二維就是「每個元素本身又是一個 vector」。宣告一個 4×4、全部填 0 的矩陣寫成 vector<vector<int>> adj(4, vector<int>(4, 0));——讀法是「4 個元素，每個都是『4 個 0 的 vector』」。

用二維 vector 存一張圖的相鄰矩陣
#include <iostream> #include <vector> using namespace std; int main() { int n = 4; vector<vector<int>> adj(n, vector<int>(n, 0)); // n x n，全部填 0 adj[0][1] = 1; adj[1][0] = 1; // 0 — 1 adj[1][2] = 1; adj[2][1] = 1; // 1 — 2 adj[0][3] = 1; adj[3][0] = 1; // 0 — 3 cout << " "; for (int j = 0; j < n; j++) cout << j << " "; cout << endl; for (int i = 0; i < n; i++) { cout << i << ": "; for (int j = 0; j < n; j++) cout << adj[i][j] << " "; cout << endl; } cout << "adj.size() = " << adj.size() << "（幾列）" << "，adj[0].size() = " << adj[0].size() << "（幾欄）" << endl; return 0; }
預期輸出
   0 1 2 3 
0: 0 1 0 1 
1: 1 0 1 0 
2: 0 1 0 0 
3: 1 0 0 0 
adj.size() = 4（幾列），adj[0].size() = 4（幾欄）

adj[i][j] == 1 代表頂點 i 和 j 之間有一條邊。無向圖的矩陣沿對角線對稱，所以每加一條邊要寫兩次。adj.size() 是列數、adj[0].size() 是欄數——二維 vector 的每一列可以不一樣長，這點跟真正的二維陣列不同。

💡 相鄰矩陣什麼時候划算

查「i 和 j 有沒有連」是 $O(1)$，非常快；代價是不管有幾條邊都要吃 $|V|^2$ 格。第 08 章算過一次：字梯問題有 5110 個四字母單字，相鄰矩陣要 5110 × 5110 = 26,112,100 格，但實際只有 53,286 條邊——填滿率 0.2%。所以那一章改用相鄰串列。

🔗 這在資料結構課哪裡會用到 · 第 08、03 章

第 08 章一開始就把相鄰矩陣與相鄰串列並排比較，矩陣的實作就是這一節的 vector<vector<int>>。

PART 07 · STL 容器速覽

STL 的 stack／queue／deque：課本要你「自己蓋」，講義也直接用現成的

第 05 章的主軸是自己蓋一個 Stack、Queue、Deque——用 vector 當底層，把 push／pop 寫出來，好搞懂它們到底是什麼。但同一章的應用題（括號配對、燙手山芋、迴文、印表機模擬）為了省事，很多地方直接用 STL 現成的容器。所以你會在同一章看到兩套介面並存。

💡 記得補標頭檔

這三個容器各有各的標頭：#include <stack>、#include <queue>、#include <deque>。課程 notebook 的 gcpph kernel 沒有自動幫你帶進來（vector、string 有），所以自己開新 cell 寫 stack<char> s; 卻編不過，八成就是漏了這一行。

三個容器的成員協定不一樣，而且不是誰包含誰——記錯就會呼叫到不存在的方法：

容器放進去看一眼拿掉其他講義出處
stack<T> push(x) top() pop() empty() size() 第 05 章括號配對：stack<char> s;
queue<T> push(x) front() back() pop() empty() size() 第 05 章燙手山芋：queue<string> simQueue;
deque<T> push_front(x) push_back(x) front() back() pop_front() pop_back() empty() size() d[i] 第 05 章迴文：deque<char> charDeque;

三個要點：① stack 只認得 top()，沒有 front()；queue 只認得 front()／back()，沒有 top()。② deque 兩頭都能進出，所以方法名一律帶方向。③ 三個都只裝值，要裝物件而不想複製就裝指標——第 05 章印表機模擬的 queue<Task*> printQueue; 就是這樣，隊伍裡排的是 Task 的位址。

⚠️ 最容易寫錯的一點：STL 的 pop() 不回傳東西

課本自己蓋的 Stack<T> 照 Python 的慣例，pop() 會把彈出來的值回傳給你，所以可以寫 T item = s.pop(); 一行搞定。

STL 的 stack 不是這樣：它的 pop() 回傳型別是 void。要值就得分成兩步——先 top() 抄下來，再 pop() 丟掉：

💡 char 可以做算術：s[i] - 'a' 是什麼意思

char 說穿了就是一個小整數（一個 byte），存的是字元的編碼值。ASCII 把 'a' 到 'z' 排成連續的 97 到 122，所以兩個字元相減，得到的是它們在字母表上差幾格：'c' - 'a' 是 2、't' - 'a' 是 19、'a' - 'a' 是 0。

這正好把 26 個小寫字母映射成 0–25，剛好可以當陣列索引用。第 07 章字謎判斷的計數解法整段就靠這一招：for (unsigned i = 0; i < s1.length(); i++) c1[s1[i] - 'a']++; —— c1 是 26 格的計數表，讀到 'c' 就讓第 2 格加一。兩個字串的計數表一模一樣，就是 anagram。注意這招只對小寫字母成立，混到大寫或空白就會算到別格去。

🔗 這在資料結構課哪裡會用到 · 第 02、06、08 章

第 02 章的 anagram 有四種解法，全部在操作 string：解法一把 s2 拆成 vector<char> 再一個一個 erase（所以是 $O(n^2)$）；解法二先 sort(s1.begin(), s1.end()) 再逐字比；解法四開兩個 26 格的計數陣列，用 s[i] - 'a' 當索引。

第 06 章的 toStr(n, base) 靠 convertString[n % base] 取字元、再用 + 把遞迴回來的字串接起來，1453 轉 16 進位就是這樣印出 5AD 的。

第 08 章的字梯問題整章都在切四字母單字：word.substr(0, i) + "_" + word.substr(i + 1) 把 fool 變成 _ool、f_ol、fo_l、foo_ 四個桶子，同一個桶子裡的單字彼此只差一個字母，就連一條邊。

PART 09 · 字串的成本

在迴圈裡串接字串：+= 便宜，s = s + x 很貴

兩行看起來只差一個等號，成本差了兩個數量級。原因回到 PART 03：s += 'x' 是就地加在尾端，容量夠就什麼都不用搬；s = s + 'x' 則要先算出 s + 'x' 這個全新的字串（複製整個 s），再賦值回去。

量給你看
#include <cstdio> #include <string> #include "pythonds3/cppds/dstimer.hpp" // 課程第 02 章的計時器，裡面是 <chrono> using namespace std; int main() { const int N = 100000; DSTimer t1; string a; for (int i = 0; i < N; i++) a += 'x'; // 就地長大 double ms1 = t1.millis(); DSTimer t2; string b; for (int i = 0; i < N; i++) b = b + 'x'; // 每次都複製一份全新的 double ms2 = t2.millis(); printf("s += 'x' %10.2f ms （攤還 O(1)/次）\n", ms1); printf("s = s + 'x' %10.2f ms （每次 O(n)，整體 O(n^2)）\n", ms2); printf("慢了 %.0f 倍\n", ms2 / ms1); return 0; }
預期輸出
s += 'x'            0.20 ms   （攤還 O(1)/次）
s = s + 'x'        98.80 ms   （每次 O(n)，整體 O(n^2)）
慢了 504 倍

十萬次的差距。+= 那條走的是攤還 $O(1)$，總成本 $O(n)$；s = s + 'x' 每一輪都複製一次現有內容，總成本是 $O(n^2)$。絕對時間每次跑會浮動，但兩者的比例穩定在幾百倍這個量級。

🎯 這一點跟 Python 的直覺相反

Python 的字串是不可變的，s += x 骨子裡也是重新配一個新字串（CPython 有特例最佳化，但不保證），所以那邊教你改用 "".join(parts)。C++ 的 string 是可變的，+= 就是真的就地長大，不需要繞路。記法很簡單：C++ 裡的 += 跟 push_back 是同一種東西。

char 與 string 是兩種東西

'a' 是一個 char，佔 1 byte，本質是一個 ASCII 整數；"a" 是字串。混用會出現初學最莫名其妙的錯誤之一：

兩個字面值相加：編譯器怎麼罵你
#include <iostream> #include <string> using namespace std; int main() { string s = "ab" + "cd"; // 兩個字面值相加：這行過不了 cout << s << endl; return 0; }
編譯錯誤（前三行）
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:6:21: error: invalid operands of types ‘const char [3]’ and ‘const char [3]’ to binary ‘operator+’
    6 |     string s = "ab" + "cd";       // 兩個字面值相加：這行過不了

"ab" 和 "cd" 的型別是 const char[3]，兩個陣列不能用 + 相加。解法是讓其中一邊先變成 string：string("ab") + "cd"，或者宣告成 string a = "ab"; a += "cd";。

轉換與陷阱
#include <iostream> #include <string> using namespace std; int main() { string s = "1453"; int n = stoi(s); // 字串 -> 整數 cout << "stoi(\"1453\") + 1 = " << n + 1 << endl; string t = to_string(n * 2); // 整數 -> 字串 cout << "to_string(2906) + \"!\" = " << t + "!" << endl; char c = s[0]; // s[0] 是 char，不是 string cout << "s[0] 是 char：" << c << "，佔 " << sizeof(c) << " bytes" << endl; cout << "s.substr(0,1) 是 string：" << s.substr(0, 1) << "，物件佔 " << sizeof(s.substr(0, 1)) << " bytes" << endl; string one(1, c); // 把一個 char 包成 string cout << "string(1, c) + \"X\" = " << one + "X" << endl; cout << "字元相加會變數字：c + 1 = " << c + 1 << "（char 被當成 ASCII 碼）" << endl; return 0; }
預期輸出
stoi("1453") + 1 = 1454
to_string(2906) + "!" = 2906!
s[0] 是 char：1，佔 1 bytes
s.substr(0,1) 是 string：1，物件佔 32 bytes
string(1, c) + "X" = 1X
字元相加會變數字：c + 1 = 50（char 被當成 ASCII 碼）

stoi 把字串轉整數、to_string 把數字轉字串，兩個都在 <string> 裡。最後一行是最容易中的陷阱：c + 1 得到 50，因為字元 '1' 的 ASCII 碼是 49——char 參與算術時會被當成整數。

操作成本表（本頁最該回頭查的東西）

操作複雜度為什麼
v[i]$O(1)$連續記憶體，位址直接算得出來。不檢查範圍
v.at(i)$O(1)$同上，多一次範圍檢查；越界丟 out_of_range
v.size()$O(1)$長度是存起來的，不用數
v.empty()$O(1)$就是問 size 是不是 0
v.capacity()$O(1)$同樣是存起來的欄位
v.push_back(x)攤還 $O(1)$通常只是寫進下一格；容量滿時要搬 n 個，但平攤下來是常數
v.pop_back()$O(1)$size 減一，沒有人需要移動
v.insert(pos, x)$O(n)$pos 之後每個元素都往後挪一格
v.erase(pos)$O(n)$pos 之後每個元素都往前挪一格
v.clear()$O(n)$要一個一個解構（int 這種簡單型別實務上很快）；capacity 不變
v.reserve(n)$O(n)$一次搬完，之後就不用再搬
走訪一遍$O(n)$三種寫法都一樣
find(v.begin(), v.end(), x)$O(n)$沒排序就只能一個一個看（第 07 章的主題）
s.length()$O(1)$跟 size() 是同一個東西
s[i]$O(1)$回傳的是 char，不是長度 1 的字串
s += x攤還 $O(1)$就地加在尾端，跟 push_back 同一回事
s = s + x$O(n)$ ／次先做出一個全新的字串再賦值。放在迴圈裡整體是 $O(n^2)$
s.substr(pos, len)$O(len)$複製出一個新字串
s.find(t)最差 $O(n \cdot m)$逐位置比對；找不到回傳 string::npos

五條記得住的規則

① 動尾巴便宜（push_back／pop_back／+=），動前面或中間就是 $O(n)$。
② size() 是住了幾個，capacity() 是有幾個位子；clear() 只清前者。
③ 知道要放幾個就先 reserve()，一次搬家都不會發生。
④ push_back 之後，之前記下來的 iterator 與指標都當作失效——記索引，不要記位址。
⑤ substr 的第二個參數是長度；find 找不到回傳 string::npos。
