PART 01 · 檔案

讀檔與寫檔：三個型別、一個模式

ofstream 寫、ifstream 讀，用法跟 cout／cin 一模一樣 —— 因為它們是同一家族。

寫進去再讀回來
#include <iostream> #include <fstream> #include <string> using namespace std; int main() { ofstream out("words.txt"); // 開檔寫入，不存在就建立 if (!out.is_open()) { cout << "開檔失敗" << endl; return 1; } out << "FOOL" << endl << "POOL" << endl << "POLL" << endl; out.close(); // 也可以讓它離開範圍自動關 ifstream in("words.txt"); // 開檔讀取 string line; int n = 0; while (getline(in, line)) { // 逐行讀到檔尾 cout << ++n << ": " << line << endl; } return 0; }
預期輸出
1: FOOL
2: POOL
3: POLL

三個重點：① 要 #include <fstream>。② getline(in, line) 讀到檔尾會回傳 false，所以可以直接當 while 的條件。③ close() 可以不寫 —— 物件離開範圍時解構式會自動關檔，這是 C++ 版的「自動收尾」，對應 Python 的 with。

寫法意思
ifstream in("a.txt");開檔讀取
ofstream out("a.txt");開檔寫入，清空原內容
ofstream out("a.txt", ios::app);附加到結尾
getline(in, line)讀一整行（含空白），讀到檔尾回傳 false
in >> word讀一個「詞」，以空白切開
🔗 這在資料結構課哪裡會用到 · 第 08 章

字梯問題需要一份四千多個五字母單字的清單。課程實際上是把單字寫死在 vector 裡（所以 ifstream 全課只出現一次），但如果你想自己換一份字典來玩，就是這一節的內容。

PART 02 · 開檔失敗

檔案不存在時，C++ 不會告訴你

開一個不存在的檔案
#include <iostream> #include <fstream> using namespace std; int main() { ifstream in("no_such_file.txt"); cout << "is_open() = " << in.is_open() << endl; cout << "檔案不存在時 ifstream 不會丟例外，只是進入失敗狀態。" << endl; cout << "所以開檔之後一定要自己檢查。" << endl; return 0; }
預期輸出
is_open() = 0
檔案不存在時 ifstream 不會丟例外，只是進入失敗狀態。
所以開檔之後一定要自己檢查。

它不丟例外、不當掉、什麼都不說，只是把串流設成失敗狀態。你如果不檢查就直接讀，會讀到零筆資料然後困惑半天。所以 ifstream 開完一定要接一句 if (!in.is_open())。

✅ 相對路徑是相對於「執行時的工作目錄」

不是相對於程式檔的位置。在 Jupyter 裡就是你啟動 jupyter lab 的那個目錄（跟 00B 講的 -I. 是同一個目錄）。「明明檔案就在旁邊卻開不起來」十次有九次是這個原因。

PART 03 · 例外

例外不是「壞掉」，是「這條路走不通，換你決定」

例外處理的骨架只有兩個關鍵字：try 圈出可能失敗的程式，catch 接住失敗。

try { // 可能失敗的那幾行，範圍越小越好找錯 risky(); } catch (const SpecificError& e) { // 只接住你預期會發生的那一種 cout << "出事了: " << e.what() << endl; } // 接住之後程式繼續往下跑
C++Python備註
try { } catch (…) { }try: / except:概念相同
throw X();raise X()主動拋出
e.what()str(e)取得訊息
沒有對應finally:C++ 用解構式自動收尾（RAII）
沒有對應else:C++ 沒有這個區塊
⚠️ 不要寫 catch (...) 把所有東西一起接住

它會連你自己寫錯造成的問題一起吞掉，讓程式默默給出錯誤答案。接住你預期會發生的那一種就好，其餘讓它往上傳。catch 的順序也要由窄到寬，寬的放後面 —— 放前面的話後面那些永遠接不到。

PART 04 · at() 與 []

兩個下標寫法，一個檢查範圍一個不檢查 整學期用得到

同一個越界存取，兩種下場
#include <iostream> #include <vector> #include <stdexcept> using namespace std; int main() { vector<int> v = {10, 20, 30}; cout << "v[10] -> " << v[10] << " <- 不檢查範圍，讀到垃圾值或當掉" << endl; try { cout << "v.at(10) -> " << v.at(10) << endl; } catch (const out_of_range& e) { cout << "v.at(10) -> 被 catch 接住了: " << e.what() << endl; } cout << "程式繼續往下跑。" << endl; return 0; }
預期輸出
v[10]     -> 1043144736   <- 不檢查範圍，讀到垃圾值或當掉
v.at(10)  -> v.at(10)  -> 被 catch 接住了: vector::_M_range_check: __n (which is 10) >= this->size() (which is 3)
程式繼續往下跑。

v[10] 不檢查範圍，直接讀那塊記憶體 —— 印出一個垃圾值（你跑會拿到不同的數字），而且沒有任何警告。v.at(10) 會丟 out_of_range，被 catch 接住。
順帶注意輸出裡 v.at(10) -> 印了兩次：左邊那段 cout 在例外拋出之前就已經送出去了。例外會中斷整條敘述，但已經發生的副作用不會被回復。

常見標準例外什麼時候發生
out_of_rangevector::at()、string::at() 越界
invalid_argumentstoi("abc") 這種轉不了的輸入
bad_allocnew 要不到記憶體
runtime_error通用的執行期錯誤，自訂例外常繼承它
🎯 什麼時候用哪個

開發與除錯時用 at() —— 越界會當場講清楚，比讀到垃圾值好追一百倍。確定索引安全的熱迴圈用 [] —— 少一次範圍檢查。課程的程式碼幾乎都用 []，但你自己 debug 時把它換成 at() 常常一秒找到問題。

🔗 這在資料結構課哪裡會用到 · 第 03、05、07 章

第 03 章的 ArrayList、第 05 章的堆疊佇列、第 07 章的雜湊表與排序，全部在對 vector 下標。索引算錯是這幾章最常見的 bug，at() 是最快的診斷工具。

PART 05 · 主動拋出

throw 與自訂例外

當函式無法完成它承諾的事時就該拋例外，而不是悄悄回傳一個假值。

空堆疊的 pop 該抗議
#include <iostream> #include <vector> #include <stdexcept> using namespace std; class EmptyStackError : public runtime_error { // 自訂例外，繼承標準的就好 public: EmptyStackError() : runtime_error("堆疊是空的，沒有東西可以彈出") { } }; template <typename T> class Stack { private: vector<T> items; public: void push(T item) { items.push_back(item); } T pop() { if (items.empty()) throw EmptyStackError(); // 我做不到，交給呼叫端決定 T top = items.back(); items.pop_back(); return top; } }; int main() { Stack<int> s; try { s.pop(); } catch (const EmptyStackError& e) { cout << "接住了: " << e.what() << endl; } return 0; }
預期輸出
接住了: 堆疊是空的，沒有東西可以彈出

自訂例外繼承 runtime_error 就好，連內容都不必寫，訊息透過建構式傳給父類別、再用 e.what() 取回。好處是呼叫端可以精準地只接住這一種，而不是用一個 catch 把所有問題一起吞掉。這也是 P9 繼承的實際應用。

💡 為什麼不回傳一個特殊值就好

因為沒有哪個值是安全的。空堆疊 pop 回傳 0？那真的存了 0 的時候怎麼辦？回傳 -1？那存負數呢？而且呼叫端很容易忘記檢查，錯誤就一路往下傳，最後在很遠的地方才爆出來。例外的價值就在於它不會被無視。

🔗 這在資料結構課哪裡會用到 · 第 05、09 章

dscpp/stack.hpp 的 pop() 沒有檢查空的情況——對空的 vector 呼叫 back() 是未定義行為。這是教材的簡化；你自己實作時加一個檢查會讓 debug 輕鬆很多。

PART 06 · 沒人接

例外沒有人接住會怎樣

讓它直接炸給你看
#include <iostream> #include <vector> using namespace std; int main() { vector<int> v = {1, 2, 3}; cout << "接下來這行會丟例外，而且沒有人接：" << endl; cout << v.at(99) << endl; cout << "這一行永遠不會被執行" << endl; return 0; }
預期輸出
接下來這行會丟例外，而且沒有人接：

[執行結束碼 -6]
terminate called after throwing an instance of 'std::out_of_range'
  what():  vector::_M_range_check: __n (which is 99) >= this->size() (which is 3)

程式直接終止，最後一行永遠不會執行。訊息 terminate called after throwing an instance of … 加上 what() 的內容，已經把「哪一種例外、為什麼」講得很清楚了 —— 這比讀到垃圾值好太多。結束碼 -6 是 SIGABRT，看到它就知道是例外沒接住或 assert 失敗。

✅ 沒接住其實常常是對的

不要為了「讓程式不要當」而到處包 try。你不知道怎麼處理的錯誤，就讓它炸 —— 帶著清楚訊息的當機，遠好過默默算出錯誤答案。只在你真的有辦法處理的地方才 catch。
