PART 01

固定大小陣列：一段連續的同型別元素

固定大小陣列適合保存數量在編譯時已知、型別相同的一組資料。宣告 int scores[4] 時，中括號內是元素個數，不是最後索引；四格依序編號 0、1、2、3。

#include <iostream>
int main() {
    int scores[4]{72, 81, 90, 66};
    int sum{0};
    for (int i{0}; i < 4; ++i) {
        sum += scores[i];
    }
    std::cout << sum << "\n";
}
預期輸出
309

int scores[4] 建立四個連續的 int，合法索引是 0 到 3。大括號逐一初始化；若初值較少，其餘元素會值初始化為 0。scores[i] 先找第 i 個元素，再取得該元素。

C++ 內建陣列不做執行期邊界檢查。讀寫 scores[4] 已越界，屬未定義行為；沒有可靠的「一定崩潰」結果。迴圈條件應是 i < 4，不是 i <= 4。

動手練習

int a[5]{2,4}; 五個元素依序為何？

看解答與理由

2, 4, 0, 0, 0。有列表初始化時，未列出的其餘元素會值初始化。

PART 02

地址、取址與解參考：三個符號

每個活著的物件都位於記憶體某處。&x 取得 x 的地址；int* 是「指向 int 的指標型別」；對有效指標做 *p 則沿地址找到目標物件。宣告中的 * 與運算式中的 * 字形相同，角色要靠位置判斷。

#include <iostream>
int main() {
    int score{70};
    int* p{&score};
    std::cout << score << " " << *p << "\n";
    *p = 95;
    std::cout << score << " " << *p << "\n";
}
預期輸出
70 70
95 95

第 4 行中 p 自己是另一個物件，保存的是 score 的地址；*p 指 p 的目標。指定 *p=95 修改目標，所以從 score 或 *p 觀察都變成 95。若寫 p = ...，修改的是指標保存的地址。

動手練習

想把 p 指向的整數加 1，應寫 *p += 1 還是 p += 1？

看解答與理由

前者修改目標值；後者移動指標，使它指向下一個 int 位置，兩者完全不同。

指標本身與目標是兩個物件

分開追蹤 p 保存的地址與 score 保存的數值。

int score{70};
int* p{&score};
*p = 95;





PART 03
空指標與使用前檢查


#include <iostream>
int main() {
    int* p{nullptr};
    if (p != nullptr) {
        std::cout << *p << "\n";
    } else {
        std::cout << "no target\n";
    }
}
預期輸出
no target



nullptr 是 C++11 起的空指標字面值，表示目前不指向任何物件。可以比較、指定，卻不可解參考；*p 在 p 為空時是未定義行為。未初始化指標甚至不保證為空，所以應立即設為有效地址或 nullptr。


舊程式常見 NULL，它通常由巨集展開成整數常數，可能在多載選擇時造成歧義；新 C++ 使用有專用型別的 nullptr。指標條件 if (p) 可用，但初學時寫 p != nullptr 更直接。


動手練習
delete 後把唯一指標設為 nullptr 有何作用？
看解答與理由
它避免該變數繼續保留已失效地址，也讓重複 delete p 對 nullptr 安全；但其他別名若仍保存舊地址，並不會自動變空。





PART 04
指標算術、索引與合法範圍


#include <iostream>
int main() {
    int values[4]{10, 20, 30, 40};
    int* p{values};
    std::cout << *p << " " << *(p + 2) << " " << p[3] << "\n";
}
預期輸出
10 30 40



陣列名稱在多數運算式中轉成指向第一個元素的指標，所以 p 取得 &values[0]。p+2 不是地址數字加 2 byte，而是移動兩個 int 元素；因此 p[i] 定義上等同 *(p+i)。


指標算術只在同一陣列範圍內有意義。可以形成「尾端後一格」指標供比較，但不可解參考它；再越過則不合法。不要對無關物件的指標做大小比較或相減來推論位置。


逐步走訪連續元素
p 每次前進一個 int 元素。
int a[3]{4, 7, 9};
int* p{a};
int sum{0};
sum += *p;
++p;
sum += *p;
++p;
sum += *p;


動手練習
若 p 指向 a[1]，p[-1] 在本例是否合法？
看解答與理由
合法，因為它等同 *(p-1)，仍落在同一陣列的 a[0]；負索引本身不保證錯，關鍵是結果是否仍在合法範圍。





PART 05
陣列退化後，長度資訊不跟著走


#include <cstddef>
#include <iostream>
void print(const int* data, std::size_t length) {
    for (std::size_t i{0}; i < length; ++i) {
        std::cout << data[i] << (i + 1 == length ? '\n' : ' ');
    }
}
int main() {
    int data[3]{8, 5, 2};
    std::size_t length = sizeof(data) / sizeof(data[0]);
    print(data, length);
}
預期輸出
8 5 2



在 main 中，sizeof(data) 是整個陣列的 byte 數，除以單一元素大小可得元素數。這只在 data 仍是實際陣列的作用域成立。一傳入函式，參數寫成 const int data[] 仍會調整成 const int*；函式內 sizeof(data) 得到的是指標大小，不是陣列大小。


所以原始陣列介面要同時傳指標與長度。const int* 表示函式透過此指標只讀元素；它不代表指標變數本身不可移動。長度使用 std::size_t，與 sizeof 的結果型別相容。


動手練習
為何不能在 print 內用 sizeof(data)/sizeof(data[0]) 求長度？
看解答與理由
函式參數中的陣列寫法已調整成指標，sizeof(data) 只量指標。長度已遺失，必須由呼叫端另傳或使用能保留大小的介面。


const int* data 的 const 修飾目標 int：不能經 data 修改元素，但 data 這個區域指標仍可前進。若是 int* const p，則固定的是指標本身；它必須初始化，之後不能改指向。兩個位置不可混讀。





PART 06
值參數、參考參數與指標參數


#include <iostream>
void byValue(int x) { ++x; }
void byReference(int& x) { ++x; }
void byPointer(int* x) {
    if (x != nullptr) ++(*x);
}
int main() {
    int n{5};
    byValue(n);
    std::cout << n << " ";
    byReference(n);
    std::cout << n << " ";
    byPointer(&n);
    std::cout << n << "\n";
}
預期輸出
5 6 7



三次呼叫用同一個 n 對照：傳值建立副本，所以第一次後仍為 5；參考成為 n 的別名，第二次後是 6；指標參數取得 n 的地址，檢查非空後解參考，第三次後是 7。


值參數複製資料；int& 參考適合一定存在且需修改的目標；int* 可表示沒有目標或配合陣列走訪，因此使用前要檢查。


動手練習
若呼叫 byPointer(nullptr)，函式會做什麼？
看解答與理由
守衛條件使它不解參考，直接返回。這正是指標參數能表達「沒有目標」時，函式必須明確處理的路徑。





PART 07
stack 與 heap：差別在生命週期


一般區域變數具有自動儲存期：進入區塊時建立，離開時自動銷毀，實作通常放在呼叫堆疊。以 new 建立的物件具有動態儲存期，直到對同一配置做相符的 delete 才結束，實作通常稱為 heap。


問題自動物件動態物件
何時建立執行到宣告執行 new / new[]
何時銷毀離開作用域delete / delete[]
名稱離開作用域後物件一起結束若無其他指標，配置仍存在並洩漏
適合大小與生命週期清楚生命週期或大小需在執行期決定


heap 並非「比較大所以比較好」；手動生命週期帶來 ownership 責任。現代 C++ 實務通常以容器與智慧指標管理資源，本節仍學 new/delete，因為必須看懂底層模型與舊程式。


動手練習
函式內 int local{3}; 回傳 &local 為何錯？
看解答與理由
函式返回時 local 的生命週期結束，地址立刻成為懸空指標；之後解參考是未定義行為。


#include <iostream>
int main() {
    int outer{4};
    {
        int inner{9};
        std::cout << outer + inner << "\n";
    }
    std::cout << outer << "\n";
}
預期輸出
13
4



inner 在內層右大括號處生命結束，outer 則活到 main 結束。若保存 inner 的地址並在區塊後解參考，地址雖仍是某個數字，目標物件已不存在，因而懸空。判斷安全性要追生命週期，不看地址外觀。





PART 08
new/delete：單一物件與動態陣列


#include <iostream>
int main() {
    int* p = new int{42};
    std::cout << *p << "\n";
    delete p;
    p = nullptr;
}
預期輸出
42



先看單一物件：new int{42} 在動態儲存區建立並初始化一個 int，回傳地址給 p；解參考讀值後，以完全相配的 delete p 結束其生命，再清空唯一指標。每一個 new 都要能指出唯一負責釋放的 owner。


範例輸入
5

#include <cstddef>
#include <iostream>
#include <new>
int main() {
    std::size_t n{0};
    if (!(std::cin >> n) || n == 0 || n > 1000) {
        std::cerr << "length must be 1..1000\n";
        return 1;
    }
    int* data = new (std::nothrow) int[n]{};
    if (data == nullptr) {
        std::cerr << "allocation failed\n";
        return 1;
    }
    for (std::size_t i{0}; i < n; ++i) data[i] = static_cast<int>(i * i);
    std::cout << data[n - 1] << "\n";
    delete[] data;
    data = nullptr;
}
預期輸出
16



new int{7} 配置並初始化單一 int，必須以 delete p 釋放。new int[n]{} 配置 n 個元素並零初始化，必須以 delete[] p 成對釋放；混用兩種 delete 是未定義行為。範例先驗證輸入與上限，再配置，避免 n=0 後存取 n-1，也避免不受限的巨量請求。


一般 new 配置失敗會丟出 std::bad_alloc；此例刻意使用 std::nothrow，失敗時回傳 nullptr，因此需要空值檢查。兩種模式不要混著假設。


動手練習
new int[20] 應用哪個釋放式？
看解答與理由
delete[] p;。即使元素是 int，也必須與陣列形式的 new[] 配對。


std::nothrow 是普通 new 的另一種失敗模式：一般 new 失敗會丟出 std::bad_alloc，nothrow 版本改回傳 nullptr，所以範例才明確檢查。先理解配置、使用、配對釋放三步，再選擇如何處理失敗。





PART 09
ownership、alias 與四種典型錯誤


owner 是負責讓動態配置恰好釋放一次的程式角色；普通裸指標的型別本身不說明它是否擁有資源。兩個指標可保存同一地址，稱為 alias。alias 很實用，但釋放後所有指向該物件的 alias 都一起失效。


int* owner = new int{42};
int* alias = owner;
delete owner;
owner = nullptr;
// *alias;       // 錯：alias 已懸空
// delete alias; // 錯：同一配置重複釋放


配置生命週期播放器
分開看兩個指標格與一個目標物件。
int* owner = new int{42};
int* alias = owner;
delete owner;
owner = nullptr;


錯誤發生方式後果／修正
記憶體洩漏最後一個地址遺失前未 delete配置仍占用；保存 owner 並釋放
懸空指標目標生命週期已結束不可解參考；重設所有相關使用路徑
重複釋放同一配置 delete 兩次未定義行為；明確單一 owner
錯配釋放new[] 配 delete 或反之未定義行為；形式必須成對


把 owner 設 nullptr 只改這一個指標，alias 不會同步。真正的推理核心是物件生命週期，而不是「地址看起來還在」。實務上優先使用 std::vector、std::string 與智慧指標，把 ownership 寫進型別。


動手練習
delete owner; owner=nullptr; 後，alias 是否安全變成 nullptr？
看解答與理由
不會。alias 是另一個指標物件，仍保留舊地址但已懸空。不可解參考或 delete 它。





PART 10
P4 語法速查


目的語法必要條件
取地址&xx 仍活著
解參考*pp 非空且指向有效物件
陣列索引p[i] == *(p+i)結果在同一陣列合法範圍
陣列長度sizeof(a)/sizeof(a[0])a 必須仍是實際陣列
可空參數void f(int* p)使用前檢查 nullptr
單一配置new int{v} / delete p恰好釋放一次
陣列配置new int[n]{} / delete[] p先驗證 n 與配置結果


動手練習
一句話分清 p 與 *p。
看解答與理由
p 是保存地址的指標物件；*p 是該有效地址所指的目標物件。
