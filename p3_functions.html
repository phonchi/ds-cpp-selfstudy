PROLOGUE · 開場

同一個 swap(a, b)，三種寫法，只有兩種真的換得動

下面這支程式把三種傳法一次跑完。三個函式的函式本體一模一樣，差別只在參數列上多不多一個符號。

三種傳法，同一份交換邏輯（真的跑出來的）
#include <iostream> using namespace std; void swapByValue(int a, int b) { // 收到的是副本 int t = a; a = b; b = t; } void swapByRef(int &a, int &b) { // 收到的是本人的別名 int t = a; a = b; b = t; } void swapByPtr(int *a, int *b) { // 收到的是位址 int t = *a; *a = *b; *b = t; } int main() { int x = 3, y = 7; swapByValue(x, y); cout << "傳值 之後: x=" << x << " y=" << y << endl; x = 3; y = 7; swapByRef(x, y); cout << "傳參考 之後: x=" << x << " y=" << y << endl; x = 3; y = 7; swapByPtr(&x, &y); cout << "傳指標 之後: x=" << x << " y=" << y << endl; return 0; }
預期輸出
傳值   之後: x=3 y=7
傳參考 之後: x=7 y=3
傳指標 之後: x=7 y=3

第一行是災難：swapByValue 認真地把 a 和 b 換了一遍，換的卻是它自己手上的兩份副本，函式一結束副本就沒了，x 與 y 原封不動。後面兩行成功，因為 int &a 與 int *a 都讓函式碰得到 main 裡的那兩格記憶體。

C++ 不會警告你第一種寫法沒有效果。它會安靜地編譯、安靜地執行、安靜地什麼都沒做。整頁要處理的就是這件事：參數列上那個 & 到底改變了什麼。

PART 01 · 宣告與定義

編譯器由上而下讀一遍，讀到才算數

Python 直譯器是在呼叫的當下才去查函式在哪裡，所以函式定義寫在下面也沒關係。C++ 的編譯器只從頭到尾掃一遍原始碼，掃到函式呼叫時如果還沒見過這個名字，它連「這是不是函式」都不知道。

定義寫在 main 後面，直接編不過
#include <iostream> using namespace std; int main() { cout << square(5) << endl; // 編譯器讀到這裡時還沒見過 square return 0; } int square(int n) { return n * n; }
預期輸出
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:5:13: error: ‘square’ was not declared in this scope
    5 |     cout << square(5) << endl;   // 編譯器讀到這裡時還沒見過 square

error: ‘square’ was not declared in this scope。這是初學最常收到的錯誤訊息之一，意思很單純：你用了一個編譯器還沒認識的名字。

解法是先寫一行函式原型（function prototype），把回傳型別、名稱、參數型別交代清楚，結尾用分號。這一行就是宣告；有函式本體的那一份才是定義。

加一行宣告就過了
#include <iostream> using namespace std; int square(int n); // 宣告（函式原型）：先告訴編譯器它長什麼樣 int main() { cout << "square(5) = " << square(5) << endl; return 0; } int square(int n) { // 定義：實際的程式碼可以擺在後面 return n * n; }
預期輸出
square(5) = 25

宣告只需要型別，參數名可以省略：int square(int); 一樣合法。編譯器要的是「呼叫時該推幾個什麼型別的東西進去、回傳幾個 byte」，參數叫什麼跟它無關。

宣告 declaration定義 definition
長相int square(int n);int square(int n) { ... }
作用告訴編譯器這個名字的長相提供實際的程式碼
可以出現幾次幾次都行整個程式只能一次
放哪個檔.hpp.cpp
💡 為什麼課程的 dscpp 全部塞在 .hpp 裡

一般的分工是宣告放標頭檔、定義放 .cpp，別人 #include 你的標頭檔就知道怎麼呼叫。但課程的 dscpp/ 全部是 template：樣板要等到你寫出 Stack<int> 那一刻編譯器才知道要生哪一版程式碼，所以樣板的定義必須跟宣告放在同一個標頭檔裡。這就是為什麼 linked_list.hpp 裡連函式本體都在。

PART 02 · 傳值

傳值：函式拿到的是副本

void f(int n) 這種寫法叫傳值（pass by value）。呼叫的瞬間，編譯器把你給的東西整個抄一份放進函式的參數裡。函式接下來怎麼折騰那份副本，外面那個都不會知道。

void addOne(int v) { // v 是一份全新的副本 v = v + 1; // 改的是副本 } // 函式結束，副本消失 int score = 60; addOne(score); // score 還是 60

這個規則沒有例外，而且對物件也一樣。物件被複製時，編譯器會呼叫它的複製建構式（copy constructor）。下面這支程式把複製這件事印出來給你看。

複製是有成本的，而且成本看得見
#include <iostream> using namespace std; class Big { public: Big(int id) { tag = id; cout << " [建構] Big " << tag << endl; } Big(const Big &other) { // 複製建構式 tag = other.tag; cout << " [複製] 又抄了一份 Big " << tag << " ← 這行就是成本" << endl; } int getTag() const { return tag; } private: int tag; }; void byValue(Big b) { cout << " 函式裡看到 " << b.getTag() << endl; } void byConstRef(const Big &b) { cout << " 函式裡看到 " << b.getTag() << endl; } int main() { Big item(7); cout << "呼叫 byValue(item):" << endl; byValue(item); cout << "呼叫 byConstRef(item):" << endl; byConstRef(item); return 0; }
預期輸出
  [建構] Big 7
呼叫 byValue(item):
  [複製] 又抄了一份 Big 7 ← 這行就是成本
  函式裡看到 7
呼叫 byConstRef(item):
  函式裡看到 7

byValue(item) 那一行觸發了一次 [複製]。這裡只是一個 int 成員，所以看不出痛；換成一個裝了十萬個元素的 vector，這一行就是十萬次複製。第二個函式收 const Big &，一次複製都沒有——那是 PART 05 的主題。

傳值的時機理由
參數是 int、double、char、bool 這種小東西複製 4 到 8 個 byte 比繞位址還快
函式本來就想要一份自己的，改了不該影響呼叫端複製本身就是你要的效果
大物件別用傳值。用 const T&
💡 Python 沒有這個問題，但也沒有這個選擇

Python 傳的一律是物件的參考，所以一個 list 傳進函式，函式裡 append 一下外面就跟著變；整數則因為不可變而看起來像傳值。C++ 把這件事交給你在參數列上明講：抄一份、還是給本人。講清楚的代價是多打幾個字，好處是讀程式的人光看簽章就知道這個函式會不會動到你的資料。

PART 03 · 傳參考

傳參考：同一個東西的另一個名字 課程用 57 次

int &r = x; 讀作「r 是 x 的參考」。它不配置新的記憶體，也不存位址，它就是編譯器層級的一個別名。從此以後寫 r 跟寫 x 完全等價。

參考與本尊住同一個門牌
#include <iostream> using namespace std; int main() { int x = 10; int &r = x; // r 不是新變數，它就是 x 的另一個名字 r = 99; cout << "改了 r 之後 x = " << x << endl; cout << "x 的位址 = " << &x << endl; cout << "r 的位址 = " << &r << " <- 完全一樣" << endl; cout << "sizeof(x)=" << sizeof(x) << " sizeof(r)=" << sizeof(r) << endl; return 0; }
預期輸出
改了 r 之後 x = 99
x 的位址 = 0x7ffe931b930c
r 的位址 = 0x7ffe931b930c   <- 完全一樣
sizeof(x)=4  sizeof(r)=4

兩個位址一模一樣，sizeof 也一樣是 4——因為 r 根本沒有自己的身體。對照 P4 的指標：指標自己佔 8 個 byte，參考佔 0 個。

參數列上寫 T&，函式收到的就是呼叫端那個變數本人：

一個 & 的差別
#include <iostream> using namespace std; void addOneWrong(int v) { v = v + 1; } // 漏了 & void addOneRight(int &v) { v = v + 1; } // 有 & int main() { int score = 60; addOneWrong(score); cout << "呼叫 addOneWrong 之後: " << score << endl; addOneRight(score); cout << "呼叫 addOneRight 之後: " << score << endl; return 0; }
預期輸出
呼叫 addOneWrong 之後: 60
呼叫 addOneRight 之後: 61

兩個函式的本體完全相同，只有參數列差一個 &，結果一個做白工、一個真的加到了。編譯這支程式時 g++ 一個字都不會抱怨——addOneWrong 在語法上完全合法，它只是沒有用。

傳值 void f(T x)傳參考 void f(T& x)
函式拿到什麼一份副本呼叫端那個變數本人
改得動外面嗎改不動改得動
複製成本整個物件抄一遍零
呼叫端寫法f(x);f(x);　← 看不出差別
可以傳 3、傳 a+b 嗎可以不行，非 const 參考只收得下有名字的變數
⚠️ 呼叫端看不出來

f(x); 這一行，無論 f 收的是值還是參考，寫法完全一樣。所以你必須去看函式簽章才知道自己的變數會不會被改掉。指標就沒這個問題：f(&x) 那個 & 明擺在呼叫端。這是下一節要談的取捨。

PART 04 · 傳指標

傳指標：明著把位址交出去

第三種寫法是 void f(T* p)，呼叫時寫 f(&x)。函式收到一個位址，用 *p 走進去改。效果跟傳參考一樣，多的是兩件事：它可以是 NULL，而且可以中途改指向別的東西。

指標做得到、參考做不到的兩件事
#include <iostream> using namespace std; void tryFill(int *p) { if (p == NULL) { // 指標可以是 NULL，所以要檢查 cout << " 收到 NULL，什麼都不做" << endl; return; } *p = 42; } void mustFill(int &r) { // 參考保證後面有東西，不用檢查 r = 42; } int main() { int a = 0; tryFill(&a); cout << "tryFill(&a) 之後 a = " << a << endl; tryFill(NULL); cout << "傳 NULL 進去也不會當掉" << endl; int b = 0; mustFill(b); cout << "mustFill(b) 之後 b = " << b << endl; int c = 1, d = 2; int *p = &c; p = &d; // 指標可以改指向別的東西 cout << "p 改指向 d 之後 *p = " << *p << endl; return 0; }
預期輸出
tryFill(&a)  之後 a = 42
  收到 NULL，什麼都不做
傳 NULL 進去也不會當掉
mustFill(b)  之後 b = 42
p 改指向 d 之後 *p = 2

tryFill(NULL) 是合法呼叫，函式自己檢查後安全退場。參考沒有「空參考」這種東西，所以 mustFill 不必檢查——參考在型別上就保證了後面有東西。最後兩行則是指標的另一個能力：換一個目標。

參考 T&指標 T*
可以是「沒有」嗎不行，一定綁著某個東西可以，就是 NULL
綁定之後能改嗎不行，一輩子只認一個可以隨時改指向別的
取值怎麼寫r*p
呼叫端怎麼寫f(x);f(&x);
自己佔記憶體嗎不佔佔，通常 8 bytes
這門課用在哪參數與回傳（57 次）節點與資料結構本身（145 次）
🎯 選哪一個

預設用參考。只有在「這個參數可以是沒有」或「函式要換掉它指向的目標」時才用指標。第 04 章的 remove() 屬於前者，稍後就會看到。

三種傳法，一次看清楚

下面這個逐步器跑的就是開場那支程式。左邊是兩個函式框（呼叫端與被呼叫端）在記憶體裡的樣子，右邊的程式碼會同步高亮。三個按鈕換傳法，注意被呼叫端那兩格是新的還是舊的。

›選一種傳法開始。三個版本的函式本體完全一樣。
速度
程式碼 CODE
void swapByValue(int a, int b) { int t = a; a = b; b = t; } int x = 3, y = 7; swapByValue(x, y);
void swapByRef(int &a, int &b) { int t = a; a = b; b = t; } int x = 3, y = 7; swapByRef(x, y);
void swapByPtr(int *a, int *b) { int t = *a; *a = *b; *b = t; } int x = 3, y = 7; swapByPtr(&x, &y);
看哪裡 KEY

傳值：callee 那格是新配的，位址不同。
傳參考：callee 那格根本沒有新配，a 只是 x 的另一個標籤。
傳指標：callee 多了兩格，裡面裝的是 x 和 y 的門牌。

🔗 這在資料結構課哪裡會用到 · 第 04 章

dscpp/linked_list.hpp 的 remove(T item) 要一邊走訪一邊記住前一個節點：Node<T> *current = head; Node<T> *previous = NULL;。previous 一開始刻意是 NULL，因為第一個節點沒有前一個；刪除時就靠 if (previous == NULL) 分辨「刪的是不是頭」。這個「可以是沒有」的語意，參考做不到，只能用指標。

PART 05 · const 參考

const T&：不複製，也不讓你改

前面兩節留了一個矛盾：傳值太貴，傳參考又讓函式有能力改動你的資料。const T& 把兩邊的好處都拿走了——參數不複製，而且編譯器保證函式碰不了它。

void print(const string &s) { // 不複製、不能改 cout << s << endl; // s = "x"; // 這行會編譯錯 }
試著改一個 const 參考
#include <iostream> using namespace std; void peek(const int &v) { v = 99; // const 參考不准改 } int main() { int x = 3; peek(x); return 0; }
預期輸出
[編譯失敗]
cell.cpp: In function ‘void peek(const int&)’:
cell.cpp:5:7: error: assignment of read-only reference ‘v’
    5 |     v = 99;                 // const 參考不准改

error: assignment of read-only reference。這是編譯期就擋下來的，不是跑到一半才出事。const 在 C++ 是一個會被檢查的承諾，不是註解。

三種傳法的決策表（本頁核心）

你想做的事寫法複製嗎改得動嗎
參數很小，函式想要一份自己的void f(int n)會只改副本
要改動呼叫端的資料void f(T& x)不會會
只是要讀一個大物件void f(const T& x)不會不會
參數可能是「沒有」，或要換目標void f(T* p)不會會

第三列是傳大物件的標準做法。看到 const vector<int>& v 這種簽章不用緊張，它只是在說「我要看你的資料，我保證不動它，而且我不想抄一份」。

順帶解釋：為什麼 getter 要寫 const

成員函式的參數列後面也可以掛一個 const，例如 int getNum() const。它的意思是「這個函式不會動到物件的任何成員」。乍看多此一舉，直到你想把物件用 const T& 傳出去：

getter 有 const，const 參考才用得下去
#include <iostream> using namespace std; class Fraction { public: Fraction(int t, int b) { num = t; den = b; } int getNum() const { return num; } // const：保證不動到成員 int getDen() const { return den; } private: int num, den; }; void show(const Fraction &f) { // 收 const 參考：不複製也不改 cout << f.getNum() << "/" << f.getDen() << endl; } int main() { Fraction half(1, 2); show(half); return 0; }
預期輸出
1/2

show 收的是 const Fraction &，所以它手上的 f 是唯讀的。唯讀物件只准呼叫承諾過不改東西的成員函式，也就是尾巴有 const 的那些。

把 getter 的 const 拿掉，同一支程式就編不過
#include <iostream> using namespace std; class Fraction { public: Fraction(int t, int b) { num = t; den = b; } int getNum() { return num; } // 忘記寫 const private: int num, den; }; void show(const Fraction &f) { cout << f.getNum() << endl; // const 物件不能呼叫非 const 成員函式 } int main() { Fraction half(1, 2); show(half); return 0; }
預期輸出
[編譯失敗]
cell.cpp: In function ‘void show(const Fraction&)’:
cell.cpp:13:21: error: passing ‘const Fraction’ as ‘this’ argument discards qualifiers [-fpermissive]
   13 |     cout << f.getNum() << endl;                 // const 物件不能呼叫非 const 成員函式

discards qualifiers 的意思是「你想把一個唯讀物件當成可寫的用」。所以規則很簡單：getter 一律加 const，否則你的類別沒辦法用 const T& 傳遞，等於逼所有人都得複製。

✅ 現代 C++ 對照

C++11 之後還有移動語意（move semantics）與 T&&，讓「回傳一個大物件」也能不複製。本課照 cppds，考試以課程風格為準：需要就地改動就用 T&，只讀就用 const T&，這兩招足以應付九章的全部程式碼。

PART 06 · 回傳

回傳：可以給值，可以給參考，就是不能給死掉的東西

回傳值跟傳值是同一件事的反方向：return x; 會把 x 複製一份交給呼叫端，所以就算 x 是函式的區域變數也沒關係，函式結束時死的是原件，副本已經送出去了。

回傳參考 T& 就不一樣了。它交出去的是「那個東西本人」，所以那個東西必須在函式結束後還活著。

回傳參考的正當用法：指向的是成員，不是區域變數
#include <iostream> using namespace std; class Counter { public: Counter() { n = 0; } int &value() { return n; } // 回傳參考：指向的是成員，不是區域變數 private: int n; }; int main() { Counter c; c.value() = 5; // 回傳參考，所以可以放在等號左邊 c.value() += 3; cout << "c.value() = " << c.value() << endl; return 0; }
預期輸出
c.value() = 8

value() 回傳的參考綁在成員 n 上，而 n 的壽命跟物件一樣長。所以 c.value() = 5; 這種「函式呼叫出現在等號左邊」的寫法是合法的，第 03 章你自己寫 ArrayList 的 operator[] 時就會用到這一招。

絕對不能做的事

回傳區域變數的位址或參考。區域變數住在呼叫堆疊上，函式一 return，那塊空間就還給系統了，你交出去的是一張過期的門牌。

g++ 有警告，而且是預設就開的
#include <iostream> using namespace std; int *makeNumber() { int local = 1234; // 住在堆疊上，函式一結束就沒了 return &local; // 回傳一個馬上要失效的位址 } int main() { int *p = makeNumber(); cout << "p 拿到的位址 = " << p << endl; cout << "順著它讀出來 = " << *p << endl; return 0; }
g++ 的警告
cell.cpp: In function ‘int* makeNumber()’:
cell.cpp:6:12: warning: address of local variable ‘local’ returned [-Wreturn-local-addr]
    6 |     return &local;           // 回傳一個馬上要失效的位址
      |            ^~~~~~
cell.cpp:5:9: note: declared here
    5 |     int local = 1234;        // 住在堆疊上，函式一結束就沒了
      |         ^~~~~

-Wreturn-local-addr 這個警告不需要 -Wall 就會出現。看到 warning 不要跳過——C++ 的警告訊息裡，這一類幾乎百分之百是真的錯。

那它跑起來會怎樣？
實際執行輸出
p 拿到的位址 = 0

[執行結束碼 -11]

g++ 發現你回傳一個必死的位址，乾脆直接把它換成 0，於是印出來的位址是 0，接著解參考一個空位址，程式收到 SIGSEGV（結束碼 −11）當場結束。換一個編譯器、換一個最佳化等級，你可能會看到 1234、看到垃圾值、看到程式若無其事地跑完。未定義行為的意思就是連結果都不保證一致，所以你沒辦法靠「我試過了，可以跑」來證明它是對的。

需要一個活得比函式久的東西，就把它配在堆積上，然後講清楚誰負責 delete：

要活得久，就 new 在堆積上
#include <iostream> using namespace std; int *makeNumberOK() { int *p = new int(1234); // 配在堆積上，函式結束也不會消失 return p; } int main() { int *p = makeNumberOK(); cout << "讀出來 = " << *p << endl; delete p; // 呼叫端負責還 p = NULL; return 0; }
預期輸出
讀出來 = 1234

new 出來的東西不歸呼叫堆疊管，函式結束也不會消失。代價是呼叫端必須記得 delete——這就是第 04 章串列的節點所有權模型。new／delete 的細節在 P4。

🔗 這在資料結構課哪裡會用到 · 第 04、09 章

第 04 章的 add() 每次都 new 一個 Node<T> 並把指標接進串列，這些節點的壽命必須長過 add() 本身；第 09 章的 BST 插入也是同一套。反過來說，只要你在函式裡寫 Node<T> temp;（沒有 new）再回傳它的位址，那棵樹就毀了。三種傳法與回傳的規則在 P4 會從記憶體佈局再看一次。

PART 07 · 多載與預設引數

同一個名字，好幾種呼叫法

C++ 允許好幾個函式共用一個名字，只要參數的個數或型別不同就行。編譯器會依照你呼叫時給的東西挑一個，這叫函式多載（function overloading）。挑選只看參數，回傳型別不算——兩個函式只有回傳型別不同的話會直接編譯錯。

課程第 01 章的 Fraction 就是靠多載提供三種建立方式：

class Fraction { public: Fraction(int top, int bottom); // 兩個引數：3/4 Fraction(int top); // 一個引數：5/1 Fraction(); // 沒有引數：1/1 };
三個建構式都是同一個名字（引用課程的 fraction.hpp）
#include "fraction.hpp" int main() { Fraction a(3, 4); // 兩個引數 Fraction b(5); // 一個引數：5/1 Fraction c; // 沒有引數：1/1 cout << a << " " << b << " " << c << endl; cout << "a + b = " << a + b << endl; return 0; }
預期輸出
3/4  5/1  1/1
a + b = 23/4

三行宣告分別挑中三個不同的建構式。這支程式直接 #include "fraction.hpp"，用的就是課程 dscpp/ 底下那一份，沒有另外抄。順帶一提，a + b 能寫成這樣是因為 Fraction 也多載了 operator+。

預設引數

另一條路是給參數一個預設值，呼叫時可以省略：

省略的參數自動吃預設值
#include <iostream> using namespace std; void report(string name, int score = 60, bool pass = true) { cout << name << " " << score << " " << (pass ? "通過" : "未通過") << endl; } int main() { report("小明", 92, true); report("小華", 55); // pass 用預設值 true report("小美"); // score 與 pass 都用預設值 return 0; }
預期輸出
小明 92 通過
小華 55 通過
小美 60 通過

三次呼叫分別給了 3、2、1 個引數。省略的部分從左到右對不上就補預設值，所以 report("小華", 55) 的 pass 用的是 true。

⚠️ 預設引數只能靠右邊排

因為呼叫端是由左往右對位的。如果 void f(int a = 1, int b) 合法，那 f(5) 到底是給 a 還是給 b？編譯器不猜，直接拒絕。

把有預設值的參數放前面，編譯器直接擋下
#include <iostream> using namespace std; void report(int score = 60, string name) { // 有預設值的參數放前面 cout << name << " " << score << endl; } int main() { report(90, "小明"); return 0; }
預期輸出
[編譯失敗]
cell.cpp:4:36: error: default argument missing for parameter 2 of ‘void report(int, std::string)’
    4 | void report(int score = 60, string name) {   // 有預設值的參數放前面
      |                             ~~~~~~~^~~~

default argument missing for parameter 2，訊息說得很白：第 2 個參數也得有預設值。規則記成一句話：有預設值的參數必須排在最後面，而且一路排到底。

💡 多載與預設引數會打架

同時寫 void f(int a) 與 void f(int a, int b = 0)，那 f(3) 兩邊都符合，編譯器會回報 call of overloaded ... is ambiguous。這兩個工具解決的是同一個問題，挑一個用就好。

PART 08 · 遞迴與呼叫堆疊

函式呼叫自己，堆疊上就多一個框

每次呼叫函式，系統會在呼叫堆疊（call stack）上開一個新的堆疊框（stack frame），裡面放這一次呼叫的參數、區域變數，以及「回去之後要從哪一行繼續」。函式回傳時這個框就被彈掉。遞迴沒有任何特別之處，它只是讓框疊得比較高。

把進出的順序印出來
#include <iostream> using namespace std; int depth = 0; int sumTo(int n) { for (int i = 0; i < depth; i++) cout << " "; cout << "進入 sumTo(" << n << ")" << endl; depth++; int result; if (n <= 1) { result = n; // 基底情形：不再往下叫 } else { result = n + sumTo(n - 1); // 遞迴情形：問題變小一號 } depth--; for (int i = 0; i < depth; i++) cout << " "; cout << "離開 sumTo(" << n << ") 回傳 " << result << endl; return result; } int main() { int answer = sumTo(4); cout << "答案 = " << answer << endl; return 0; }
預期輸出
進入 sumTo(4)
  進入 sumTo(3)
    進入 sumTo(2)
      進入 sumTo(1)
      離開 sumTo(1) 回傳 1
    離開 sumTo(2) 回傳 3
  離開 sumTo(3) 回傳 6
離開 sumTo(4) 回傳 10
答案 = 10

縮排就是堆疊的高度。注意四個「進入」全部印完，才開始印「離開」——因為 n + sumTo(n - 1) 這一行必須等右邊算完才能相加，所以 sumTo(4) 的框會一直卡在堆疊上等。這就是為什麼遞迴的空間複雜度是 O(深度)。

›按「開始」，看堆疊框怎麼疊上去、又怎麼收回來。
速度 堆疊上的框：0
程式碼 CODE
int sumTo(int n) { if (n <= 1) { return n; } return n + sumTo(n - 1); } cout << sumTo(4);
兩個必備零件 KEY

基底情形：小到不必再遞迴的情況，這裡是 n <= 1。
遞迴情形：把問題變小一號再交給自己。
少了基底情形，或問題沒有真的變小，堆疊就會一直疊上去。

堆疊真的會爆

呼叫堆疊的大小是有上限的，Linux 上預設通常是 8 MB。一個框就算只佔幾十個 byte，疊個幾十萬層也夠了。

同一支函式，換個輸入就當掉
#include <iostream> using namespace std; int sumTo(int n) { if (n <= 1) return n; return n + sumTo(n - 1); } int main() { cout << "sumTo(1000) = " << sumTo(1000) << endl; cout << "sumTo(1000000) = " << sumTo(1000000) << endl; // 堆疊撐不住 return 0; }
預期輸出
sumTo(1000)    = 500500

[執行結束碼 -11]

sumTo(1000) 好端端地算出 500500，sumTo(1000000) 直接 SIGSEGV（結束碼 −11）。程式沒有一個字寫錯，錯的是遞迴深度超過堆疊容量——這就是堆疊溢位（stack overflow）。Python 遇到同樣的狀況會丟 RecursionError 讓你知道；C++ 不管，直接砍。

💡 遞迴的框裡有什麼

每個框裝的是這一次呼叫專屬的參數與區域變數。所以 sumTo(4) 的 n 跟 sumTo(3) 的 n 是兩個不同的東西，互不干擾。這也回頭解釋了 PART 06：區域變數活在框裡，框一彈掉它就沒了，回傳它的位址當然拿不到東西。

🔗 這在資料結構課哪裡會用到 · 第 06、09 章

第 06 章整章都在練這件事：河內塔、碎形樹、找零錢、還有把堆疊框畫出來的 toStr()。第 09 章的樹走訪則是遞迴最自然的舞台——preorder(node) 先處理自己，再對左右子樹各叫自己一次，走訪一棵高度 h 的樹，堆疊上最多同時有 h 個框。第 05 章還會教你怎麼把遞迴改寫成用一個明確的 Stack 來做，那是同一件事的手動版。

Python ↔ C++ 對照

你在 Python 怎麼做C++ 的對應差在哪
函式定義寫在檔案任何地方都能用要先宣告或先定義C++ 由上而下編譯一遍，沒見過的名字就是錯

五條記得住的規則

① 函式要改動呼叫端的資料，參數列一定要有 &。
② 只讀的大物件用 const T&，別用傳值。
③ getter 一律寫 const，否則你的物件沒辦法用 const T& 傳。
④ 參數可能是「沒有」時才用指標，其餘場合優先用參考。
⑤ 永遠不要回傳區域變數的位址或參考。
