PART 01 · 繼承

is-a：子類別自動拿到父類別的一切 DRY

「有序串列是一種串列」—— 這種 is-a 關係就用繼承。子類別自動擁有父類別所有的成員，只需要寫「不一樣的那部分」。

繼承與覆寫
#include <iostream> #include <string> using namespace std; class Animal { // 父類別（基底類別） protected: string name; // protected：自己與子類別看得到，外人看不到 public: Animal(string n) { name = n; } void eat() { cout << name << " 在吃東西" << endl; } void speak() { cout << name << " 發出聲音" << endl; } }; class Dog : public Animal { // 子類別，繼承 Animal 的一切 public: Dog(string n) : Animal(n) { } // 成員初始化列表：先蓋好父類別的部分 void speak() { cout << name << " 汪汪叫" << endl; } // 覆寫 }; int main() { Dog d("小黑"); d.eat(); // 繼承來的，不用重寫 d.speak(); // 用自己覆寫的版本 return 0; }
預期輸出
小黑 在吃東西
小黑 汪汪叫

Dog 沒有自己寫 eat()，直接用繼承來的；但它寫了自己的 speak()，蓋掉父類別的版本，這叫覆寫。另外注意 protected：它讓子類別碰得到 name，但外人還是碰不到。

寫法意思
class Dog : public AnimalDog 繼承 Animal，父類別的 public 仍是 public
protected:自己與子類別看得到，外人看不到
Dog(string n) : Animal(n)成員初始化列表：先把父類別的部分蓋好
void speak() override明說「我是在覆寫」，名字打錯編譯器會抓出來

pythonds3/cppds/gates.hpp 有一整個繼承階層：LogicGate → BinaryGate / UnaryGate → AndGate / OrGate / NotGate。課程第 01 章就會看到它。

PART 02 · 建構順序

先蓋父類別，再蓋子類別

建立子類別物件時，C++ 一定先把父類別的部分建好，再執行子類別的建構式主體。父類別如果沒有無參數建構式，你就必須用成員初始化列表明說要呼叫哪一個。

class BinaryTree { public: string key; BinaryTree(string rootObj) { key = rootObj; } }; class AVLTree : public BinaryTree { private: int balanceFactor; public: AVLTree(string rootObj) : BinaryTree(rootObj) { // 冒號後面就是初始化列表 balanceFactor = 0; // 父類別蓋好之後才輪到這裡 } };
⚠️ 最常見的錯誤

子類別寫了建構式卻忘記呼叫父類別的版本，於是父類別的欄位根本沒被初始化。之後某個繼承來的函式讀到垃圾值，而錯誤爆出來的位置離真正的原因很遠。父類別有無參數建構式時編譯器會默默幫你呼叫它，沒有的話會直接編譯錯誤 —— 後者反而是好事。

PART 03 · virtual

沒有 virtual，就沒有多型 與 Python 差最多的一節

Python 的多型是免費的：方法名字對得上就能互換。C++ 不是。

沒有 virtual：用基底指標呼叫，跑的是父類別的版本
#include <iostream> using namespace std; class Base { public: void who() { cout << "我是 Base" << endl; } // 沒有 virtual }; class Derived : public Base { public: void who() { cout << "我是 Derived" << endl; } }; int main() { Derived d; Base *p = &d; // 用父類別的指標指向子類別物件 p->who(); // 沒有 virtual：編譯期就決定，跑父類別的版本 d.who(); // 直接用物件：跑子類別的版本 return 0; }
預期輸出
我是 Base
我是 Derived

同一個物件 d，用 Base* 指標呼叫跑父類別、直接用物件呼叫跑子類別。因為沒有 virtual 時，編譯器在編譯期就照指標的型別決定要呼叫誰。

加上 virtual：執行期才決定，跑的是子類別的版本
#include <iostream> using namespace std; class Base { public: virtual void who() { cout << "我是 Base" << endl; } // 加上 virtual }; class Derived : public Base { public: void who() override { cout << "我是 Derived" << endl; } }; int main() { Derived d; Base *p = &d; p->who(); // 有 virtual：執行期查表，跑子類別的版本 return 0; }
預期輸出
我是 Derived

加了 virtual，C++ 會在執行期查一張表（虛擬函式表）找出物件真正的型別。這就是動態繫結，也是多型能運作的機制。子類別那邊建議加 override：名字或簽章打錯時編譯器會直接抓出來。

💡 兩個條件缺一不可

① 方法要標 virtual；② 要透過基底類別的指標或參考呼叫。
少了第二點，多型也不會發生 —— 而且如果你是用值傳遞子類別物件給一個吃父類別的函式，子類別多出來的部分會被直接切掉（叫做 object slicing）。所以多型場合一律傳指標或參考。

PART 04 · 純虛擬

= 0：規定「所有子類別都必須實作」

有時候父類別只想定義「有這個操作」，但沒辦法給出實作 —— 邏輯閘一定會運算，但「怎麼運算」要看是 AND 還是 OR。這時用純虛擬函式。

class LogicGate { public: virtual int performGateLogic() = 0; // 純虛擬：沒有實作 virtual void setNextPin(Connector* source) = 0; }; class AndGate : public BinaryGate { public: int performGateLogic() { // 子類別必須實作，否則也是抽象類別 return (getPinA() == 1 && getPinB() == 1) ? 1 : 0; } };
✅ 有純虛擬函式的類別叫抽象類別

它不能被實例化（LogicGate g; 會編譯錯誤），只能拿來當基底。這正是它的用途：定義一份所有子類別都得遵守的契約。上面這段是 pythonds3/cppds/gates.hpp 的原文。

PART 05 · 相等

operator==：定義「什麼叫一樣」

預設情況下，兩個自訂型別的物件根本不能用 == 比較（編譯錯誤）。要讓「內容一樣就算相等」，得自己寫。

class Fraction { public: bool operator==(Fraction& otherFrac) { int firstnum = num * otherFrac.den; // 交叉相乘，避免浮點數誤差 int secondnum = otherFrac.num * den; return firstnum == secondnum; } private: int num, den; };
💡 這段來自 pythonds3/cppds/fraction.hpp

注意它不是直接比 num 與 den：1/2 與 2/4 應該相等，所以要交叉相乘。這提醒了一件事 —— 「什麼叫一樣」是你的設計決定，不是語言幫你決定的。

PART 06 · 排序的關鍵

operator<：定義了「小於」，整個 STL 就能用你的物件

沒有 operator< 的下場
#include <iostream> #include <vector> #include <algorithm> #include <string> using namespace std; class Task { public: string name; int priority; Task(string n, int p) { name = n; priority = p; } }; int main() { vector<Task> v = { Task("備份", 5), Task("修 bug", 1) }; sort(v.begin(), v.end()); // 沒有 operator<，編譯器不知道怎麼比 return 0; }
預期輸出
[編譯失敗]
predefined_ops.h:45:23: error: no match for ‘operator<’ (operand types are ‘Task’ and ‘Task’)
predefined_ops.h:98:22: error: no match for ‘operator<’ (operand types are ‘Task’ and ‘Task’)

sort、min_element、priority_queue、set、以及課程第 07 章的六種排序 —— 全部只做一件事：兩兩比大小。你沒告訴 C++ 怎麼比，它連編譯都不讓你過。訊息 no match for 'operator<' 值得認得。

補上一個成員函式，四個地方同時能用
#include <iostream> #include <vector> #include <algorithm> #include <queue> #include <string> using namespace std; class Task { public: string name; int priority; Task(string n, int p) { name = n; priority = p; } bool operator<(const Task& other) const { // 定義「什麼叫比較小」 return priority < other.priority; } }; int main() { vector<Task> v = { Task("備份", 5), Task("修 bug", 1), Task("回信", 3) }; sort(v.begin(), v.end()); cout << "sort -> "; for (const Task& t : v) cout << t.name << "(" << t.priority << ") "; cout << endl; cout << "min -> " << min_element(v.begin(), v.end())->name << endl; priority_queue<Task> pq(v.begin(), v.end()); // 同一份物件直接丟進優先佇列 cout << "pq 頂 -> " << pq.top().name << "（預設是最大優先）" << endl; return 0; }
預期輸出
sort  -> 修 bug(1) 回信(3) 備份(5) 
min   -> 修 bug
pq 頂 -> 備份（預設是最大優先）

只寫了一個 operator<，sort、min_element、priority_queue 就全部能用了。注意 priority_queue 預設是最大優先，所以頂端是 priority 最大的那個。

下面這個逐步器把 sort() 拆開來看：每一次比較都是一次 operator< 呼叫。

排序前
備份(5)
修bug(1)
回信(3)
寫報告(2)
›sort 內部靠 operator< 兩兩比較 —— 這組插入排序總共呼叫了 6 次。
排序後
修bug(1)
寫報告(2)

插入排序 CODE
void insertionSort(vector<Task>& a) { for (int i = 1; i < a.size(); i++) { Task cur = a[i]; int j = i - 1; while (j >= 0 && cur < a[j]) { a[j + 1] = a[j]; j--; } a[j + 1] = cur; } }
關鍵那一行 WHY

cur < a[j] 就是 cur.operator<(a[j])。你沒定義它，這一行就編不過；你定義錯了，整個排序會悄悄排錯 —— 而且不會有任何錯誤訊息。

🔗 這在資料結構課哪裡會用到 · 第 07、09 章

第 07 章六種排序法的核心都是這一次比較；第 09 章的二元堆積（pythonds3/cppds/binaryheap.hpp）在 percUp 與 percDown 時每一步都在比大小。想把自訂的工作物件丟進優先佇列？先給它 operator<。

PART 07 · 分岔

有序容器要 operator<，無序容器要雜湊

這是 C++ 與 Python 一個結構性的差別。Python 的 dict 與 set 一律要求鍵可雜湊；C++ 分成兩套：

容器底層你的型別要提供查詢成本
set / map紅黑樹operator<$O(\log n)$，走訪有序
unordered_set / unordered_map雜湊表operator== ＋ std::hash 特化平均 $O(1)$，走訪是桶序
// 想把自訂型別當 unordered_map 的鍵，要特化 std::hash namespace std { template <> struct hash<Point> { size_t operator()(const Point& p) const { return hash<int>()(p.x) ^ (hash<int>()(p.y) << 1); } }; }
💡 鐵則跟 Python 一樣

a == b 為真時，hash(a) 必須等於 hash(b)。所以雜湊值要從「決定相等的那些欄位」算出來。這條規則違反了，同一個鍵會查不到、或在容器裡出現兩份。

🔗 這在資料結構課哪裡會用到 · 第 07、08 章

第 07 章整章在解釋雜湊表怎麼做到 $O(1)$ —— 那正是 unordered_map 的底層。第 08 章的 pythonds3/cppds/graph.hpp 則用 map 存頂點，走訪出來是照鍵排序的。

PART 09 · 設計抉擇

組合 vs 繼承：Deque 該繼承 vector 嗎？

做一個雙端佇列，最省事的寫法看起來是直接繼承 vector。試試看會怎樣：

繼承 vector 的陷阱
#include <iostream> #include <vector> #include <algorithm> using namespace std; class BadDeque : public vector<int> { // 繼承 vector：看似省事 public: void addFront(int x) { insert(begin(), x); } }; int main() { BadDeque d; d.addFront(1); d.addFront(2); cout << "內容: "; for (int x : d) cout << x << " "; cout << endl; // 但使用者也拿到了這些——全都違反雙端佇列的契約 sort(d.begin(), d.end()); d.insert(d.begin() + 1, 99); cout << "被 sort 跟 insert 亂搞之後: "; for (int x : d) cout << x << " "; cout << endl; return 0; }
預期輸出
內容: 2 1 
被 sort 跟 insert 亂搞之後: 1 99 2

問題不在它不能動，而在它能做的事太多了：使用者可以對你的 Deque 呼叫 sort()、insert(begin()+1, x) ——這些操作全都違反雙端佇列「只能從兩端進出」的契約，而你完全擋不住。

繼承（is-a）組合（has-a）
寫法class Deque : public vector<T>vector<T> items;
對外露出什麼父類別所有方法，擋不掉只有你自己寫的
能換底層實作嗎不能，已經綁死能，改內部一行就好
什麼時候該用子類別真的是一種父類別，而且父類別每個方法對它都合理絕大多數的資料結構
🎯 判斷法則

問自己一句：「父類別的每一個方法，用在子類別身上都說得通嗎？」只要有一個說不通（例如對 Deque 呼叫 sort()），就不要繼承，改用組合。
課程標頭的 Stack、Queue、Deque 全部採用組合 —— 現在你知道為什麼了。

⚠️ 課程沒教、但你遲早會撞到：Rule of Three

類別裡有 new 出來的成員時，光有建構式是不夠的：還需要解構式釋放它、以及拷貝建構式與 operator=，否則複製物件時兩份會共用同一塊記憶體，一個 delete 掉另一個就變成懸空指標。這三個合稱 Rule of Three。
本課的 pythonds3/cppds/ 一律沒做（全課只有一個解構式）—— 教材程式跑完就結束，不會出事。但你要知道這是取捨。真的要寫產品程式時，回頭查 Rule of Three／Five 與 std::unique_ptr。

本課標頭檔省掉的常用寫法一覽

都是「平常會這樣寫、課程標頭為了短而省掉」的東西。教材程式跑完就結束所以沒事；自己寫作業或專案時把它們補回來。

  • 標頭裡寫 using namespace std; → 標頭一律用 std::，只在 .cpp 裡 using（P1）
  • new 出來的成員沒有解構式、拷貝建構式、operator= → Rule of Three（上面那一框）（本頁）
  • pop()／peek() 對空容器不檢查 → 先問 isEmpty()，或丟例外（P7）
  • 讀取用的成員函式沒加 const → 不改成員就加 const（P8）
  • string 參數傳值 → const string&（P3）
  • size() 回 int → size_t，或至少不要跟 unsigned 混算（P5）
  • NULL → nullptr（P4）
  • BinaryTree、Graph 的資料成員直接 public → private ＋ getter／setter（P8）
PART 10 · template

一份程式碼，所有型別都能用

C++ 沒有 Python 那種「什麼型別都收」的彈性，但它有更強的東西：編譯期產生程式碼。

同一個 Box，兩種型別各產生一份
#include <iostream> #include <string> using namespace std; template <typename T> // T 是型別參數 class Box { private: T item; public: Box(T v) { item = v; } T get() const { return item; } }; int main() { Box<int> a(42); Box<string> b("hello"); cout << a.get() << " / " << b.get() << endl; // 編譯期各自產生一份程式碼，是兩個不同的型別 cout << "sizeof(Box<int>) = " << sizeof(Box<int>) << endl; cout << "sizeof(Box<string>) = " << sizeof(Box<string>) << endl; return 0; }
預期輸出
42 / hello
sizeof(Box<int>)    = 4
sizeof(Box<string>) = 32

Box<int> 與 Box<string> 是兩個不同的型別，編譯器各產生一份機器碼 —— 所以 sizeof 也不一樣。這叫實例化，發生在編譯期，執行期沒有任何額外成本。

💡 為什麼 pythonds3/cppds/ 底下全是 .hpp、沒有半個 .cpp

因為編譯器要看到完整的實作才能替 Stack<int> 產生程式碼。一般類別可以宣告放 .hpp、實作放 .cpp，template 不行。這解釋了 P8 PART 09 留下的那個問題。

⚠️ 在課程 notebook 裡，template 類別的 cell 一定要自帶 main()

沒有 main( 的 cell 會被 kernel 自動包進一個 main()，於是你的 template 類別變成區域類別 —— 而區域類別不能是 template，直接編譯失敗。詳見 00B 的踩坑 FAQ。

🔗 這在資料結構課哪裡會用到 · 第 04、05 章

Node<T> 從第 04 章第一行就出現，Stack<T>、Queue<T>、Deque<T> 是第 05 章的主角。不懂 template，連 pythonds3/cppds/ 的第一個檔案都讀不下去。（順帶一提：第 09 章的 BinaryTree 反而不是 template，它的鍵固定是 string。）
