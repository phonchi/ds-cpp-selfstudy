一個資料結構，就是一個類別

這門課的形狀就是這樣：資料結構 = 資料（要存什麼）＋ 操作（能對它做什麼），而 C++ 用來把這兩件事包在一起的工具就是 class。

PART 01 · 類別與物件

藍圖與成品 四個必背詞

類別是藍圖，物件是照著藍圖蓋出來的東西。藍圖只有一份，蓋出來的房子可以有很多間，每一間的門牌、住戶各自不同。

最小可用的 Node 類別（第 04 章鏈結串列的主角）
#include <iostream> using namespace std; class Node { // 藍圖 private: int data; // 成員變數：每個物件各有一份 Node *next; public: Node(int initdata) { // 建構式：建立物件時自動執行 data = initdata; next = NULL; } int getData() const { return data; } // const：我保證不改動任何成員 Node *getNext() const { return next; } void setNext(Node *n) { next = n; } }; int main() { Node n(93); // 一個物件（實例） cout << "n.getData() = " << n.getData() << endl; cout << "n.getNext() = " << n.getNext() << " <- NULL 印出來是 0" << endl; cout << "sizeof(Node) = " << sizeof(Node) << " bytes（一個 int + 一個指標）" << endl; return 0; }
預期輸出
n.getData() = 93
n.getNext() = 0   <- NULL 印出來是 0
sizeof(Node) = 16 bytes（一個 int + 一個指標）

三個觀察：① Node n(93); 建立一個物件，會自動去跑建構式。② next 一開始是 NULL，代表後面還沒接東西。③ sizeof(Node) 是 16 bytes —— 一個 int（4）加一個指標（8），再加上對齊補的 4。物件的大小是它所有成員加起來。

🔗 這在資料結構課哪裡會用到 · 第 04 章

Node 是鏈結串列的基本磚塊。整章都在做同一件事：new 一個 Node、改它的 next、沿著 next 走訪。看不懂 class，那一章就只能死背。

PART 02 · 建構式

建構式與 this

建構式：跟類別同名、沒有回傳型別

你寫 Node n(93); 的時候，C++ 先配置一塊記憶體，然後自動呼叫 Node(93) 把它填好。所以建構式裡做的事就是「這個物件一出生要帶著哪些資料」。

它有兩個外觀特徵：名字跟類別一模一樣，而且沒有回傳型別（連 void 都不寫）。

this：指向「是誰呼叫我」的指標

成員函式被呼叫時，C++ 會偷偷傳一個 this 進來，它是指向呼叫者本人的指標。平常你不用寫它 —— 直接寫 data 就等於 this->data。

class Node { private: int data; public: Node(int data) { this->data = data; // 左邊是成員，右邊是參數，同名時要用 this 分辨 } int getData() const { return data; // 等同 this->data，沒有同名問題就不用寫 } };
💡 跟 Python 的 self 差在哪

Python 的 self 是明寫在參數列裡的第一個參數；C++ 的 this 是編譯器偷偷傳進來的指標，不寫在參數列裡，而且因為是指標所以用 -> 存取。兩者角色一樣，但 C++ 這邊你平常根本不會看到它。

PART 03 · 存取控制

public 與 private：C++ 靠編譯器擋，不靠約定

private 成員從外面碰不到（真的編不過）
#include <iostream> using namespace std; class Node { private: int data; public: Node(int d) { data = d; } int getData() const { return data; } }; int main() { Node n(93); cout << n.getData() << endl; // 可以：透過公開介面 cout << n.data << endl; // 不行：data 是 private return 0; }
預期輸出
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:15:15: error: ‘int Node::data’ is private within this context
   15 |     cout << n.data << endl;        // 不行：data 是 private

這是 C++ 與 Python 一個很實際的差別：Python 的底線只是約定，你硬要碰還是碰得到；C++ 的 private 是編譯器強制的，碰了就編不過。訊息 is private within this context 值得認得。

區段誰能存取通常放什麼
public:任何人建構式、對外的操作（介面）
private:只有這個類別自己的成員函式資料成員、內部輔助函式
protected:自己 ＋ 子類別要給子類別用的東西（見 P9）
⚠️ class 預設是 private

沒寫存取區段的話，class 裡的成員預設是 private（struct 則預設 public，這是兩者唯一的差別）。所以建構式忘了放在 public: 底下，就會出現「明明有建構式卻說不能建立物件」的錯誤。

PART 04 · 封裝

課程自己就有兩套寫法 —— 而且兩套都對

這一節值得慢慢看，因為它是真實世界的取捨，不是教科書的標準答案。

同一門課、同一套 dscpp/，兩個類別的寫法完全相反：

dscpp/linked_list.hpp 全包起來
template <typename T> class Node { private: T data; Node<T> *next; public: T getData() const { return data; } Node<T> *getNext() const { return next; } void setData(T newData) { data = newData; } void setNext(Node<T> *n) { next = n; } };
dscpp/binarytree.hpp 全公開
class BinaryTree { public: string key; BinaryTree* leftChild; BinaryTree* rightChild; BinaryTree(string rootObj) { key = rootObj; leftChild = NULL; rightChild = NULL; } };
💡 為什麼可以不一樣

Node 是被 UnorderedList 包起來的內部零件，使用者根本不該直接碰它，所以把資料藏起來、只留 getter/setter 是合理的。BinaryTree 則是直接當公開結構用，走訪演算法要一直讀 leftChild／rightChild，全部包起來只會讓程式碼變長。
封裝是手段不是目的：問「這個成員被外面亂改會出事嗎」，會就藏起來，不會就算了。

隨堂 1 · 該不該包起來

你要寫一個 Stack，內部用 vector 存元素。這個 vector 該放 public 還是 private？

(A) private，只留 push／pop／peek 對外
(B) public，這樣比較方便
(C) 都可以，沒有差別
🔗 這在資料結構課哪裡會用到 · 第 04、09 章

第 04 章的 Node 全部走 getter/setter；第 09 章的 BinaryTree 直接公開成員。讀原始碼時看到兩種風格不要以為自己看錯，那是刻意的取捨。

PART 05 · const 成員函式

T getData() const：括號後面那個 const 在承諾什麼

寫在參數列後面的 const 是對編譯器的承諾：這個函式不會改動任何成員變數。改了就編不過。

class Node { private: int data; public: int getData() const { return data; } // 只讀，加 const void setData(int d) { data = d; } // 要改，不能加 const }; void printIt(const Node& n) { // 收到的是 const 參考 cout << n.getData(); // 可以：getData 保證不改 // n.setData(5); // 不行：setData 沒有 const 承諾 }
✅ 為什麼值得養成習慣

因為 const 物件只能呼叫 const 成員函式。傳大物件時用 const T& 是標準做法（不複製又不讓改，見 P3），而那時候所有的讀取函式都必須是 const 的，否則呼叫不了。dscpp/linked_list.hpp 的每個 getter 都有加。

PART 06 · 多載

同名不同參數：Fraction 的三種建立方式

C++ 允許同一個名字有多個版本，只要參數列不同就好。編譯器會依你傳的引數挑一個。這在 Python 只能靠預設參數繞，C++ 直接支援。

class Fraction { public: Fraction(int top, int bottom) { num = top; den = bottom; } // 兩個引數 Fraction(int top) { num = top; den = 1; } // 整數：top/1 Fraction() { num = 1; den = 1; } // 沒給：1/1 private: int num, den; };
三個建構式各自被挑中（引用課程的 dscpp/fraction.hpp 實跑）
#include "fraction.hpp" #include <iostream> using namespace std; int main() { Fraction a(3, 4); // 兩個引數 -> Fraction(int, int) Fraction b(5); // 一個引數 -> Fraction(int)，也就是 5/1 Fraction c; // 沒有引數 -> Fraction()，也就是 1/1 cout << "a = " << a << endl; cout << "b = " << b << endl; cout << "c = " << c << endl; cout << "a + b = " << (a + b) << endl; return 0; }
預期輸出
a = 3/4
b = 5/1
c = 1/1
a + b = 23/4

Fraction b(5) 挑中單參數版本、Fraction c 挑中無參數版本。注意最後一行 a + b 也能用 —— 那是 operator+ 的功勞，屬於 P9 的運算子多載。

編譯器怎麼挑：一個一個比參數列

「編譯器會依你傳的引數挑一個」這句話講得太快了。它實際上做三件事：先把同名的建構式全抓出來當候選，再逐一比對參數列，個數或型別對不上就淘汰，最後從活下來的裡面挑一個。下面的逐步器把這個過程放慢給你看。

候選名單裡多了一個你沒寫的 Fraction(const Fraction &other) —— 那是複製建構式。你沒寫的話編譯器會自動幫你生一個，所以它永遠在名單上，也因此永遠參與比對。

呼叫端：（按下面任一顆按鈕開始）
 
#1 Fraction() // 候選 A：不收引數 #2 Fraction(int top) // 候選 B：1 個 int #3 Fraction(int top, int bottom) // 候選 C：2 個 int #4 Fraction(const Fraction &other) // 候選 D：複製建構式（自動生成）
›選一種呼叫寫法開始。四個候選的名字一模一樣，決勝負的只有括號裡那一段。
速度
看簽名，不看名字 KEY

能區分多載的只有參數列：型別、個數、順序。名字全部相同，回傳型別也不算在內 —— 兩個函式只差回傳型別的話，那不是多載，是重複定義，直接編不過。

複製建構式什麼時候被呼叫？用同型別的物件初始化另一個物件時（Fraction g = f;、Fraction g(f);）、物件以傳值方式當引數傳進函式時、以及函式以傳值回傳物件時。這也是 P3 說「大物件請用 const T&」的理由 —— 傳值會多跑一次複製。

預設參數 vs 多載 取捨

前三個候選也可以用一個帶預設值的建構式取代：Fraction(int top = 1, int bottom = 1);。少寫兩份本體、少兩份要一起維護的程式碼，這是它的好處。

代價是兩者不能並存：留著預設參數版又留著 Fraction()，寫 Fraction c; 時兩個都可行、也分不出高下，編譯器會報 call of overloaded … is ambiguous。判準很簡單：各版本本體一樣、只差沒填的值就用預設參數；本體真的要做不同的事（例如收 int 跟收 Fraction）就寫成多載。

⚠️ Fraction c; 不要寫成 Fraction c();

加了括號，C++ 會把它當成「宣告一個回傳 Fraction 的函式 c」，而不是建立物件。這個坑有個名字叫 most vexing parse，錯誤訊息通常離現場很遠。要建立物件就不要加空括號。

PART 07 · 印得出來

operator<< 與 friend：讓你的物件說人話

沒有定義 operator<< 的下場
#include <iostream> using namespace std; class Point { private: int x, y; public: Point(int a, int b) { x = a; y = b; } }; int main() { Point p(3, 4); cout << p << endl; // 沒有定義 operator<<，編譯器不知道怎麼印 return 0; }
預期輸出
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:13:10: error: no match for ‘operator<<’ (operand types are ‘std::ostream’ {aka ‘std::basic_ostream<char>’} and ‘Point’)
   13 |     cout << p << endl;      // 沒有定義 operator<<，編譯器不知道怎麼印

cout << p 編不過。C++ 不像 Python 有預設的字串表示 —— 沒教過它怎麼印你的類別，它就直接拒絕。訊息 no match for 'operator<<' 第一次看到會嚇一跳，其實意思很單純：找不到能印這個型別的版本。

解法是自己定義一個。因為 cout << f 的左邊是 ostream 而不是你的物件，這個函式不能寫成成員函式，只能寫在類別外面 —— 但它又需要讀 private 的成員，所以要用 friend 開一道門：

class Fraction { public: // …建構式… friend ostream& operator<<(ostream& stream, const Fraction& fraction); private: int num, den; }; ostream& operator<<(ostream& stream, const Fraction& fraction) { stream << fraction.num << "/" << fraction.den; // 靠 friend 才碰得到 private return stream; // 回傳 stream 才能串接 << << << }
💡 兩個容易漏的細節

① 一定要 return stream;，否則 cout << a << b 這種串接就斷了。
② 參數用 const Fraction&：參考避免複製、const 保證不改。這是傳物件的標準寫法。

🔗 這在資料結構課哪裡會用到 · 第 01、04、09 章

第 01 章的 Fraction 就是這個寫法的出處。到了第 04、09 章，沒有 operator<< 你就沒辦法把一條串列或一棵樹印出來看，debug 等於瞎子摸象。

PART 08 · 組合

用現成的東西蓋新的東西 has-a

要做一個 Stack，不需要從零管理記憶體 —— 直接持有一個 vector 就好。這種「A 擁有一個 B」的關係叫組合，是資料結構課裡最常見的蓋法。

完整的 Stack：這一份會在第 05 章反覆出現
#include <iostream> #include <vector> using namespace std; template <typename T> class Stack { private: vector<T> items; // 組合：Stack「擁有」一個 vector public: bool isEmpty() { return items.empty(); } void push(T item) { items.push_back(item); } T pop() { T top = items.back(); items.pop_back(); return top; } T peek() { return items.back(); } int size() { return items.size(); } void display() { for (T x : items) cout << x << " "; cout << endl; } }; int main() { Stack<char> s; for (char c : {'a', 'b', 'c'}) s.push(c); cout << "內容（底到頂）: "; s.display(); cout << "peek = " << s.peek() << "，size = " << s.size() << endl; cout << "pop = " << s.pop() << "，剩下 "; s.display(); return 0; }
預期輸出
內容（底到頂）: a b c 
peek = c，size = 3
pop  = c，剩下 a b

重點在 vector<T> items; 這一行：Stack 不是一個 vector，Stack 有一個 vector。而且它是 private 的 —— 外面只看得到 push/pop/peek，看不到裡面是什麼。所以你哪天要把它換成鏈結串列，外面一行都不用改。

隨堂 2 · 選對那一端

上面的 Stack 把 vector 的尾端當成堆疊頂端。課程的 dscpp/stack.hpp 另外附了一個 Stack2，改成用前端。會發生什麼？

(A) 完全一樣，只是寫法不同
(B) 行為一樣正確，但每個操作從 $O(1)$ 變成 $O(n)$
(C) 會出錯，vector 不支援從前端刪除
🔗 這在資料結構課哪裡會用到 · 第 05 章

Stack、Queue、Deque 三個 ADT 在 dscpp 裡全部用同一招：持有一個 vector，只是選擇從哪一端操作。選錯端就是 $O(n)$。

PART 09 · 標頭檔

.hpp 與 include guard：課程的 dscpp/ 怎麼組起來的

類別通常放在 .hpp 裡，讓別的檔案 #include 進來用。但 #include 就是把整個檔案的內容原地貼過來，同一個檔案被貼兩次，類別就重複定義了。

// dscpp/stack.hpp #ifndef DSCPP_STACK_HPP // 如果還沒定義過這個名字 #define DSCPP_STACK_HPP // 就定義它，然後往下走 #include <iostream> #include <vector> using namespace std; template <typename T> class Stack { /* … */ }; #endif // 第二次被 include 時，整段直接跳過
💡 為什麼 template 類別整份都寫在 .hpp 裡

一般類別可以把宣告放 .hpp、實作放 .cpp；但 template 不行 —— 編譯器要看到完整的實作才能替 Stack<int> 產生程式碼。所以 dscpp/ 底下全是 .hpp，沒有半個 .cpp。細節見 P9 的 template 一節。

class 類別名稱 { private: 型別 成員變數; // 預設就是 private public: 類別名稱(參數) { … } // 建構式：同名、沒有回傳型別 類別名稱() { … } // 多載：參數列不同就是不同版本 回傳型別 成員函式(參數) const { // const = 我保證不改成員 return 成員變數; } friend ostream& operator<<(ostream&, const 類別名稱&); // 開門給外部函式 }; 類別名稱 物件(引數); // 建在堆疊上，離開範圍自動消失 類別名稱 *p = new 類別名稱(引數); // 建在堆積上，要自己 delete

Q1.以下程式印出什麼？
class Node {
    private:
        int data;
        Node *next;
    public:
        Node(int d) { data = d; next = NULL; }
        int getData() const { return data; }
};

int main() {
    Node n(93);
    cout << n.getData();
}
Q2.以下程式為什麼編不過？
class Node {
    private:
        int data;
    public:
        Node(int d) { data = d; }
};

int main() {
    Node n(93);
    cout << n.data;
}
