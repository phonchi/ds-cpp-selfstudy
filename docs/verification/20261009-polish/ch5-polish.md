# 第 5 章（`linear_structures.html`）潤稿摘要

這次找到並修改了 7 處。

第 5 章的 gen 區正文本來就寫得平實，沒有空泛導引句、罐頭結論或中國用語，中文句子裡的半形括號都是運算式。AI 味主要集中在 gen 區外的 h2 標題：用引號包裝的比喻（「排隊學」「盤子塔」）、行銷式用語（「殺手級應用」「經典考點」）與擬人化（「公平隊伍」）。h2 不會被產生器覆蓋，直接改在頁面上；正文的一處改在 `tools/enrich/content/linear_depth.py`。圖說（`linear_figures.py`）、字卡（`data/flashcards_zh/ch5.json`）、使用方式框與目錄檢查後不需要修改。

1. **P00 h2**
   - 原句：「線性結構：資料的「排隊學」」
   - 為什麼要改：引號包裝的比喻，讀者讀完仍不知道這節講什麼。
   - 改成了什麼：「線性結構：從哪一端進、從哪一端出」（正是本節用來區分三種結構的依據）

2. **P01 h2**
   - 原句：「Stack：後進先出的「盤子塔」」
   - 為什麼要改：「盤子塔」是額外的比喻包裝；正文已用餐盤與書本舉例，標題不需要再加一層。
   - 改成了什麼：「Stack：後進先出」

3. **P02 h2**
   - 原句：「括號配對：stack 的第一個殺手級應用」
   - 為什麼要改：「殺手級應用」是誇大的行銷用語。
   - 改成了什麼：「括號配對：用 stack 檢查括號是否平衡」

4. **P04 h2**
   - 原句：「中序、前序、後序：把括號「編譯」掉」
   - 為什麼要改：引號包裝的比喻，而且「編譯」容易和真正的編譯混淆；本節內容是轉換與求值。
   - 改成了什麼：「中序、前序、後序：運算式的轉換與求值」

5. **P05 h2**
   - 原句：「Queue：先進先出的公平隊伍」
   - 為什麼要改：「公平隊伍」是修飾性擬人說法，沒有增加資訊。
   - 改成了什麼：「Queue：先進先出」（和 Stack 的標題對稱）

6. **EX h2**
   - 原句：「動手驗證：三個經典考點」
   - 為什麼要改：「經典考點」是誇大用語，而且本節實際列的是講義的三個程式練習。
   - 改成了什麼：「動手驗證：三個程式練習」

7. **P02 括號平衡的說明**（`linear_depth.py`）
   - 原句：「能分辨括號平衡與否，是辨認許多程式語言結構的重要一步。」
   - 為什麼要改：「是……的重要一步」是拔高句型，主詞也繞了一圈。
   - 改成了什麼：「要辨認許多程式語言的結構，得先能分辨括號是否平衡。」
