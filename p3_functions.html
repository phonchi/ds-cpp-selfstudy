PART 01

先看一項工作如何變成函式

想像你要在不同地方計算包裹費用：預估畫面要算一次，確認訂單時又要算一次。直接複製算式雖然能工作，但調整規則時容易只改到其中一處。函式把一項工作命名，讓程式透過名稱重複使用同一份規則。這裡先學如何定義、呼叫和取得結果，之後才比較不同的參數傳遞方式。

先把函式想成有清楚邊界的一段程式：呼叫端交出輸入，函式用自己的參數與區域變數完成工作，再把結果交回。輸入、輸出與螢幕顯示是不同的事；函式可以回傳一個數字而完全不印文字，也可以只顯示提醒而不回傳計算結果。

回傳型別 函式名稱(參數列) {
    函式本體
}
部分如何閱讀
int deliveryFee(int boxes)回傳一個 int；函式名是 deliveryFee；接收一個名叫 boxes 的 int。
{ return boxes * 12; }大括號包住函式本體；return 先計算右邊，再結束這一次呼叫。
deliveryFee(3)這是呼叫，括號內是交給函式的引數；不是再次定義函式。
#include <iostream>

int deliveryFee(int boxes) {
    return boxes * 12;
}

int main() {
    int fee = deliveryFee(3);
    std::cout << "運費 = " << fee << '\n';
}
預期輸出
運費 = 36

程式從 main 開始，不會因為 deliveryFee 寫在前面就先執行它。遇到 deliveryFee(3) 才進入函式，此時 boxes 取得 3；return 算出 36，控制流程回到原本的呼叫位置，36 才被用來初始化 fee。下一行 cout 是 main 的工作。

動手練習

把呼叫改成 deliveryFee(5)，哪些位置會變？需要修改函式定義嗎？

看解答與理由

只需改引數。這次 boxes 是 5，回傳 60；函式的規則仍是乘以 12，因此定義不變。

PART 02

引數、參數與回傳值：把資料流追清楚

引數是呼叫時提供的值，參數是函式用來接收它的名稱。兩者不必同名：呼叫端可以叫 quantity，函式內叫 boxes；連接兩者的是參數的位置與型別，不是名稱相同。引數也可以是運算式，例如 deliveryFee(quantity + 1)，先算出引數的值才進入函式。

有兩個參數時，依位置配對。deliveryFee(3, 12) 的第一個值交給 boxes，第二個值交給 rate。函式的參數列用逗號分開每個完整宣告，不能把 int boxes, rate 當成兩個合法參數宣告。這和一般變數宣告的簡寫不同。

#include <iostream>
int deliveryFee(int boxes, int rate) {
    int fee = boxes * rate;
    return fee;
}
int main() {
    int quantity = 3;
    int result = deliveryFee(quantity + 1, 10);
    std::cout << quantity << " " << result << '\n';
}
預期輸出
3 40

quantity + 1 得到 4，但沒有把 quantity 指派成 4，所以呼叫後 quantity 仍是 3。函式內 fee 為 40，return fee 交回的是數值。函式結束後區域變數 fee 不再存在，但已交出的 int 結果仍可存進 result。

互動：控制流程在哪裡，資料就流到哪裡

逐步觀察呼叫端與函式的區域變數。初始畫面尚未執行第一行。

int quantity = 3;
int result = deliveryFee(quantity + 1, 10);
// deliveryFee: fee = boxes * rate;
// deliveryFee: return fee;
std::cout << quantity << " " << result;


動手練習
把呼叫改為 deliveryFee(10, quantity + 1)，結果會一樣嗎？
看解答與理由
這個乘法例子仍回傳 40，但 boxes 與 rate 的意義已對調。一般函式不保證參數可以交換，因此理解每個位置比只看結果重要。





PART 03
return 結束呼叫，void 表示沒有回傳值


有回傳型別的函式，應讓每一條正常結束的路徑交出符合型別的值。return 不是單純把答案記在某個位置：執行到它，就立即結束這一次函式呼叫。放在 return 後面的敘述不會繼續執行。多個分支可以各有自己的 return。


#include <iostream>
int deliveryFee(int boxes) {
    if (boxes <= 0) {
        return 0;
    }
    return boxes * 12;
}
void showReminder() {
    std::cout << "請確認收件地址\n";
}
int main() {
    std::cout << deliveryFee(0) << " " << deliveryFee(2) << '\n';
    showReminder();
}
預期輸出
0 24
請確認收件地址



showReminder 的回傳型別是 void，意思是呼叫不產生可用來計算的值。呼叫仍要寫 showReminder() 的小括號，但不能寫 int x = showReminder()。void 函式可以用不帶值的 return; 提早離開，也可以自然走到結尾。


要特別分清 cout 與 return：cout 把文字送到輸出串流，return 把結果送回程式中的呼叫位置。只印出答案的函式，不能直接拿顯示內容去做後續運算。初學時可以把「計算結果」與「顯示結果」分成兩步，較容易測試與重複使用。


動手練習
一個 int 函式只在 if 成立時 return，其他情況直接走到結尾，可以依賴得到 0 嗎？
看解答與理由
不可以。一般需要回傳值的函式若走到結尾卻沒有回傳，不能當作自動回傳 0；main 是特殊情況。應補上所有正常路徑的 return。





PART 04
作用域、生命週期與同名變數


作用域回答「這個名稱在哪裡能使用」，生命週期回答「這個物件什麼時候存在」。對本頁的一般區域 int 來說，進入宣告時建立，離開所在區塊時結束；函式參數也只屬於這一次呼叫。之後再次呼叫，會有新的一組參數與區域變數。


#include <iostream>
int doubleValue(int value) {
    int answer = value * 2;
    return answer;
}
int main() {
    int value = 7;
    {
        int value = 3;
        std::cout << doubleValue(value) << '\n';
    }
    std::cout << value << '\n';
}
預期輸出
6
7



內層區塊宣告了另一個 value，暫時遮蔽外層名稱；它沒有把外層的 7 改成 3。呼叫時傳入內層的 3，函式又用自己的參數 value 接收副本。三個名稱拼字相同，仍代表不同的物件。離開內層區塊後，再寫 value 指的是外層的 7。


區域變數不是函式替外界保管的永久儲存空間。若想在 main 使用 answer，應取得回傳值；直接在 main 寫 answer 會因名稱不可見而編譯失敗。另一方面，即使某個名稱還能取得舊位址，物件也可能早已結束生命；這是後面回傳參考與 P4 指標必須注意的界線。


動手練習
上述程式在內層區塊結束後加入 cout << answer，為何錯誤？
看解答與理由
answer 的作用域在 doubleValue 的函式本體，main 根本看不到它。應先用變數接住 doubleValue 的回傳值，再印那個呼叫端變數。





PART 05
先宣告呼叫方式，再提供定義


編譯器遇到函式呼叫時，需要已看過能描述該函式的宣告。最直接的排列是先放完整函式定義，再寫 main；如果希望把實作放在後方，可以先寫一行宣告。宣告的末尾是分號，定義則帶著函式本體。


#include <iostream>
int deliveryFee(int boxes, int rate);
int main() {
    std::cout << deliveryFee(3, 10) << '\n';
}
int deliveryFee(int boxes, int rate) {
    return boxes * rate;
}
預期輸出
30



宣告承諾函式名稱、參數型別與回傳型別；參數名稱主要幫助閱讀。定義必須符合這個承諾。若宣告說接收 int，定義卻寫成另一種參數型別，可能變成另一個多載版本，並沒有完成原本承諾的函式。


「沒有宣告就呼叫」通常在編譯時被抓到；「已有宣告，卻找不到相符定義」則可能到連結階段才失敗。P1 的編譯流程在這裡就有實際用途：先辨認失敗階段，才知道該查名稱可見性、型別，還是漏編譯的來源檔。P8 會再把這個做法用到標頭檔與多檔程式。


動手練習
上例保留宣告，但刪掉最後的定義，問題會出在哪裡？
看解答與理由
呼叫的語法與型別已有宣告可以檢查，但連結器找不到 deliveryFee(int, int) 的實作，所以不能產生完整可執行程式。



把宣告與定義放在一起比較


比較項目函式宣告（Declaration）函式定義（Definition）
語法外觀int deliveryFee(int n);int deliveryFee(int n) { return n * 12; }

PART 06
傳值：函式改的是副本


參數寫成 int points 時，這一次呼叫會建立自己的 points，初值來自引數。它不是呼叫端變數換了名字，也不是把原物件搬進函式。對 int 而言可以直接想成把數字複製到另一格。


#include <iostream>
void addBonus(int points) {
    points = points + 10;
    std::cout << "函式內 " << points << '\n';
}
int main() {
    int score = 20;
    addBonus(score);
    std::cout << "呼叫後 " << score << '\n';
}
預期輸出
函式內 30
呼叫後 20



points 的確被改成 30，所以函式內輸出 30；但 score 從未被指定新值，所以仍是 20。傳值很適合只需要一份輸入、希望函式內的暫時計算不影響呼叫端的情況。若希望得到新分數，也可以讓函式回傳結果，再由呼叫端明確寫 score = addBonus(score)。


這不是「函式裡的修改沒有作用」，而是要先問修改的是哪個物件。等到 P5 學容器，傳值可能涉及複製整份資料，成本就不只是一個整數；這時才更能理解唯讀參考的用途。


動手練習
如果函式內把 points 改成 0，score 會變嗎？要如何明確更新 score？
看解答與理由
仍不會變。可改成回傳新值的 int 函式，然後在 main 寫 score = 函式呼叫；下一節則會介紹直接修改原物件的參考參數。



什麼時候刻意選擇傳值


情境傳值是否合適原因與取捨
int、double、char、bool 等小型輸入通常合適取得自己的值，介面簡單。不要只用固定 byte 數或未量測的速度斷言誰一定比較快。
函式需要可以自行修改的快照合適副本正是所需效果；呼叫端物件保持原樣。
大型資料只需讀取先考慮 const 參考避免不必要的整份複製，並表達不透過參數修改。
函式需要保存一份獨立資料需依需求評估不能只因物件大就一律禁止傳值；若本來就需要自己的資料，複製或後續移動可能合理。


選參數形式先看資料要不要共享、修改與保存，再談成本。對自訂類別而言，複製的工作由型別自己定義；它可能很便宜，也可能涉及多個資源。P8 建立類別後會介紹複製建構，P9 再談資源所有權。





PART 07
參考先是別名，之後才是參數寫法


參考替既有物件取另一個名稱。先離開函式，單獨理解 int& alias = value：型別中的 & 表示參考，alias 必須在宣告時綁定到物件。它不是第三份數值，也不是指向不同地方的可改變門牌。


#include <iostream>
int main() {
    int value = 20;
    int other = 7;
    int& alias = value;
    alias = 25;
    std::cout << value << " " << alias << '\n';
    alias = other;
    std::cout << value << " " << other << '\n';
}
預期輸出
25 25
7 7



第二次 alias = other 是普通賦值：把 other 的 7 指派給 alias 所代表的 value。它不會讓 alias 改綁到 other。之後若 other 再改值，value 不會自動跟著變。讀參考程式時，把 alias 心中替換成它綁定的原名稱，通常就能看出結果。


把相同寫法放進參數列，就能讓這次呼叫的參數成為呼叫端物件的別名。呼叫端仍寫 addBonus(score)，不需要額外的符號；表示參考關係的是函式定義中的 int&。一般可修改的 int& 必須綁到適合的既有 int 物件，不能直接把整數常量 20 當成可修改的 score。


#include <iostream>
void addBonus(int& points) {
    points = points + 10;
}
int main() {
    int score = 20;
    addBonus(score);
    std::cout << score << '\n';
}
預期輸出
30



互動：同一格資料，兩個名稱
將每一步與上一節傳值對照：這裡沒有建立 points 的獨立整數副本。
int score = 20;
addBonus(score);
// int& points 綁定 score
// points = points + 10
// 回到 main


動手練習
int a = 4; int b = 9; int& r = a; r = b; b = 2; 最後 a、b、r 為何？
看解答與理由
a 與 r 都是 9，b 是 2。r = b 只複製當時的數值 9 到 a，沒有改變 r 的綁定。



同一個呼叫，副本與別名差在哪裡


以下以可修改的 int 變數 score 為例。先比較本頁已介紹的兩種形式；注意呼叫看起來一樣，參數宣告才決定是否使用副本。


比較項目void f(int x)void f(int& x)
函式內的 x這次呼叫建立的獨立值score 的另一個名稱
執行 x = 0只改參數副本改到呼叫端的 score
呼叫端外觀f(score);f(score);
複製什麼以引數的值初始化參數不複製被參考的 int 物件
常量或算式能否作引數f(3); f(score + 1); 可以一般可修改的 int& 不能綁到這些暫時值
需要特別符號讀值嗎函式內直接使用 x函式內也直接使用 x
使用情境希望函式有自己的輸入值需要經由函式修改既有物件


「必須是有名字的變數」只是過度簡化的口訣。真正要問的是引數能否代表合適、仍活著的物件；例如本頁稍後回傳 int& 的函式，也可能提供可綁定的位置。另一方面，參考宣告本身不承諾執行時永遠零儲存成本，sizeof(reference) 量到的則是被參考型別。





PART 08
唯讀參考：限制透過這個名稱的修改


const int& 同樣是參考，但不能透過這個名稱改變原值。這讓函式介面能表達「我只讀取你交給我的物件」。const 約束的是這條存取途徑；若原物件本來不是 const，擁有可修改名稱的其他程式仍可能修改它。


#include <iostream>
void showScore(const int& value) {
    std::cout << value << '\n';
}
int main() {
    int score = 20;
    const int& view = score;
    score = 35;
    showScore(view);
    showScore(8);
}
預期輸出
35
8



view 不是在綁定時拍下數值的快照，所以 score 改成 35 後，經由 view 看到的也是 35。若在 showScore 內寫 value = 0，編譯器會拒絕。唯讀參考也能接收暫時值，像 showScore(8)；該值可供這次呼叫使用，但不能因此把參考保存成永遠有效的連結。


對 int 這類小型數值，傳值通常已很清楚，並不是所有輸入都應改成參考。參考更重要的價值，是清楚表達是否修改原物件，或在需要時避免複製較大的資料。P5 會用 string 與 vector 示範這個差別。


動手練習
如果希望函式能更新呼叫端的 score，該選 int、int& 還是 const int&？
看解答與理由
選 int&，讓參數代表可修改的原物件。int 是副本；const int& 不能透過參數修改物件。



用需求挑選介面


表中的 T 是表示資料型別的記號，例如 int；不是省略型別就能直接編譯的寫法。指標列供讀完 P4 後回查，本頁先掌握前三列。


需求參數形式是否取得物件副本能否透過參數修改原物件
只需要小型輸入，或本來就需要快照T x一般由引數初始化自己的值不直接修改
需要修改既有物件T& x不複製目標物件可以
只讀既有大型物件const T& x不複製該目標物件不可以
要用位址表達目標，也允許沒有目標T* p（P4）複製指標的值，不是複製所指物件指向有效可修改物件時可以


const 參考在直接綁定既有相容物件時避免複製，但型別轉換可能先建立暫時物件。不要把簡短表格讀成任何呼叫都不會建立物件。物件的大小、使用方式與生命週期仍要一起判斷。





PART 09
回傳數值安全，回傳參考要問物件還活著嗎


回傳參考會讓呼叫結果代表既有物件。語法是在回傳型別加 &，但它不會自動延長物件生命。要先指出「參考的是誰」以及「呼叫結束後誰仍負責讓它存在」，才能判斷是否安全。


#include <iostream>
int& largerSlot(int& left, int& right) {
    if (left >= right) return left;
    return right;
}
int main() {
    int a = 4;
    int b = 9;
    int& chosen = largerSlot(a, b);
    chosen = 12;
    std::cout << a << " " << b << '\n';
}
預期輸出
4 12



a 與 b 都建立在 main 中，函式回傳後仍然存在。largerSlot 回傳 b 的參考，所以 chosen = 12 修改 b。若回傳型別改成 int，取得的會是數值結果；將它存進一般 int 變數後再修改，就不會改到 b。


int& badResult() {
    int local = 10;
    return local;  // 錯誤示意：local 在函式結束後生命已結束
}


這個片段用來辨識錯誤，不要拿回傳結果來存取。函式結束時 local 消失，回傳的參考懸空；即使某次執行看似讀到 10，也不構成任何保證。回傳 local 的數值則不同：在 local 還活著時取出值，再交給呼叫端。回傳位址也有同樣的生命週期問題，等 P4 建立指標觀念後再對照。


動手練習
把 largerSlot 的參數改成傳值 int left, int right，仍回傳 int& 可以嗎？
看解答與理由
不可以這樣使用。left/right 變成函式自己的區域副本，呼叫結束後生命終止，回傳它們的參考會懸空。



回傳後仍可使用，才算有效的結果


不能用一次試跑證明生命週期安全
回傳數值會把結果交給呼叫端；回傳參考或位址則保留對某個物件的連結。若那個物件已結束生命，舊記憶體內容看似未變也沒有用。不要將「這次還印出原值」當成正確；改了編譯器、最佳化或下一個函式呼叫，就可能得到完全不同的行為。


回傳內容呼叫結束後的情況判斷
區域 int 的值結果已交出；不再依賴該區域 int可以
main 內仍存活物件的參考仍依賴該物件的生命週期使用時原物件仍活著才可以
一般區域物件的參考或位址原物件生命已結束不得經由它繼續存取
暫時物件的連結可能在完整敘述結束時失效不能假設回傳會延長其生命





PART 10
多載與預設引數：分清楚選版本和補資料


多載讓同名函式有不同的參數列。編譯器根據呼叫的引數選擇能匹配的版本；這個選擇發生在編譯時，不是程式執行後猜測你想要的行為。只有回傳型別不同，不足以形成這種同名多載。


#include <iostream>
int deliveryFee(int boxes) { return boxes * 12; }
double deliveryFee(double weight) { return weight * 12.0; }
int main() {
    std::cout << deliveryFee(2) << " " << deliveryFee(2.5) << '\n';
}
預期輸出
24 30



2 是 int，因此第一個版本直接匹配；2.5 是 double，第二個版本匹配。若不同版本都需要轉型，可能沒有唯一較好的候選，這時編譯器會報多義。明確的型別與不同用途的函式名稱，通常比堆疊許多容易混淆的多載更易使用。


預設引數做的是另一件事：呼叫省略尾端資料時，用宣告提供的值補上。參數仍存在，不是少了一個參數。預設值應從參數列尾端安排，並在呼叫端看得到的宣告中提供；同一預設值不要在宣告與定義重複指定。


#include <iostream>
int fee(int boxes, int rate = 12);
int fee(int boxes, int rate) { return boxes * rate; }
int main() {
    std::cout << fee(3) << " " << fee(3, 10) << '\n';
}
預期輸出
36 30



動手練習
同時提供 int f(int) 與 int f(int, int = 0)，呼叫 f(3) 會更方便嗎？
看解答與理由
反而會多義：兩個版本都能接受這個呼叫，沒有唯一應選的版本。預設引數與多載要一起考慮。



預設引數與多載一起檢查


兩種方便寫法，也可能合成歧義
省略參數列尾端的引數之前，要先確認呼叫位置看得到預設值。已有多載版本時，再檢查省略後是否同時符合兩個候選。這是編譯時的介面問題，不能期待執行時自動挑出「比較符合直覺」的版本。


檢查項目正確做法常見錯誤
參數順序一般情況從尾端安排預設值前面有預設、後面卻仍必填
宣告與定義在呼叫端可見的宣告提供預設，定義不重複同一個預設值在相同作用域重複指定
多載候選檢查所有可以接受省略引數的版本把 f(int) 與 f(int,int=0) 當成不會衝突
回傳型別依參數列區分一般函式多載只改 int/double 回傳型別，參數完全相同





PART 11
從一般呼叫到遞迴：每次呼叫都有自己的狀態


函式可以呼叫其他函式，也可以再次呼叫自己。遞迴沒有新的呼叫語法，困難在於同時存在多次尚未完成的呼叫。理解它時，要把每次呼叫的參數、區域變數與回來後要繼續的位置分開記錄。這一份紀錄常稱為呼叫框架，通常由呼叫堆疊管理。


先用小範圍的倒數理解控制流程。停止條件回答「何時不再呼叫」，n - 1 則讓輸入逐次靠近停止條件。沒有停止條件，或每次仍傳入同一個 n，都可能讓呼叫越堆越多，最終耗盡可用資源。


#include <iostream>
void countdown(int n) {
    if (n <= 0) return;
    std::cout << n << " enter\n";
    countdown(n - 1);
    std::cout << n << " leave\n";
}
int main() { countdown(2); }
預期輸出
2 enter
1 enter
1 leave
2 leave



n=2 的呼叫尚未結束，就暫停去執行 n=1。n=1 又呼叫 n=0，後者立即返回；這才輪到 n=1 印 leave，再回到 n=2 印 leave。看見不同的 n 不是同一個變數不斷被改值，而是不同呼叫各自保存自己的參數。


互動：進入與返回不是同一個順序
堆疊由左到右表示較早到較新的呼叫。返回時，先完成最後進入的呼叫。
countdown(2);
// n=2 印 enter，再呼叫 countdown(1)
// n=1 印 enter，再呼叫 countdown(0)
// n=0 直接 return
// n=1 印 leave 並返回
// n=2 印 leave 並返回


遞迴並不自動比較快，也不一定比較慢；此處重點是能否清楚表示子問題以及需要保存多少呼叫狀態。深度很大的遞迴應特別小心，不能把「某個小例子跑得動」當成可以無限加深。後續演算法教材會再比較用迴圈或遞迴表達問題。


動手練習
若呼叫 countdown(3)，最後一行是 1 leave 還是 3 leave？
看解答與理由
3 leave。最外層最早進入，必須等所有內層呼叫完成才返回；輸出為 3 enter、2 enter、1 enter、1 leave、2 leave、3 leave。



遞迴也會逐層回傳計算結果


除了在進入、離開時輸出文字，函式也可以等待內層的回傳值再完成計算。以下假設第 day 天讀 2×day 頁；pagesAfter(day) 回傳前 day 天合計讀了幾頁。先處理零天，再把今天的頁數加上前幾天的結果。


#include <iostream>
int pagesAfter(int day) {
    if (day <= 0) return 0;
    return 2 * day + pagesAfter(day - 1);
}
int main() { std::cout << pagesAfter(3) << '\n'; }
預期輸出
12



正在完成的呼叫等內層回來後的算式交回的值
pagesAfter(0)基底情形直接 return 00
pagesAfter(1)2 + 02
pagesAfter(2)4 + 26
pagesAfter(3)6 + 612


day=3 的呼叫沒有先把 6 當成最終答案回傳；它要等待 day=2 的結果。每層都保留自己的 day，直到內層回來才做剩下的加法。倒數例子幫你看進入順序，這個表則幫你看結果如何反方向累積。


呼叫堆疊有有限容量
本頁的每個呼叫框架只需固定數量的參數、區域值與返回資訊。在這個呼叫堆疊模型中，同時存活的框架數隨遞迴深度增加，所以額外空間為 O(深度)。例如 pagesAfter(n) 到基底情形最多有 n+1 層，因此額外空間為 O(n)。若每層另建立大小會變的資料，還要把那部分空間算進去。
有停止條件仍不代表任意大的輸入都安全：如果需要的呼叫深度太大，實作仍可能耗盡堆疊。不同平台的限制與失敗方式不相同，不能預測一定收到某個固定例外或訊號。對可能很深的遞迴，應重新考慮迴圈或其他保存狀態的方式。


動手練習
pagesAfter(4) 等待哪個結果？最後多少頁？
看解答與理由
先等 pagesAfter(3) 回傳 12，再做 8 + 12，因此是 20 頁。
