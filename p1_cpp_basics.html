PROLOGUE · 開場

你按下執行之後，C++ 比 Python 多做了四件事

本頁那支 hello world 只有 9 行。把它丟給 g++，它會先展開成 46,577 行、再翻成 103 行組合語言，最後吐出一個 16 KB 的執行檔。這些全部發生在你看到 Hello 之前，而且是每改一次程式碼就重來一次。

Python 沒有這一段。你按下執行，直譯器就從第一行開始邊讀邊做；程式跑到第 40 行才會發現第 40 行的錯字。C++ 反過來：整份翻譯完才開始跑，所以第 40 行的錯字在你連一個字都還沒印出來之前就被抓到了。

PythonC++
怎麼跑起來直譯器讀一行跑一行先整份編譯成執行檔，再執行那個檔
什麼時候發現打錯字執行到那一行才發現編譯時就發現，程式根本跑不起來
型別執行時才決定，同一個變數可以換型別宣告時就定死，之後不能換
要不要自己管記憶體不用，有垃圾回收要，new 之後自己 delete
速度慢，但寫得快快，通常差一到兩個數量級
執行需要什麼目標機器上要有直譯器執行檔本身，但換平台要重編

這門課選 C++ 不是為了折磨你。資料結構在意的是「這個操作要花多少時間」，而 Python 把陣列、記憶體配置、複製成本全部藏在 C 寫的內建型別底下 —— 你量不到自己寫的那層。C++ 把這些攤開來，你才有東西可以分析。

PART 01 · 從原始碼到執行檔

g++ -std=c++17 -Wall main.cpp -o main 拆開來看

這行指令你整個學期會打幾百次。先把每個零件認清楚：

零件意思不寫會怎樣
g++GNU 的 C++ 編譯器驅動程式—
-std=c++17用 C++17 這版語言標準吃到編譯器的預設版本，某些寫法會突然不能用

💡 為什麼要知道有四個階段

因為錯誤訊息長得不一樣。編譯階段的錯會指到你的某一行（main.cpp:6:5: error:）；連結階段的錯不指行號，開頭是 /usr/bin/ld: 加上 undefined reference to。看到後者就不要再盯著那一行看了，問題是「某個函式只宣告沒定義」或「少編了一個檔」。PART 07 會拿真的訊息來對。

PART 02 · 程式骨架

四個零件，每支 C++ 程式都有

Python 的檔案可以只有一行 x = 1 就能跑。C++ 不行，它要求一個固定的外框：

#include <iostream> // ① 把要用的東西宣告搬進來 using namespace std; // ② 省掉 std:: 前綴 int main() { // ③ 程式從這裡開始 cout << "hi" << endl; return 0; // ④ 回報結束碼給作業系統 }
零件它在做什麼Python 對應
#include <iostream>把 <iostream> 這個標頭檔整份貼進來，於是編譯器才認得 coutimport
using namespace std;把 std 這個命名空間攤平，讓你可以寫 cout 而不是 std::coutfrom x import *
int main()程式的進入點。名字固定叫 main，作業系統只找它if __name__ == "__main__"
return 0;回報結束碼，0 表示正常。非 0 代表出錯，shell 腳本會看這個值sys.exit(0)

#include 是前處理階段做的，字面上就是文字替換 —— PART 01 那個從 9 行變成 46,577 行的膨脹，全部是 #include 貼進來的。

✅ 現代 C++ 對照

實務上多數團隊禁止 using namespace std;，因為它會把整個標準函式庫的名字倒進來，容易跟你自己的名字撞（例如你也寫了一個 count）。本課照 cppds 教科書寫 using namespace std;，考試以課程風格為準；等你開始寫多檔案專案，再改成逐個 using std::cout; 或直接寫 std::。

備註：課程標頭檔裡也寫了 using namespace std;

上面 stack.hpp 開頭幾行就有這一句。標頭檔會被原地貼進每個 include 它的檔案，所以只要 include 了課程標頭，std 的名字就跟著進來——這是為什麼有些 cell 沒寫 using namespace std; 也能用 cout。這是教材的簡化；自己寫 .hpp 時不要這樣做，標頭裡一律寫 std::，別替 include 你的人決定。

PART 03 · 變數與型別

宣告的時候就定死，之後不能換

這是 Python 轉 C++ 第一個要改的習慣。Python 裡 x 前一行是整數、下一行變字串完全沒問題；C++ 的 int x 從出生到離開範圍都是 int。

沒給初值不存在這種事，一定要指派合法，但值是垃圾

sizeof(s) 那行是重點：印出 32，那是 string 這個物件本身的大小（裡面存指標、長度、容量），不是字元佔的空間 —— 字元另外放在別的地方。

›點一個型別，看它佔幾個 byte、裝得下多大的數，以及裝不下時會怎樣。
怎麼選 RULE

整數一律先用 int，會超過二十一億再換 long long。小數一律用 double，不要用 float（只有 6 位有效數字，這門課的累加會失真）。

數字都是真的 REAL

面板上的大小與範圍是在這台 64 位元 Linux 上用 sizeof 與 <climits> 實際印出來的。C++ 標準只規定下限，換平台可能不一樣，所以要問大小就用 sizeof，不要背。

沒初始化的變數裡面是垃圾

這件事在 Python 不可能發生，卻是 C++ 初學最常見的靈異現象來源：程式有時候對、有時候錯，改一行不相干的程式碼結果就變了。

同一支程式，兩個沒初始化的 int
#include <iostream> using namespace std; void dirty() { // 先在堆疊上留下一些值 int a = 123456, b = -987654; (void)a; (void)b; } int main() { dirty(); int x; // 沒有初始化：值是上一個人留下的垃圾 int y; int z = 0; // 有初始化 cout << "x = " << x << endl; cout << "y = " << y << endl; cout << "z = " << z << endl; return 0; }
預期輸出
x = 1985727112
y = 32767
z = 0

x 與 y 印出來的是上一個用過這塊堆疊記憶體的人留下的殘值，而且每次執行、每次編譯都可能不同 —— 標準把讀取未初始化變數列為未定義行為。-Wall 通常會警告你，這就是 PART 01 說「警告常常就是 bug」的意思。解法只有一個：宣告的同時就給值。

⚠️ 最常見的翻車寫法

寫累加器時 int sum; 就直接進迴圈 sum += a[i];。這不是加到 0 上面，是加到一個垃圾值上面。永遠寫 int sum = 0;。同理，計數器要 int count = 0;，指標要 Node *p = NULL;。

💡 一行宣告多個變數

int num, den; 是一行宣告兩個同型別的變數，逗號隔開，類別成員宣告時很常見。初始值要各自寫：int a, b = 5; 只有 b 拿到初值 5，a 還是沒初始化的垃圾值，跟上面那條規則是同一個坑。

🔗 這在資料結構課哪裡會用到 · 第 03 章

〈陣列與稀疏矩陣〉要你自己算元素位址：第 i 格在 起始位址 + i × sizeof(元素)，二維的 row-major 則是 起始位址 + (i × 欄數 + j) × sizeof(元素)。那個 sizeof(元素) 就是這一節量到的 4 或 8，寫錯就整排位址都偏掉。

PART 04 · 輸入輸出

cout << 與 cin >>：箭頭指著資料流的方向

記法很直觀：cout << x 是把 x 推進輸出串流，cin >> x 是把輸入串流的東西倒出來放進 x。箭頭指哪邊，資料就往哪邊跑。

cout 的四種常見用法
#include <iostream> #include <string> using namespace std; int main() { string name = "David"; int age = 20; cout << "姓名：" << name << "，年齡：" << age << endl; cout << "一行" << '\n' << "兩行" << '\n'; cout << 1 << 2 << 3 << endl; // << 可以一直串下去 cout << "1 + 2 = " << 1 + 2 << endl; // 運算先做完才丟給 << return 0; }
預期輸出
姓名：David，年齡：20
一行
兩行
123
1 + 2 = 3

第三行印出 123 而不是 1 2 3 —— << 不會自動加空格，要空格自己寫。第四行的 1 + 2 先算完才丟給 <<，因為 + 的優先順序比 << 高。

endl 與 '\n' 差在哪

兩個都換行，但 endl 多做一件事：強迫把緩衝區的東西立刻寫出去。輸出量大的時候（例如印一萬筆排序結果）每行都 endl 會明顯變慢。

endl'\n'
換行會會
清空緩衝區會不會
速度慢快
什麼時候用要立刻看到輸出時，例如印 debug 訊息、程式可能會當掉其他所有情況

順帶一提：'\n' 是單引號包的一個 char，"\n" 是雙引號包的字串。這門課裡單引號與雙引號不能互換，char c = "A"; 會編譯錯誤。

讀進來：>> 讀一個詞，getline 讀一整行

#include <iostream> #include <string> using namespace std; int main() { int n; cout << "請輸入一個整數："; cin >> n; // 以空白或換行為界，讀進一個 int cin.ignore(); // 丟掉 >> 沒吃掉的那個換行 string line; cout << "請輸入一整行："; getline(cin, line); // 連空白一起讀，直到換行 cout << "n = " << n << "，line = " << line << endl; return 0; }

上面這支要你在終端機打字，所以沒辦法在網頁上附輸出。把輸入換成一段固定的文字，行為完全一樣，就能實際跑給你看：

同一組資料，>> 與 getline 各讀到什麼
#include <iostream> #include <sstream> #include <string> using namespace std; int main() { // 用 istringstream 模擬鍵盤輸入，行為跟 cin 完全一樣 istringstream input("David Malan 20\nHello data structures\n"); string first, last; int age; input >> first >> last >> age; // >> 以空白為分隔，一次讀一個 token cout << "first=[" << first << "] last=[" << last << "] age=" << age << endl; string line; getline(input, line); // >> 沒吃掉的換行還留著，先讀到空字串 cout << "第一次 getline=[" << line << "]" << endl; getline(input, line); // 這次才讀到整行 cout << "第二次 getline=[" << line << "]" << endl; return 0; }
預期輸出
first=[David] last=[Malan] age=20
第一次 getline=[]
第二次 getline=[Hello data structures]

看第二行輸出：第一次 getline 讀到的是空字串。因為 >> 讀完 20 就停了，那個換行還留在串流裡，getline 一讀就碰到它、當場結束。這是初學者最常卡住的地方 —— 解法是在 >> 之後、getline 之前補一行 cin.ignore();，把那個換行丟掉。

⚠️ >> 以空白分隔，讀不到有空格的名字

cin >> name; 碰到 David Malan 只會拿到 David，Malan 留在串流裡等下一次讀。要整行就用 getline(cin, name);。

printf 跟 cout 混著用：講義自己就這樣寫

C 語言留下來的 printf 跟 C++ 的 cout 是兩套完全不同的輸出機制，但講義兩者混用了十八次——原因很單純：要對齊成表格時，printf 的欄寬語法比 cout 好用太多。認得下面四個轉換字元就夠應付講義：

轉換字元對應型別講義例句
%dintprintf("%d 頁", pages);
%s字串，要先 .c_str()printf("%s costs %d cents\n", item.c_str(), price);
%f　%10.7fdouble10 是欄寬、7 是小數位數，數字自動靠右對齊
%lldlong longprintf("Sum is %lld required %10.7f seconds\n", s, secs);
#include <iostream> #include <cstdio> #include <string> using namespace std; int main() { string item = "eraser"; int price = 35; printf("The %s costs %d cents\n", item.c_str(), price); // string 要先 .c_str() long long s = 500000500000LL; double secs = 0.0012345; printf("Sum is %lld required %10.7f seconds\n", s, secs); bool found = true; cout << "found（沒加 boolalpha）= " << found << endl; cout << boolalpha; cout << "found（加了 boolalpha）= " << found << endl; return 0; }
預期輸出
The eraser costs 35 cents
Sum is 500000500000 required  0.0012345 seconds
found（沒加 boolalpha）= 1
found（加了 boolalpha）= true

第一行印字串用的是 %s，但 item 是 std::string 不是 C 的字元陣列，一定要先呼叫 .c_str() 轉成 printf 認得的型別，直接丟 string 進去是未定義行為。最後兩行是另一件講義做了 23 次的事：cout 印 bool 預設是 1 / 0，要看到 true / false 得先丟一個 boolalpha 進 cout，而且之後整條串流都變了，不是只有這一次輸出。

PART 05 · 運算子

整數除法：這一節最重要的一件事 第 06、07 章都靠它

在 Python 3 裡 7 / 2 是 3.5，要整數除法得寫 7 // 2。C++ 沒有 // 這個運算子（那是註解），它的規則只有一句：兩邊都是整數，除法就是整數除法，小數直接丟掉。

整數除法與取餘數
#include <iostream> using namespace std; int main() { cout << "7 / 2 = " << 7 / 2 << " <- 兩邊都是 int，小數被截掉" << endl; cout << "7 % 2 = " << 7 % 2 << " <- 餘數" << endl; cout << "7.0 / 2 = " << 7.0 / 2 << " <- 有一邊是 double 就變浮點除法" << endl; cout << "-7 / 2 = " << -7 / 2 << " <- 往零的方向截，不是往下取整" << endl; cout << "-7 % 2 = " << -7 % 2 << " <- 餘數跟被除數同號" << endl; cout << "1453 / 16 = " << 1453 / 16 << endl; cout << "1453 % 16 = " << 1453 % 16 << " <- 進位制轉換就靠這兩個" << endl; return 0; }
預期輸出
7 / 2     = 3   <- 兩邊都是 int，小數被截掉
7 % 2     = 1   <- 餘數
7.0 / 2   = 3.5 <- 有一邊是 double 就變浮點除法
-7 / 2    = -3  <- 往零的方向截，不是往下取整
-7 % 2    = -1  <- 餘數跟被除數同號
1453 / 16 = 90
1453 % 16 = 13   <- 進位制轉換就靠這兩個

四個要記住的點：① 只要有一邊是 double，整條式子就變浮點除法。② -7 / 2 是 -3 不是 -4，C++ 往零的方向截，跟 Python 的 // 往下取整不一樣。③ 因此 -7 % 2 是 -1，餘數跟被除數同號，Python 的 % 則跟除數同號。④ 最後兩行就是進位制轉換的全部：/ 拿到下一輪要處理的數，% 拿到這一位的數字。

式子Python 3C++為什麼
7 / 23.53C++ 兩邊都是 int，做整數除法
7.0 / 23.53.5有一邊是浮點數就做浮點除法
7 // 23語法錯誤//
-7 / 2-3.5-3往零截斷
-7 // 2-4—Python 往下取整
-7 % 21-1C++ 的餘數跟被除數同號
🔗 這在資料結構課哪裡會用到 · 第 06、07 章

第 07 章的雜湊表 pythonds3/cppds/hashtable.hpp 第 16 行就是 int hashFunction(int key) {{ return key % size; }} —— 整張表能不能均勻分布，全靠這個 %。第 06 章的進位制轉換 toStr(n, base) 則是 toStr(n / base, base) + convertString[n % base]：/ 負責往下一層遞迴，% 負責取出這一位。這兩個地方把 / 寫成 1.0 * n / base 就整個垮掉。

遞增與複合指定

i++ 與 ++i 差在什麼時候加
#include <iostream> using namespace std; int main() { int i = 5; cout << "i++ 印出 " << i++; // 先用後加 cout << "，之後 i = " << i << endl; int j = 5; cout << "++j 印出 " << ++j; // 先加後用 cout << "，之後 j = " << j << endl; int total = 10; total += 5; cout << "total += 5 -> " << total << endl; total -= 3; cout << "total -= 3 -> " << total << endl; total *= 2; cout << "total *= 2 -> " << total << endl; total /= 4; cout << "total /= 4 -> " << total << " <- 整數除法還是會截" << endl; return 0; }
預期輸出
i++ 印出 5，之後 i = 6
++j 印出 6，之後 j = 6
total += 5  -> 15
total -= 3  -> 12
total *= 2  -> 24
total /= 4  -> 6  <- 整數除法還是會截

i++ 是先把舊值交出去，再加一；++i 是先加一，再交出新值。單獨寫一行當作敘述時兩者沒差（for 迴圈的 i++ 換成 ++i 結果一樣），差別只在把它塞進別的式子裡的時候。最後一行提醒你：/= 一樣會截斷。

優先順序，還有一個 Python 習慣帶不過來

連續比較在 C++ 是另一個意思
#include <iostream> using namespace std; int main() { cout << boolalpha; cout << "2 + 3 * 4 = " << 2 + 3 * 4 << endl; cout << "(2 + 3) * 4 = " << (2 + 3) * 4 << endl; cout << "10 < 5 = " << (10 < 5) << endl; cout << "10 < 5 < 3 = " << (10 < 5 < 3) << " <- 先算 10<5 得到 0，再算 0<3" << endl; return 0; }
預期輸出
2 + 3 * 4   = 14
(2 + 3) * 4 = 20
10 < 5      = false
10 < 5 < 3  = true   <- 先算 10<5 得到 0，再算 0<3

Python 的 10 < 5 < 3 是「同時滿足兩個條件」，答案是假。C++ 沒有這種語法糖，它從左邊算起：10 < 5 得到 false（也就是 0），再算 0 < 3，於是變成真。要表達範圍檢查，一定要寫成 (5 <= x) && (x <= 10)。

優先順序（高到低）運算子
1()　[]　->　.
2++　--　!　*（解參考）　&（取址）
3*　/　%
4+　-
5<<　>>
6<　<=　>　>=
7==　!=
8&&
9||
10=　+=　-=　*=　/=　%=

不用背整張表，記兩件事就夠：<< 的優先順序比比較運算高，所以 cout << a < b 會編譯錯誤，要寫 cout << (a < b)；&& 比 || 高，混用時加括號比較安全。

💡 rand()／srand()：靠 % 把亂數壓進範圍

rand() 回傳一個很大的亂數（範圍看平台，通常到二十億出頭），單獨看沒什麼用；配上這一節的 % 就能壓進你要的範圍。講義第 05 章印表機任務要「隨機印 1 到 20 頁」，寫的就是 pages = rand() % 20 + 1;：% 20 先壓成 0 到 19，+ 1 再平移成 1 到 20。

#include <iostream> #include <cstdlib> using namespace std; int main() { srand(42); // 固定種子，這裡才能給出固定的預期輸出 for (int i = 0; i < 3; i++) { int pages = rand() % 20 + 1; // 壓進 1..20 cout << "第 " << i + 1 << " 份文件要印 " << pages << " 頁" << endl; } return 0; }
預期輸出
第 1 份文件要印 7 頁
第 2 份文件要印 1 頁
第 3 份文件要印 2 頁

不設種子的話，rand() 每次程式重新執行都是同一個起始種子，於是每次跑出來的序列一模一樣——這在偵錯時很方便，但不是你要的「隨機」。要讓序列每次執行都不同，得先呼叫 srand(time(0));（<ctime>），用當下的時間當種子。

PART 06 · 型別轉換

編譯器會自己轉，問題是它轉的時機不是你要的

C++ 遇到型別不同的兩邊，會偷偷把「小的」轉成「大的」再算，這叫隱式轉換。多數時候它很聰明，但 int / int 這個組合會讓你吃虧：兩邊都是 int，它就沒有理由轉，除法結果直接被截掉，之後再怎麼補救都來不及。

式子編譯器怎麼做結果
7 / 2.0把 7 轉成 7.0，做浮點除法3.5
7 / 2兩邊都是 int，不轉3
double d = 7 / 2;先算完 3，才轉成 3.03
int n = 3.99;截斷小數，不是四捨五入3
int n = true;bool 轉 int1
int n = 'A';char 轉 int，取 ASCII 碼65

第三列是最陰險的一個。double avg = sum / n; 看起來完全合理，但等號右邊是兩個 int，除法在轉成 double 之前就做完了。

同一組數字，轉型位置不同，答案不同
#include <iostream> using namespace std; int main() { int a = 7, b = 2; cout << "a / b = " << a / b << endl; cout << "(double)(a / b) = " << (double)(a / b) << " <- 先做整數除法才轉，太晚了" << endl; cout << "static_cast<double>(a) / b = " << static_cast<double>(a) / b << " <- 先把一邊變成 double，正確" << endl; double d = 3.99; cout << "static_cast<int>(3.99) = " << static_cast<int>(d) << " <- 轉 int 是截斷，不是四捨五入" << endl; int scores[3] = {90, 85, 78}; int sum = 0; for (int i = 0; i < 3; i++) sum += scores[i]; cout << "平均（錯）= " << sum / 3 << "，平均（對）= " << static_cast<double>(sum) / 3 << endl; return 0; }
預期輸出
a / b                       = 3
(double)(a / b)             = 3  <- 先做整數除法才轉，太晚了
static_cast<double>(a) / b  = 3.5 <- 先把一邊變成 double，正確
static_cast<int>(3.99)      = 3   <- 轉 int 是截斷，不是四捨五入
平均（錯）= 84，平均（對）= 84.3333

第二行的 (double)(a / b) 是典型的錯法：括號包住整個除法，等於「先算出 3，再把 3 變成 3.0」。第三行才對 —— 把其中一邊先變成 double，除法才會用浮點的規則做。只轉一邊就夠，另一邊會被隱式轉換帶上去。

💡 一個口訣

要浮點的答案，轉型要放在除號的左邊、括號的裡面：static_cast<double>(a) / b。放錯位置的 static_cast<double>(a / b) 編得過、跑得動、答案錯，而且錯得很安靜。

💡 舊式轉型：講義還有兩種寫法

static_cast<double>(x)、(double)x（C 式，第 05、09 章）、double(x)（函式式，第 01、07 章）——三種寫法效果完全一樣，都是把 x 轉成 double。講義圖省事常用後兩種較短的寫法，看得懂就好，作業建議一律用 static_cast（理由見下方「現代 C++ 對照」）。

整數溢位：裝不下的時候會繞回去

int 是 4 個 byte，能表示的最大值是 2,147,483,647。加到超過這個數，位元進到最高位，整個值就翻成負的。

int 撞到天花板
#include <iostream> #include <climits> using namespace std; int main() { cout << "int 的範圍：" << INT_MIN << " ~ " << INT_MAX << endl; int big = INT_MAX; cout << "big = " << big << endl; cout << "big + 1（未定義）= " << big + 1 << endl; unsigned int u = 0; cout << "unsigned 0 - 1 = " << u - 1 << " <- 無號數會繞回最大值" << endl; long long safe = static_cast<long long>(big) + 1; cout << "先轉 long long = " << safe << " <- 這才是想要的答案" << endl; return 0; }
預期輸出
int 的範圍：-2147483648 ~ 2147483647
big              = 2147483647
big + 1（未定義）= -2147483648
unsigned 0 - 1   = 4294967295  <- 無號數會繞回最大值
先轉 long long   = 2147483648  <- 這才是想要的答案

第三行 big + 1 印出最小的負數。要注意的是：有號整數溢位在 C++ 標準裡是未定義行為，這裡看到的繞回只是這台機器、這個最佳化等級下剛好如此，不保證。無號數就不一樣了 —— unsigned 的繞回是標準明文規定的，所以 0u - 1 一定得到最大值。最後一行給出正確作法：在溢位發生之前就把型別放大，而不是事後補救。

💡 INT_MAX 也拿來當「無限大」哨兵

<climits> 的 INT_MAX 除了標範圍，還有另一個常見用法：當「還沒找到答案」的哨兵值。講義第 06 章找零問題就這樣寫 int minCoins = INT_MAX;——先假裝目前的最佳解是無限大，只要找到任何一個真正可行的組合，數字一定比它小，就能把 minCoins 換掉；如果從頭到尾都沒更新，代表根本湊不出零錢。

⚠️ 這在第 02 章會咬到你

分析演算法時常常要算「n 個元素兩兩配對有幾組」，也就是 n * (n - 1) / 2。n 到四萬六千左右（n > 46,340），n * n 就爆掉 int 了。寫成 long long total = static_cast<long long>(n) * (n - 1) / 2; 才安全 —— 轉型要放在乘法之前，跟上面除法那個坑是同一個道理。

✅ 現代 C++ 對照

C 風格的 (double)x 跟 static_cast<double>(x) 在這裡效果一樣，但 static_cast 會擋掉一些不合理的轉換，而且在程式碼裡一眼就看得到（搜尋 static_cast 就能把所有轉型找出來）。本課兩種都會出現，考試以課程風格為準；自己寫的時候建議一律用 static_cast。

PART 07 · 讀懂編譯錯誤

g++ 罵人的話有固定格式，看懂前三行就夠了

初學者看到滿螢幕紅字的反應通常是全選複製去問人。其實 g++ 的訊息有結構，而且只有第一個 error: 值得看 —— 後面那幾十行多半是被第一個錯連累的。

main.cpp: In function 'int main()': main.cpp:6:5: error: expected ',' or ';' before 'cout'
片段意思
main.cpp哪一個檔出事
6第幾行
5那一行的第幾個字元（欄）
error:等級。error 一定要修，warning 編得過但通常也該修
expected ',' or ';' before 'cout'錯在哪。這一段才是要讀的東西
In function 'int main()'出事的位置在哪個函式裡。函式一多這行就很有用

下面四個是整學期出現頻率最高的，訊息都是真的跑 g++ 印出來的。

① 漏了分號
#include <iostream> using namespace std; int main() { int x = 10 cout << x << endl; return 0; }
g++ 錯誤訊息
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:6:5: error: expected ‘,’ or ‘;’ before ‘cout’
    6 |     cout << x << endl;

注意它指的是第 6 行，但分號其實漏在第 5 行。編譯器讀完 int x = 10 還在等分號，一路讀到下一行的 cout 才發現不對，所以行號會往後偏一行。看到 expected ';' 就往上一行找，這條規則幾乎百發百中。

② 型別不合
#include <iostream> #include <string> using namespace std; int main() { string name = "David"; int n = name; cout << n << endl; return 0; }
g++ 錯誤訊息
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:7:13: error: cannot convert ‘std::string’ {aka ‘std::__cxx11::basic_string<char>’} to ‘int’ in initialization
    7 |     int n = name;

cannot convert A to B 是最好讀的一類：它明講了「有一個 A，但這裡要的是 B」。中間那串 std::__cxx11::basic_string<char> 是 string 的完整名字，看到 aka 後面才是人話。這一類錯誤在你開始用 template <typename T> 之後會變得又臭又長，訣竅一樣：只讀 cannot convert 那一句。

③ 未宣告的識別字
#include <iostream> using namespace std; int main() { int total = 0; total = total + conut; cout << total << endl; return 0; }
g++ 錯誤訊息
[編譯失敗]
cell.cpp: In function ‘int main()’:
cell.cpp:6:21: error: ‘conut’ was not declared in this scope; did you mean ‘const’?
    6 |     total = total + conut;

was not declared in this scope 只有三種可能：打錯字（這裡是 conut）、忘了宣告、忘了 #include。g++ 甚至會猜你想打什麼（did you mean），雖然這次猜錯了。如果訊息裡的名字是 cout 或 sqrt 這種標準函式庫的東西，那就是第三種。

④ 連結錯誤：函式只宣告沒定義
#include <iostream> using namespace std; int addUp(int a, int b); // 只宣告，沒有定義 int main() { cout << addUp(3, 4) << endl; return 0; }
g++ 錯誤訊息
[編譯失敗]

main.cpp:(.text+0x13): undefined reference to `addUp(int, int)'

認得出來的兩個特徵：開頭是 /usr/bin/ld:（ld 是連結器），而且沒有指到你的哪一行。undefined reference to 的意思是「我知道有這個函式，但找不到它的身體」。常見原因是宣告了忘記實作、函式簽章打錯字，或多檔案專案只編了一個 .cpp。

看到這句八成是先去哪裡看

No such file or directoryinclude 的路徑不對-I 有沒有加對（見 PART 02）

🎯 三個習慣，可以少掉一半的 debug 時間

① 從第一個 error 開始修，修完馬上重編 —— 一個錯常常引發後面二十個。
② 永遠加 -Wall。它抓得到「變數沒初始化」「比較有號跟無號」這類編譯得過但會出事的東西。
③ 每寫十行就編譯一次。寫完兩百行才第一次按編譯，錯誤會互相糾纏到看不出源頭。

🔗 這在資料結構課哪裡會用到 · 整學期

這一節沒有對應到某一章，因為它每一章都會用到。第 04 章漏掉 template <typename T> 會噴一整頁；第 09 章的 BST<int> 型別參數寫錯，訊息會長到滾三個螢幕。能在三十秒內定位到第一個 error: 並看懂它，是這門課投報率最高的技能。

備註：assert，另一種比編譯錯誤更晚一步的檢查

上面講的都是編譯期的錯誤；assert(條件) 抓的是執行期的錯誤——條件不成立，程式立刻中止，並印出出事的那一行，比讓程式帶著錯誤值繼續跑、幾百行之後才爆掉好抓多了。

#include <iostream> #include <cassert> using namespace std; int half(int n) { assert(n % 2 == 0); // 條件不成立就中止，並印出這一行 return n / 2; } int main() { cout << half(10) << endl; cout << half(7) << endl; // 這裡會觸發 assert return 0; }
預期輸出
5
[執行結束碼 -6]
main: main.cpp:6: int half(int): Assertion `n % 2 == 0' failed.

第一次呼叫 half(10) 通過檢查，正常印出 5；第二次 half(7) 讓 n % 2 == 0 不成立，assert 直接中止程式（結束碼 -6，也就是 SIGABRT），訊息裡連檔名、行號、失敗的條件式都印出來了。講義第 03、06 章常拿它做自我檢查，例如確認陣列索引沒有越界、確認遞迴的參數符合預期。
